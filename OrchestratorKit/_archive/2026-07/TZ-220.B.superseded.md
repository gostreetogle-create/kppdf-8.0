## 1. Контекст

Audit Theme 1 — defense-in-depth chain для MongoDB data integrity. Цепочка TZ-120 (Soft-delete ✅ DONE) → TZ-121 (Cross-service TX) → TZ-122 (Optimistic locking) → TZ-126 (EAV atomicity). Все CRITICAL priority. Audit Theme 1 explicitly mandates:

- TZ-122: Optimistic Locking (Object.assign silent overwrite → `versionKey` + 409 response).
- TZ-126: EAV atomicity (bulkWrite in withTransaction).

## 2. Проблема

| Issue | Risk manifestation |
|---|---|
| TZ-121 non-atomic Order+Reservation TX | Orphan orders создаются даже при inventory failure → business/money risk |
| TZ-122 silent overwrite | Concurrent Contract edits → data loss without 409 signal |
| TZ-126 partial attribute writes | 5th attribute update failure leaves 4 done + 1 missing = corruption |

## 4. Action Steps

1. **Verify MongoDB replica set** is configured in `docker-compose.yml` (transactions require replica set or sharded cluster).
2. **TZ-121 implementation:** Wrap cross-service operations (Order.create → Reservation.reserve) в `SessionRunner.run(async (session) => ...)` helper. Verify rollback semantics.
3. **TZ-122 implementation:** Add `@Prop({ default: 0 }) @VersionKey() __v` where missing (Mongoose default name). Add 409 response on stale-version `updateOne({ _id, __v: N }, {...newdoc, __v: N+1})`.
4. **TZ-126 implementation:** Replace N sequential `updateOne` with `bulkWrite([updateOne, updateOne, ...], { ordered: false, session })` + `withTransaction()` wrap.
5. Re-test: failures in Nth op should roll back 1..N-1.
