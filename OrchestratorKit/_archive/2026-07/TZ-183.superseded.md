## 1. Контекст

Audit (2026-07-25) обнаружил:
- 74 backend service files → **1** has `.spec.ts` (99.86% gap).
- 20 e2e suites compensate partially for happy-paths.
- **NO** unit-level coverage for service internals (controllers, audit hooks, soft-delete plugin, RBAC guards).

Приближающие TZ-172/173/174/175 (soft-delete refactor) и TZ-180/181 (RBAC) **требуют** baseline test coverage чтобы verification of changes не сломать regression.

## 4. Action Steps

1. Verify `backend/jest.config.js` exists; if not, archive TZ для setup.
2. For each new spec — follow NestJS testing conventions: `Test.createTestingModule({ providers: [...] })`.
3. Mock Mongoose Models через `getModelToken()`.
4. Cover key paths:
   - `auth.service.login()` happy + invalid password + lockout-prep.
   - `users.service.findOne()` returns softDeleted=null filter.
   - `jwt-auth.guard` pass through with `@Public()` decorator.
   - `roles.guard` rejects role-mismatch with 403.
   - `soft-delete.plugin.spec.ts` (after TZ-172) — verifies auto-filter behavior.
5. Ensure CI-script (`pnpm test:backend:cov`) runs new specs.
6. Update `package.json` scripts если missing.

## 5. Acceptance Criteria

1. New spec files created и visible в `find backend/src -name "*.service.spec.ts"` count (was: 1, target: ≥7).
2. `pnpm exec jest --config backend/jest.config.js` exit 0 + 0 failing tests.
3. `pnpm exec jest --config backend/jest.config.js --coverage` → coverage report shows ≥40% on auth.module.ts + users.module.ts + permissions.module.ts.
4. New specs runnable standalone: `pnpm exec jest src/modules/auth/auth.service.spec.ts` exit 0.
