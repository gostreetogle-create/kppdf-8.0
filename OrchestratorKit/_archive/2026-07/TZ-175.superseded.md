═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. CI pipeline (`.github/workflows/ci.yml`) НЕ запускает `pnpm audit` —
   проверка зависимостей на известные уязвимости отсутствует.

2. Нет dependency review для PR (GitHub Dependency Review Action).

3. Нет secret scanning (GitHub secret scanning или trufflehog).

4. Это значит: новые PR могут тянуть зависимости с критическими
   CVE без какого-либо warning в CI.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Добавить pnpm audit в CI

В `.github/workflows/ci.yml` добавить новую job `security-audit`:

```yaml
security-audit:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - uses: pnpm/action-setup@v4
    - uses: actions/setup-node@v4
      with:
        node-version: 20
        cache: pnpm
    - run: pnpm install --frozen-lockfile
    - run: pnpm audit --audit-level=high
      continue-on-error: false
```

  Под-шаг 1.1: Определить позицию job в ci.yml (после lint/test jobs)
  Под-шаг 1.2: Добавить job с pnpm audit
  Под-шаг 1.3: Убедиться что `--audit-level=high` фейлит только на high/critical

ШАГ 2: Добавить license compliance check (опционально)

Добавить step с `pnpm license-checker --failOn "GPL-3.0;AGPL-3.0"` для
проверки что нет copyleft лицензий в зависимостях.

  Под-шаг 2.1: Установить license-checker как devDependency
  Под-шаг 2.2: Добавить step в security-audit job

ШАГ 3: Обновить ci-passed gate

Убедиться что `ci-passed` gate job зависит от `security-audit`:
```yaml
ci-passed:
  needs: [frontend-lint, frontend-test, frontend-build, backend-lint, backend-test, backend-build, security-audit]
```
