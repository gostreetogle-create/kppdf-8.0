# TZ-199 — Proposal ⇄ Quotation single-source-of-truth consolidation

**Дата:** 2026-07-25
**Тип:** Data-model consolidation (successor-TZ для `docs/data-model-audit.md` Priority 1 #2)
**Priority:** 🔴 CRITICAL
**Status:** ⏳ READY
**Layer:** 4 (Backend — schemas, controllers, DTOs)
**Agent Role:** Backend data-model engineer
**Estimated complexity:** L (data migration + cross-cutting renames)

## 1. Контекст

`docs/data-model-audit.md` §1.1 #2 identifies duplication между `Proposal` (id, customerId), `Quotation` (counterpartyId, tenderId) и `CommercialProposal` (компактный, без id). Цель: **канонический `Quotation`**. Диагностика (2026-07-25) подтвердила:
- Реальный `Proposal`/`CommercialProposal` schema-модуля **НЕТ в файловой системе** (`backend/src/modules/proposal/` не существует).
- Все ссылки на Proposal — это Mongoose Ref `'Quotation'` (alias):
  - `Contract.schema.ts:38` — `proposalId?: Types.ObjectId` (ref: `'Quotation'`)
  - `ProductionOrder.schema.ts:27` — `proposalId?: Types.ObjectId` (ref: `'Quotation'`)
  - `production-order.service.ts:72-73` использует `proposalId`
  - `contract.service.ts:35, 69, 83` использует `proposalId`
- `DocumentTableType.schema.ts:38`: enum `'products' | 'orders' | 'proposals'` указывает на legacy Proposal.

## 2. Проблема

Naming inconsistency (`proposal` vs `quotation`) ведёт к:
- Cognitive overhead для разработчиков (2 имени для одного объекта).
- Несоответствие audit (`docs/data-model.md` указывает Proposal, но код везде Quotation).
- Frontend путается при API design (какой prefix выбрать для нового endpoint).
- Risk ошибочных populate-chains в Mongoose.

## 4. Action Steps

1. **Pre-stage**: Create migration script `backend/scripts/migrate-proposal-to-quotation.ts`:
   - `db.contracts.updateMany({}, { $rename: { "proposalId": "quotationId" } })` 
   - `db.productionorders.updateMany({}, { $rename: { "proposalId": "quotationId" } })`
   - Test на dev mongo replica.
2. **Schema update**: Rename field `@Prop proposalId` → `@Prop quotationId` в 2 schemas. Add `@deprecated` JSDoc note для legacy DTO alias `proposalId` в migration window.
3. **Service update**: replace `populate('proposalId')` → `populate('quotationId')` в 4+ service methods.
4. **DTO update**: `CreateContractDto.proposalId` → `quotationId`. Old name deprecated через alias property.
5. **Frontend audit** (placeholder PR): `grep -r "proposalId" frontend/src/` — log findings, fix outside this TZ scope.
6. **Typecheck pass**.
7. **E2E test**: extend `contract.e2e-spec.ts` to verify `quotationId` field round-trips correctly.
