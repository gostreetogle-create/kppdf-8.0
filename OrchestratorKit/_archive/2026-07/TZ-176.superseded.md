TZ-176: Заменить console.warn на Logger в backend
═══════════════════════════════════════════════════════════════

РОЛЬ АГЕНТА: Backend Developer

ЗАВИСИМОСТИ: Нет

LAYER: 4

═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. `document-template.service.ts:675` использует `console.warn()` вместо
   NestJS Logger. Это обходит structured logging и password redaction.

2. `text-block.service.ts` содержит `as any` cast на column mapping (строка 103):
   ```typescript
   .map(c => ({...c, content: sanitizeBlockContent(c.content ?? '')})) as any
   ```
   Это типовое несоответствие между DTO и schema.

3. `eav.service.ts` содержит `as any` cast на operations array.

4. `document-template.service.ts` содержит 2× `as any` для orientation/defaultBackgroundIndex.

5. Всего: ~5 `as any` + 1 `console.warn` в production backend коде.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Заменить console.warn на Logger

В `document-template.service.ts` заменить:
```typescript
console.warn('...');
```
на:
```typescript
this.logger.warn('...');
```

  Под-шаг 1.1: Найти все `console.warn` / `console.log` / `console.error` в backend/src
  Под-шаг 1.2: Заменить на `this.logger.warn()` / `this.logger.log()` / `this.logger.error()`
  Под-шаг 1.3: Убедиться что сервис имеет `private readonly logger = new Logger(XxxService.name)`

ШАГ 2: Убрать as any касты

Для каждого `as any` — найти правильный тип:
- `eav.service.ts` — operations array: типизировать через `MongoBulkWriteOperation` или конкретный тип
- `text-block.service.ts` — column mapping: проверить тип DTO и привести к нему
- `document-template.service.ts` — orientation/defaultBackgroundIndex: добавить типизацию

  Под-шаг 2.1: Для каждого `as any` — определить реальный тип
  Под-шаг 2.2: Заменить `as any` на правильный тип или `as unknown as T`
  Под-шаг 2.3: Если тип сложный — использовать intermediate interface

ШАГ 3: Проверить что build проходит

Запустить `pnpm run build` в backend/ после изменений.
