## 1. Контекст

Per code-reviewer verdict on `tasks/TZ-202.md`: split TZ-202 into TZ-202.A (AuditLog unify) + TZ-202.B (3NF cleanup). Audit §4.7 identifies `OrderHistory` + `UserActivity` (both narrative-style loggers) — consolidates **в новый `AuditLog` единый канон**. `Comment` остаётся отдельным (не аудит, обсуждение).

## 2. Проблема

3 разных log-patterns:
- `OrderHistory` (order-related narrative)
- `UserActivity` (per-user narrative)
- `audit-log` (TZ-05 AuditInterceptor writes)

Scattered, hard to query across all actions. Substitute no **canonical source-of-truth** audit/event-store.

## 3. Файлы

## 4. Action Steps

1. Audit schema canonical:
   ```typescript
   @Schema({ collection: 'auditlogs', timestamps: true, softDelete: false })
   class AuditLog {
     @Prop({ type: String, enum: ['order','user','entity','system'], index: true })
     entityType!: string;
     @Prop({ type: Types.ObjectId, index: true })
     entityId?: Types.ObjectId;
     @Prop({ index: true })
     action!: string;        // 'create', 'update', 'login', etc.
     @Prop({ type: Types.ObjectId, ref: 'User', index: true })
     actorId?: Types.ObjectId;
     @Prop()
     actorName?: string;     // denormalized for fast admin display
     @Prop({ type: Object })
     payload?: any;          // before/after snapshot
     @Prop()
     ipAddress?: string;
     @Prop()
     userAgent?: string;
   }
   ```

   - `db.orderhistories.find().forEach(...)` → append to auditlogs with mapping.
   - `db.useractivities.find().forEach(...)` → append to auditlogs.
   - One-time idempotent (verify by checking counts before insert).
3. Test: write `backend/test/integration/auditlog-unify.e2e-spec.ts` — verify unified corpus returns expected rows.
4. Update `docs/data-model-audit.md` §4.7 status → **DONE**.
