ЧТО СДЕЛАНО (ретроспективно — implementation существовала до formal closure)
═══════════════════════════════════════════════════════════════

Файл 1: `frontend/src/app/core/idempotency.interceptor.ts` (~13 LoC):
   - HttpInterceptorFn для `provideHttpClient(withInterceptors([...]))`
   - Только POST/PATCH/DELETE модифицированные requests
   - Reads active UUID из SubmitGuard.getActiveKey(url, method) — НЕ генерирует независимо
   - Если нет active submit в SubmitGuard — генерирует fresh UUID (service-level mutations)
   - Preserves existing `Idempotency-Key` header (не перезаписывает если уже есть)
   - Returns next(req.clone({ setHeaders: { 'Idempotency-Key': key } }))

Файл 2: `frontend/src/app/shared/dsl/submit-guard.ts` (~85 LoC):
   - @Injectable({ providedIn: 'root' }) — singleton DI scope
   - Single-source-of-truth `inFlight: Map<composite_key, UUID>` — корреляция с interceptor
   - Graded `completedCache: Map<composite_key, {result, expiresAt}>` for L3 protection
     - ok:true → cache expires 5 min
     - 5xx → cache expires 60 sec
     - 4xx → NO cache (force retry)
   - Background setInterval (60s sweep) для cleanup expired entries
   - guard<T>(opts): Promise<SilentResult<T>>:
     1. composite = `${method}|${url}|${formKey}`
     2. completedCache check (early return)
     3. inFlight check (return 429 SilentResult if exists)
     4. debounce 300ms (configurable via debounceMs)
     5. Register in entry AFTER debounce (NOT before — cross-component isolation fix)
     6. await firstValueFrom(opts.fetcher())
     7. Cache graded by status code
     8. finally: delete in-flight entry
   - getActiveKey(url, method): string | null — read-only API для interceptor

Файл 3: `frontend/src/app/core/idempotency.interceptor.spec.ts` (5 tests):
   - POST генерирует header
   - GET НЕ получает header (только state-changing verbs)
   - existing header preserved
   - PATCH генерирует header
   - DELETE генерирует header
   (mockUUID helper для deterministic headers в tests)

Файл 4: `frontend/src/app/shared/dsl/submit-guard.spec.ts` (5 tests):
   - Successful result cached → second call returns cached (5min TTL)
   - 4xx errors NOT cached (force retry)
   - 5xx errors cached 60s (retry storm protection)
   - inFlight entry cleared after request completes (no permanent locks)
   - getActiveKey returns null when no active submit

Integration:
   - `frontend/src/app/app.config.ts`: provideHttpClient(withInterceptors([idempotencyInterceptor, authInterceptor]))
   - Interceptor ordering CRITICAL: idempotency ПЕРЕД auth (TZ-232 §6.1 risk note)
