## 3. Файлы

- All `frontend/src/app/**/*.ts` containing `ngOnDestroy()` → replace with `inject(DestroyRef).onDestroy()`.

### Files NOT to modify
- `frontend/src/main.ts` (TZ-179 already DONE).
- `frontend/src/app/shared/ui/pi-rich-text-editor.component.ts` (TZ-179 already DONE).
- `frontend/src/app/core/services/api.tokens.ts` (no `any` expected).
- `*.spec.ts` files (out of scope).

## 4. Action Steps

1. **Diagnostic scan:** `grep -rlE "as any" frontend/src/app/ --include="*.ts" --exclude="*.spec.ts"` — capture list of files. Expected: 5-10 files based on audit roadmap.
2. **One-by-one fix:** For each `as any` reference, replace with concrete type. If genuine unknown type (e.g., debug injection), use `Record<string, unknown>`.
3. **Same for ngOnDestroy:** `grep -rlE "ngOnDestroy\(|\bOnDestroy\b" frontend/src/app/ --include="*.ts" --exclude="*.spec.ts"`.
4. **Typecheck:** `cd frontend && pnpm exec tsc --noEmit -p tsconfig.app.json` exit 0.
5. **Browser smoke:** smoke-test affected components do not regress.
