## 1. Контекст

Audit Theme 3 — Security & Reliability CRITICAL priority. Audit explicit mandates:
- **TZ-127**: Auth Rate-Limit Bypass + XSS Tokens. Авторизованный user = unlimited req/s (DoS from compromised account). Refresh token в localStorage = XSS. **HttpOnly cookie + tiered throttler**.
- **TZ-125**: Interceptor RxJS Leaks. `tap(async)` в audit interceptor → crash Node при audit-failure. **Replace with `mergeMap` + `catchError`**.
- **TZ-119**: Backend safety sweep. `GET /api/products/INVALID_ID` → 500 (нет ObjectId validation pipe). **Add ValidationPipe + lookup-table cleanup**.
- **TZ-105.3**: Server-side DOMPurify for block HTML (Backlog P2 — defer to follow-up batch).

## 2. Проблема

| Issue | Risk |
|---|---|
| TZ-127 unlimited req/s | Application-Layer DoS from compromised account |
| TZ-127 XSS token storage | XSS attacker can request refresh and exfiltrate user data |
| TZ-125 audit interceptor crash | Entire API crashes on DB connection error |
| TZ-119 unhandled 500 on invalid IDs | Production log noise + potential security info disclosure |

## 4. Action Steps

1. **TZ-127 HttpOnly cookie:** Configure `res.cookie('refreshToken', token, { httpOnly: true, secure: true, sameSite: 'strict' })`. Update `@Public() /auth/refresh` to read token from cookie OR body (dual-mode for backwards compat).
2. **TZ-127 tiered throttler:** Add 3-tier @Throttle decorator on auth endpoints (per-user, per-IP, per-endpoint).
3. **TZ-125 interceptor fix:** Replace `tap(async () => auditAction())` with `mergeMap(() => auditAction().pipe(catchError(logAndContinue)))`. Verify failure is logged, NOT crash.
4. **TZ-119 ValidationPipe:** Apply `new ValidationPipe({ transform: true, whitelist: true, exceptionFactory: ValidationErrorFactory })` globally OR scoped @UsePipes. Add `ParseObjectIdPipe` controller-level.
5. **TZ-119 lookup cleanup:** Audit `lookup-table.service.ts` (if exists) for memory leaks; convert to LRU cache with TTL.
