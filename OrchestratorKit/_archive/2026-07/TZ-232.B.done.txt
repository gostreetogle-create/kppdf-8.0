До этой TZ: 16 hand-written service classes в `frontend/src/app/shared/services/` с
идентичным 5-методным паттерном (`list` / `findById` / `create` / `update` / `remove`).
~600 строк boilerplate, копипаста из services один в другой (только endpoint + entity
type отличаются). `<pi-entity-list>` wrapper (TZ-232.C scope) требует `EntityService<T, P>`
интерфейс — без defineEntity каждый consumer должен оборачивать hand-written service
через `toEntityService`.

Per TZ-232.md §1.3: «Type-safety через defineEntity<T, P>» — coerced compile-time guards
через TypeScript's type narrowing: `HttpClient` import ESLint-banned в *.component.ts,
`defineEntity()` требует `schema.endpoint` to be `string` literal, methods are typed для
T/P → PATCH/POST body must match T's shape, missing _id update → compile error.

Per TZ-232.md §2.3: 16-18 services identified for migration through defineEntity (~600
строк boilerplate → 0, plus ~100 строк shim-кода для backward-compat). Migration is
separate TZ (TZ-232.C/D/E/F/G rollout), NOT in TZ-232.B scope.

ЧТО СДЕЛАНО (ретроспективно — implementation существовала до formal closure)
═══════════════════════════════════════════════════════════════

Файл 1: `frontend/src/app/shared/dsl/entity/entity-service.ts` (~226 LoC):
   - **paramsToHttpParams(params)** — filter conventions: skip null/undefined/empty-string,
     drop empty arrays, serialize scalars через `String(value)`, serialize arrays as multiple
     keys (`?role=admin&role=manager`, NestJS-friendly). Returns `HttpParams` instance.
   - **PaginatedResponse<T>** — canonical paginated envelope `{items, total, page, limit}`.
     Matches shape already used by ~11 of 16 existing services (MaterialsService /
     ProductsService / OrganizationsService / CounterpartyService).
   - **EntitySchema<T>** — per-entity configuration: `endpoint` (mandatory string) +
     optional `idKey` (default `'_id'`, type-level hint).
   - **EntityService<T, P>** — 5 canonical Angular service methods, each returns
     `Observable<SilentResult<U>>` (discriminated union from `core/silent-http`).
   - **toEntityService<T, P>(svc)** — adapt hand-written service with canonical 5-CRUD
     shape to `EntityService<T, P>` interface. Synthetic page/limit mapping for
     non-paginated endpoints. 1-LOC bridge per page that wants to use EntityService
     interface with existing hand-written service.
   - **DefineEntity<T, P>** — return type of `defineEntity()`. Holds `schema` (for
     reflection/logging) + `inject()` function for Angular DI lookup.
   - **defineEntity<T, P>(schema)** — factory function. Creates per-endpoint
     `InjectionToken<EntityService<T, P>>` with `providedIn: 'root'` + lazy-constructed
     factory function that injects `HttpClient` + `API_BASE_URL`. Returns `{schema, inject}`.
   - **URL normalization**: strip trailing slash from `rawBaseUrl` (preserves leading slash
     so joined URL stays absolute), strip BOTH leading AND trailing slashes from
     `schema.endpoint` via two separate `.replace()` calls (single combined regex
     `/^/+|\\/+$/g` is unreliable for trailing slashes under some V8/Node engines).

Файл 2: `frontend/src/app/shared/dsl/entity/entity-service.spec.ts` (~250 LoC, **18 tests**):
   - **paramsToHttpParams (5 tests)**: drops null/undefined/empty, serializes scalars,
     serializes arrays as multiple keys (NestJS-friendly), drops empty arrays, handles
     empty input.
   - **Users 5-CRUD (8 tests)**: list() GETs /api/users with encoded params, list() drops
     undefined params, findById() GETs /api/users/:id, create() POSTs payload,
     update() PATCHes /api/users/:id with payload, remove() DELETEs /api/users/:id (null body),
     returns ok=false with HttpErrorResponse 4xx on failing GET, exposes schema.idKey of "_id".
   - **bare-config defaults (5 tests)**: singleton across separate inject() calls, default
     idKey "_id" (list), default idKey "_id" (findById URL), collapses duplicate leading
     slashes, collapses trailing slashes.
   - Helper: `inCtx<T>(fn)` wraps calls in `runInInjectionContext(TestBed.inject(Injector), fn)`
     so inner `Users.inject()` runs inside authentic injector (jest workers where `beforeEach`
     is NOT Angular injection context).

Файл 3: `frontend/src/app/shared/dsl/entity/index.ts` (~15 LoC):
   - Barrel re-exports: `defineEntity`, `paramsToHttpParams`, types `DefineEntity`,
     `EntitySchema`, `EntityService`, `PaginatedResponse`. Single import path for consumers.

Файл 4: `frontend/src/app/pages/users/users.entity.ts` (~10 LoC, **demo entity**):
   ```typescript
   import { defineEntity } from '../../shared/dsl/entity/entity-service';
   export interface User {
     _id: string;
     username: string;
     email: string;
     role: string;
   }
   export const Users = defineEntity<User>({
     endpoint: '/users',
     idKey: '_id',
   });
   ```
   - Demo entity used by `entity-service.spec.ts` (imported + used in 8 tests).
   - Production-ready pattern для 9 TZ-240 sentinels (orders/products/contracts/materials/
     work-types/organizations/modules/doc-constructor×3/inventory×2) — they can replace their
     hand-written services через `defineEntity<T>({endpoint: '...'})` в own TZs (TZ-232.C/D/E/F/G).

ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ (non-blockers)
═══════════════════════════════════════════════════════════════

1. **No production consumer yet.** `Users` is a demo entity, не подключён к production page
   (нет `pages/users/users.page.ts`). This is intentional — TZ-232.B is the factory foundation;
   actual page migration is TZ-232.C/D/E/F/G scope (87-119 h per master plan §4.2).

2. **toEntityService shim migration is OUT of TZ-232.B scope.** Per TZ-232.md §2.3, the
   16 hand-written services (`materials.service.ts`, `products.service.ts`, etc.) migrate
   через TZ-232.B-shim OR full defineEntity в separate TZ (TZ-232.C/D/E/F rollout phases).
   TZ-232.B only formalizes the factory + demo entity + 18 tests.

3. **Pre-existing builder.page.ts TS errors** (TS2339, TS7006, lines 1115-1116):
   - NOT introduced by TZ-232.B — задокументировано в TZ-232.N архиве как TZ-230 successor work
   - OUT of TZ-232.B scope, filtered from TSC verification

4. **`any` for service.list params in toEntityService.** Hand-written services often have
   narrower param types than wrapper's full `P extends DefaultListParams` (e.g.,
   WorkTypesService.list accepts only `WorkTypeListParams` without page/limit/search).
   We type source service's `list` parameter as `any` so any function signature can be
   adapted without page-level casts. Function bivariance on `any` means service accepting
   narrower type IS assignable. Runtime is safe — backend ignores unknown query params
   (NestJS default). The wrapper's `P` type IS preserved on returned `EntityService<T, P>`.

5. **Synthetic page/limit mapping for non-paginated endpoints.** Some hand-written services
   return `{items, total}` without `page`/`limit`. The wrapper needs full `PaginatedResponse<T>`
   shape for pagination signals (e.g., `showPager` computed in `<app-pi-table>` reads `total()`
   and `page()` to decide whether to render pager). We fill synthetic `page: 1` and
   `limit: Math.max(items.length, 1)` so wrapper's arithmetic works — `showPager` returns
   `false` when `total <= pageSize` (single page), so user never sees bogus pager. If backend
   ever adds pagination, swap synthetic mapping for real values; rest of wrapper stays unchanged.
