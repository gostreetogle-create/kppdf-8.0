TZ-173: Исправить CI backend format → format:check
═══════════════════════════════════════════════════════════════

РОЛЬ АГЕНТА: DevOps / Backend Developer

ЗАВИСИМОСТИ: Нет

LAYER: 4

CONFLICT KEYS: .github/workflows/ci.yml

═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. Файл `.github/workflows/ci.yml`, строка 89:
   ```yaml
   - run: pnpm run format    # <-- БАГ: пишет файлы, а не проверяет
     working-directory: backend
   ```

2. Команда `pnpm run format` в backend запускает Prettier в режиме записи
   (auto-fix), а не в режиме проверки (`format:check`).

3. Это значит: CI молча исправляет форматирование файлов, но не фейлит
   билд при наличии format issues. Проблемы форматирования накапливаются
   без visibility.

4. В frontend CI уже используется `pnpm run format:check` — консистентность
   нарушена.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Исправить команду в ci.yml

Заменить `pnpm run format` на `pnpm run format:check` в секции backend lint.

  Под-шаг 1.1: Найти строку в `.github/workflows/ci.yml` (примерно строка 89)
  Под-шаг 1.2: Заменить `pnpm run format` → `pnpm run format:check`
  Под-шаг 1.3: Проверить что `backend/package.json` содержит скрипт `format:check`

ШАГ 2: Проверить наличие format:check в backend

Если `format:check` не определён в `backend/package.json` — добавить:
```json
"format:check": "prettier --check \"src/**/*.ts\""
```

ШАГ 3: Локальная верификация

Запустить `pnpm run format:check` в backend/ и убедиться что:
- Если есть format issues — команда падает с ненулевым exit code
- Если format чист — команда проходит
