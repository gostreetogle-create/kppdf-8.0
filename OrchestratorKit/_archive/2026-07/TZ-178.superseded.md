═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. Backend имеет **72 модуля**, но только **1 unit test файл**
   (`bom-component-resolve.service.spec.ts`). Это критически мало.

2. E2E тесты покрывают интеграцию (10 suites, 56 tests), но НЕ
   покрывают edge cases сервисов в изоляции.

3. Ключевые сервисы без unit тестов:
   - `auth.service.ts` — JWT, bcrypt, login/register logic
   - `product.service.ts` — CRUD, populate, module attach/detach
   - `order.service.ts` — CRUD, status transitions
   - `contract.service.ts` — CRUD, activation logic
   - `document-template.service.ts` — build, upload, render

4. Risk: regression bugs в критических сервисах ловятся только на E2E
   (требует MongoDB), что замедляет CI и затрудняет debugging.
