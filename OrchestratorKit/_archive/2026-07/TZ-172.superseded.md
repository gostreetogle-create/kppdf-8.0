TZ-172: Закрыть публичный /auth/register
═══════════════════════════════════════════════════════════════

РОЛЬ АГЕНТА: Backend Developer

ЗАВИСИМОСТИ: Нет

LAYER: 4

CONFLICT KEYS: backend/src/modules/auth/auth.controller.ts; backend/src/modules/auth/auth.service.ts; backend/src/modules/auth/dto/register.dto.ts

═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. `POST /api/auth/register` имеет декоратор `@Public()` — доступен без аутентификации.

2. Любой пользователь может создать аккаунт с ролью `user` (роль по умолчанию).

3. В ERP-системе регистрация должна быть административной операцией.
   Публичная регистрация — attack surface: создание аккаунтов для
   перебора, spam, reconnaissance.

4. Контекст: контроллер в `backend/src/modules/auth/auth.controller.ts`,
   DTO в `backend/src/modules/auth/dto/register.dto.ts`.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Убрать @Public() с register endpoint

В `auth.controller.ts` убрать декоратор `@Public()` с метода `register()`.
Это автоматически защитит эндпоинт через глобальный `JwtAuthGuard` (APP_GUARD).

  Под-шаг 1.1: Найти метод `register` в auth.controller.ts
  Под-шаг 1.2: Убрать `@Public()` декоратор
  Под-шаг 1.3: Добавить `@Roles('admin')` для явного указания кто может регистрировать

ШАГ 2: Добавить ограничение роли при регистрации

Убедиться что DTO `RegisterDto` не позволяет клиенту задать роль.
Текущая реализация: роль берётся из дефолта схемы (`user`).
Если DTO имеет поле `role` — удалить его (критично!).

  Под-шаг 2.1: Проверить RegisterDto — есть ли поле `role`
  Под-шаг 2.2: Если есть — удалить, оставить только `email` + `password`

ШАГ 3: Обновить e2e тесты

Обновить `auth.e2e-spec.ts`:
- Тест на успешную регистрацию только с валидным JWT (admin token)
- Тест на 401/403 при попытке регистрации без токена
- Тест на 403 при попытке регистрации с role=user token
