## 2. Проблема

Audit §3 (3NF normalization) выявил 6 entity schemas с избыточными `*Name`/`*Sku`/`*Total` cached fields:
- `ProductionOrder`: `productName`, `productSku`, `total` (derived from items)
- `OrderTask`: derived operations
- `CostCalculation`: derived cost totals
- `ReconciliationAct`: derived reconcile totals
- `FinancialReport`: derived report aggregates
- `User`: `passwordHash` (security-sensitive — spot-check bcrypt vs plaintext, password verify+delete methods)

Избыточность приводит к: (1) sync inconsistencies при изменениях source records (e.g., product renamed but cachedProductName stale), (2) increased storage cost, (3) complexity в custom-aggregation reporting (custom pipeline должен remember cache invalidation).

## 10. Risk Assessment

- **Data loss:** if migration runs without E2E test verification, virtual field naming divergence could break frontend display. Mitigation: E2E test mandatory before prod run.
- **Performance:** virtual getters can be expensive if called repeatedly without caching. Mitigation: profile before prod run; consider adding manual aggregation in service layer for hot paths.
- **Backward compat:** if any service code reads `doc.productName` (cached field) post-migration, will return undefined. Mitigation: search codebase for all `productName`/`productSku`/`total` refs and update to virtual-aware logic.
