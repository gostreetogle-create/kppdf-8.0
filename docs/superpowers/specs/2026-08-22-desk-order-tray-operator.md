# Design: раскрытый заказ на столе — рабочее место, не простыня

> **Статус:** TZ-DESK-423 DONE (`57b6a7fa`). Gemini 2026-08-22 (красота): берём чистку рамок дерева + сетку правой колонки + не дублировать клиента; не новый flyout-компонент; не цветные бейджи; не глобальный dark-sweep. Следующий код: **TZ-DESK-424**.  
> **Страница:** [`docs/pages/manager-desk.page.md`](../../pages/manager-desk.page.md)  
> **Аудит IA (правый стек):** [`docs/audits/2026-08-22-desk-order-tray-execution-panel-audit.md`](../../audits/2026-08-22-desk-order-tray-execution-panel-audit.md)  
> **Разбор:** Cursor + Claude Code, 2026-08-22. ID DESK-422 уже занят (group-by customer).

## Зачем

Менеджер на `/desk` раскрывает заказ и должен **здесь** понять: что в составе, на какой стадии, что нажать дальше. Не читать абзацы. Не открывать «Редактирует заказ», чтобы добавить изделие.

## Почему снова бардак

IA из аудита 421 **не попала в код** (successor-номер украла другая задача). Tray до сих пор три равные карточки, underline «Открыть», вечная подпись под «Подтвердить», пустой состав → «Добавить линию» → `panel=edit`. Rail «Состав» (`panel=bom`) — заглушка «в следующей волне».

## Канон (не развилка)

- Shared `app-order-hub-tray` (`mode="desk"|"hub"`). Не форк.
- Write позиций = тот же `OrderFormPanelComponent` + `OrdersService`. Не второй CRUD.
- Цвета / hairline / gold rail / chips — как сейчас. Меняется плотность и клики.
- Подсказка — **по нажатию**, не подпись под кнопкой.
- `boardLane` / `readyForWork` из tray **не писать**. Карандаш дерева = каталог (live BOM).
- Hub expand остаётся read-only по заказу. PATCH статуса только `mode="desk"`.
- Не строить чат, Task-очередь, «Оценку в цехе» без числа, отгрузку-API.

## Пустой черновик (цель)

```
[Черновик]  Клиент: …                         [Подтвердить]
────────────────────────────────────────────────────────────
┌ Состав заказа · 0 позиций          ┐  ┌ Исполнение        ┐
│                                    │  │ Готовность —      │
│  [ Добавить изделие ]              │  └───────────────────┘
│                                    │  ▸ Снабжение …          [Снабжение]
└────────────────────────────────────┘  ▸ Логистика и документы [Блокнот]
```

Нет фраз «Нет изделий», «Нет линий», «Добавьте изделия, чтобы…», «Отгрузка пока не ведётся», «Оценка в цехе».

## Есть изделия

Слева: существующее `app-composition-tree` (строка кликается, фото → lightbox). Над каждым корнем — одна строка факта: имя · полоса Комбайна (`boardLane`) · готово/не готово. Кнопка «Добавить изделие» остаётся.

Справа: «Исполнение» всегда открыто (чипы полос + `Готовность X из Y`). Остальное — disclosure, счётчик в заголовке, кнопки не ссылки.

## Кнопки (не underline)

Компактные `min-h-touch` + `border-rule-strong` + `rounded-sm` (как фильтр стола) или `app-pi-button` `size="sm"` `variant="outline"`. Подписи: **Добавить изделие**, **Снабжение**, **Производство**, **Склад**, **Отгрузка**, **Документ**, **Шаблоны**, **Блокнот**. Маршруты/события как сейчас (`from=desk` на производстве).

## Подтвердить

- Включена только `draft` + есть `items` + есть `siteId`.
- Клик → host `OrdersService.update({ status: 'confirmed' })` → reload очереди.
- Иначе кнопка выглядит вторичной (`aria-disabled`), клик по обёртке → toast/status с уже готовым `primaryCtaDisabledReason()`. Вечного `desk-primary-cta-hint` нет.
- «В производство» / «К отгрузке» / «Отгрузить» **не** патчить из tray (rollup Комбайна / POST ship).

## Добавить изделие

`onAddLines` → `panel=bom` (не `edit`). Flyout wide. Внутри `app-order-form-panel` с `variant="items"`: только секция позиций + Сохранить/Отмена. Тот же `onSubmit`. После save — закрыть панель, reload списка, состав остаётся раскрытым.

## Auto-open правых групп

- Снабжение: только `supplyError`.
- Логистика: ошибка броней или статус `ready`/`shipped`.
- Иначе свёрнуты; цифры в заголовке.
