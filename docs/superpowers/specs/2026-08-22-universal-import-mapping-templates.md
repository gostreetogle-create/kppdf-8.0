  показывать читаемые русские подписи полей в выпадающем списке

- **Кнопка «Предложить сопоставление»** — уже есть в UI. Сейчас работает

- **Модуль под ИИ-сопоставление уже заготовлен, но не подключён:**
  `desktop/src/core/ai/` — рассчитан на Ollama/OpenAI-совместимый чат,

## 2. Чего действительно не хватает (новое)

### 2.1 Именованные шаблоны сопоставления (главный запрос PO)

Сейчас: сопоставление полей делается заново на каждый файл, ничего не
запоминается по названию. Нужно: сохранить связку «эти заголовки → эти поля»
под именем, в следующий раз при том же формате — выбрать шаблон из списка,
не подбирать заново.

- Новая backend-сущность `ImportMappingProfile`: `name`, `targetEntity`
  (material/product/module/order — см. §2.3), `columnMap` (JSON: заголовок →
  каноническое поле), `headerSignature` (хэш/список заголовков файла, для
  авто-предложения «похоже на шаблон X»), `createdBy`, org-scope.
- Desktop UI: после ручного/AI-сопоставления — кнопка «Сохранить как шаблон» →
  имя → сохранено. При новом файле: если заголовки совпадают с сохранённым
  `headerSignature` — сразу предлагается «Похоже на шаблон "3D Studio Max
  выгрузка" — применить?», иначе обычный ручной/AI-путь.
- CRUD-экран шаблонов (список, переименовать, удалить) — можно минимальный,
  без отдельной страницы на вебе для v1.

### 2.2 Заказы с сохранением количества (сегодняшняя находка)

Как показал сегодняшний живой тест (`docs/audits/2026-08-22-desktop-import-live-test.md`):
конвейер сейчас пишет только в каталог материалов, поле «Кол-во» нигде не
хранится. Нужно расширить `mutation-journal` / import-task target на `order`
(или сначала `quotation`/КП-строку — уточнить у PO бизнес-приоритет между
этими двумя, я исходно предполагаю КП, т.к. заказ обычно рождается из КП по
`docs/audits/2026-08-08-sales-to-shop-flow-canon.md`) с полем `qty`.
Это уже было осознанно отложено в аудите 2026-08-08 («Order/КП bulk — Defer,
пока HITL каталога не живёт») — сегодняшний тест подтвердил, что HITL каталога
**уже живёт и работает надёжно**, значит условие снято, можно начинать.

### 2.3 Явный выбор «куда льём» (продукт/материал/заказ/КП)

Видение PO — выпадающий список раздела назначения. Сейчас путь определяется
по форме файла (плоский → материал, иерархия → спецификация/BOM), явного
селектора нет. Добавить простой dropdown в начале Import Studio: Материалы /
Продукты / Заказы / КП — так пользователю не нужно помнить, как файл «поймут»
автоматически, дальше это просто уточняет, какой `targetEntity` использовать
при сохранении шаблона (§2.1).

### 2.4 Ошибки → в ИИ на исправление

Issues-панель уже показывает первые 12 ошибок с «…и ещё N» (B8, 2026-08-16).
Не хватает: кнопки «Отправить в ИИ» рядом с ошибками — передаёт список issues
+ пример строк в тот же локальный/MCP-агент (§1), тот предлагает
исправленное сопоставление или правки данных, пользователь подтверждает,
повторная валидация.

## 3. Из чего не лепим заново (границы, из аудита 2026-08-08 — остаются в силе)

- Не вторая БД / не Excel-зеркало.
- Не тихая запись в SoT без propose/confirm.
- Не bulk-запись заказов/КП, пока каталожный HITL не проверен — **снято сегодня**, но других новых обходов проверки не вводим.
- Не автодеплой desktop-сборки без команды PO.

## 4. Предлагаемая последовательность TZ

Roadmap продолжает уже начатую агентами линию (TZD-23→26→38 сделаны), не
параллельную:

1. **TZD-AI-IMPORT-01** — подключить Ollama к `desktop/src/core/ai/`
   (= TZD-AI-02/03 из спеки локального ИИ, тот же код обслуживает обе фичи).
2. **TZD-IMPORT-TPL-01** — backend `ImportMappingProfile` (schema + CRUD API).
3. **TZD-IMPORT-TPL-02** — Desktop UI: сохранить/выбрать/авто-предложить
   шаблон по `headerSignature`; dropdown «куда льём» (§2.3).
4. **TZD-ORDER-IMPORT-01** — journal target `order`/`quotation` line с `qty`
   (нужно решение PO: заказ или КП — см. §2.2).
5. **TZD-IMPORT-FIX-LOOP-01** — кнопка «Отправить в ИИ» на issues-панели.

Роль: 1-2 — Claude Code/Cursor (архитектурные решения, новая схема); 3-5 —
можно Freebuff по готовым точным ТЗ после авторинга.
