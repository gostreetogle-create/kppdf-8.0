# Design: Group Chip Workspace (справочники и любые «много разделов в группе»)

> **Статус:** APPROVED direction PO 2026-08-04 (обсуждение в Cursor).  
> **Код:** не стартовать, пока PO не скажет «стартуем код» / не выданы child-TZ.  
> **Автор:** Cursor Mode A + PO.  
> **Первый экземпляр:** меню «Справочники».  
> **Правило переиспользования:** если итоговый экран понравится PO — **тот же паттерн** обязателен для других зон с несколькими родственными разделами (не изобретать второй «обзор + огромный H1»).

---

## 0. Зачем

Сейчас у справочников:

- выпадающее меню **и** отдельный обзор-карточки → ощущение задвоения;
- на страницах разделов — крупный заголовок + счётчик + tools → пустое место сверху;
- таблицы ещё разношёрстные (следующий слой — table kit).

Нужен один понятный приём: **группа → ряд переключателей → сразу таблица**.

---

## 1. Название паттерна

| RU (для PO) | Код / docs |
|-------------|------------|
| «Экран группы с жёлтыми крошками» | **Group Chip Workspace** |
| Ряд переключателей сверху | **Group chips** (`PiGroupChips` — имя компонента TBD) |
| Зона таблицы под ними | **Workspace body** |

Это **не** классический путь «Справочники › Измерения › Единицы» для возврата назад.  
PO явно отказался от path-breadcrumbs: здесь нет глубокой «дорожки», есть **соседи одной группы**.

---

## 2. Поведение (канон)

### 2.1 Меню

1. Пункт бокового меню **«Справочники»** открывает выпадающий список **по группам**:
   - Классификация  
   - Измерения  
   - Оформление  
   - Документы  
   - (будущие группы…)
2. Клик по **группе** (напр. «Измерения») → маршрут экрана группы (напр. `/dictionaries/measurements` или `/dictionaries?group=measurements` — выбрать в TZ).
3. Пункты «Обзор» как отдельная страница-карточки **больше не нужны** как основной вход (старый hub можно redirect → первая группа или последняя посещённая).

### 2.2 Экран группы

```
┌─────────────────────────────────────────────────────────────┐
│ [Единицы]  [Другой справочник…]  [Ещё…]     ← chips, wrap  │  sticky
│  ▲ жёлтый = активный                                        │
├─────────────────────────────────────────────────────────────┤
│ [поиск] [фильтры…]                    [+ CTA]               │  sticky tools
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   таблица / дерево выбранного справочника                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Правила:

| # | Правило |
|---|---------|
| 1 | Сверху **только** chips справочников **этой** группы. |
| 2 | Активный chip — **жёлтый** (акцент темы Paper & Ink / sunrise, не кислотный). |
| 3 | Неактивные — обычные (hairline / muted). |
| 4 | Клик по chip → та же страница, другая таблица (без огромного H1 «Единицы измерения»). |
| 5 | **Нет** path-строки `Справочники › Измерения`. |
| 6 | **Нет** большого title + отдельной строки «N записей» как главного chrome (счётчик — в tools или в footer таблицы, компактно). |
| 7 | Chips могут переноситься на **2-й ряд**; workspace body сдвигается вниз. |
| 8 | Chips + tools таблицы — **sticky** под app header. |
| 9 | По умолчанию открыт **первый** справочник группы (или last-selected в session — решение в TZ). |
| 10 | Опционально: фильтр/поиск chips по имени или первой букве, если группа разрастётся. |

### 2.3 Сложные справочники

Дерево категорий с drag — **та же оболочка** (chips + body). Меняется только начинка body. Не уводить в отдельный «особый» chrome без причины.

---

## 3. Переиспользование (критично для PO)

> Если итоговая страница с chips понравится — **тиражируем** на все места, где есть «много категорий / разделов одного семейства».

Примеры кандидатов (не исчерпывающий список):

- Справочники (первый пилот)
- Документы (шаблоны / тексты / таблицы — если групп много)
- Склад / номенклатура (если появятся подгруппы)
- Любой будущий «раздел с 3+ соседними списками»

**Запрещено** после принятия паттерна:

- снова делать отдельный hub-карточки + дублирующий dropdown с теми же ссылками без групп;
- возвращать тройной chrome (eyebrow + H1 + description + section) на таких экранах;
- делать уникальный «только для справочников» chrome, который нельзя вынести в shared UI.

Компоненты класть в shared UI / shared page (рядом с `PiDictionaryShell` → эволюция или замена на `PiGroupWorkspace`).

---

## 4. Связь с таблицами

Отдельный трек (не блокирует спеку chips, но желателен следом):

| Вариант таблицы | Зачем |
|-----------------|--------|
| Flat | обычный список (единицы, цвета) |
| Expandable row | строка раскрывается, внутри состав |
| Tree / reorder | категории |

Снаружи — один визуальный язык (`pi-table` family). Смена дизайна в kit → везде.

Пилот Group Chip Workspace может временно жить на текущих таблицах; унификация table kit — Wave 2 / отдельные TZ.

## 6. Acceptance (для будущих TZ)

1. Клик группа в меню → экран группы с chips, без path-breadcrumbs.  
2. Жёлтый = активный chip; клик переключает body.  
3. Нет гигантского H1 раздела как основного chrome.  
4. Sticky chips + tools; wrap chips ок.  
5. Паттерн задокументирован здесь + кратко в `docs/PO-DIARY.md` §5.  
6. При тираже на другую зону — ссылка на **этот** файл как SoT паттерна.

---

## 7. Не делать в пилоте

- Аккордеон «карточка раскрывает таблицу на той же простыне всех групп».  
- Master-detail слева список / справа таблица (отложен, если chips не зайдут).  
- Менять backend API справочников.  
- Полный table kit в том же TZ, что и chips (можно параллелить вторым агентом после shell chips).

---

## 8. Решение PO (зафиксировано)

| Тема | Вердикт |
|------|---------|
| Path `Справочники › Группа` | **Нет** |
| Chips соседей в группе, жёлтый активный | **Да** |
| Сразу таблица под chips | **Да** |
| Dropdown меню по группам | **Да** (не «на всякий случай», а на рост) |
| Тираж паттерна на другие multi-section экраны | **Да, если пилот понравится** |
