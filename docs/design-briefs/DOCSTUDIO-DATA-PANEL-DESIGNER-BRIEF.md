# Бриф дизайнеру: панель «Данные» в Документ-студии

> **Назначение:** внешний / UI-дизайнер. Не код, не backend.  
> **Экран:** вкладка **«Докум.»** → редактор студии → левый icon-rail → **«Данные»**.  
> **К брифу приложите скриншот** текущего UI (ориентир по стилю продукта).  
> **Дата канона содержимого:** 2026-09-06 · источник правды по смыслу: `docs/pages/document-studio.page.md`, аудит IA `docs/audits/2026-09-05-docstudio-data-panel-ia-audit.md`.

---

## 0. Что от тебя нужно

Спроектировать **читаемую, плотную, красивую** раскладку панели «Данные» (+ соседний буфер «Выбрано»), опираясь на:

1. **список данных и их вид** ниже (что именно лежит в панели);
2. **скриншот нашего продукта** (цвета, типографика, плотность, иконки);
3. **наши UI-законы** в §7–8.

**Не нужно:** придумывать новые сущности ERP, менять бизнес-смысл полей, рисовать правый rail (Элементы / Слои / Свойства) или сам лист A4 — только левая зона **Данные / Выбрано** и то, как данные внутри неё выглядят и группируются.

Визуальный язык, сетка карточек, иерархия, пустые состояния, микровзаимодействия — **твоя зона мастерства**. Мы фиксируем **что** должно быть и **в каком виде данные** (тип контента), чтобы ты выбрал правильный UI-паттерн.

---

## 1. Контекст продукта (одним абзацем)

Это цеховой ERP (~10 пользователей). **Документ-студия** — рабочее место менеджера: по центру лист A4 (КП, договор, паспорт…), слева и справа — вертикальные **icon-rails** с выезжающими панелями **поверх** листа (лист **не сжимается** и не уезжает).

Оператор открывает **«Данные»**, чтобы привязать к документу:

- **товары из каталога** (что попадёт в таблицу на листе),
- **кому** документ (клиент / плательщик),
- **связи** с уже существующим КП или заказом,
- редкие поля (**поставщик**, наша фирма).

Отдельно — буфер **«Выбрано»**: что уже набрано из витрины, откуда вставляют на лист.

## 2. Каркас меню (IA — не менять смысл)

```
Левый chrome-rail (иконки)
  ├─ «Данные»     → широкая overlay-панель
  │     TOC (горизонтальные/сегментные вкладки внутри панели):
  │       Товары | Кому | Связи | Ещё
  └─ «Выбрано»    → более узкая overlay-панель
                    список выбранного + CTA «Вставить на лист»
                    на иконке rail — badge с числом позиций

Центр: лист A4 (не трогаем)
Правый rail: Элементы / Слои / Страницы / Свойства / Шаблон (не трогаем)
```

**Правила каркаса**

| Правило | Почему |
|---------|--------|
| «Выбрано» — **отдельная иконка** под «Данные», не вкладка TOC | PO: буфер = отдельный жест; не смешивать с витриной |
| Внутри «Данные» — **макс. 4 пункта TOC** | Не плодить иконки rail |
| Дефолт TOC при открытии — **Товары** | Главный сценарий КП |
| Повторный клик по активной иконке / клик по листу — панель сворачивается | Геометрия студии |
| Панель = **overlay** поверх серой зоны и частично листа | Лист A4 **не reflow** при open/close |

Ширины: ориентируйся на скрин / текущий shell. «Данные» — **wide** (витрина-сетка). «Выбрано» — уже (~340px-класс). Не делай «Данные» узкой колонкой селектов — там магазин каталога.

## 3. Словарь (чтобы подписи не врали)

| На экране (RU) | Смысл для менеджера | Не путать с |
|----------------|---------------------|-------------|
| **Клиент** | Кому продаём / покупатель | Наша фирма |
| **Плательщик** | Кто платит (часто = клиент) | Клиент |
| **Поставщик** | Редко для КП; другие типы документов | Клиент |
| **Наша фирма / Исполнитель** | Мы (уже задана системой) | Клиент |
| **КП** | Коммерческое предложение (коротко «КП», не длинная фраза) | Заказ |
| **Заказ** | Производственный/продажный заказ | КП |
| **Товары** | Изделия / модули / детали / материалы из каталога | Строки уже существующего КП |

## 4. Инвентарь данных — что показать и **в каком виде**

Дизайнеру: колонка «Вид данных» = подсказка паттерна (карточки / селект / chip / read-only строка). Конкретный виджет — твой выбор, если он читается лучше.

### 4.1 TOC · Товары (главный экран)

**Задача:** как витрина магазина — найти позицию и явно **Добавить / Убрать**.

| Что | Вид данных | Поля / признаки на UI | Поведение / состояния |
|-----|------------|------------------------|------------------------|
| Переключатель типа каталога | Segmented / chips | **Изделия · Модули · Детали · Материалы** | Один активный тип за раз |
| Поиск (если есть в продукте) | Однострочный input | placeholder по типу | Не раздувать шапку |
| Сетка позиций | **Карточки каталога** (compact) | Миниатюра фото (или placeholder), **название** (макс. 2 строки), **артикул/SKU** (1 строка, ellipsis), опционально цена/краткая мета | Только **вертикальный** скролл; длинные имена **не** разъезжают сетку вширь |
| Действие на карточке | Явные кнопки/тоггл | **Добавить** / **Убрать** (или эквивалент «в витрине / выбрано») | Не «аккуратно кликай по всей карточке» без affordance; spam-клики не должны выглядеть как ошибка |
| Состояние «уже в буфере» | Визуальный акцент на карточке | Отличие от «ещё не выбрано» | Должно считываться за 0.5 с |

**Не смешивать** на этом экране селекты клиента/КП — это другие вкладки.

---

### 4.2 Rail · Выбрано (буфер)

**Задача:** увидеть накопленное и одним жестом отправить на лист (в таблицу).

| Что | Вид данных | Поля | Поведение |
|-----|------------|------|-----------|
| Список выбранного | **Chips / компактные строки** (не огромные карточки) | Тип (изделие/модуль/…), короткое имя, снятие (×) | Удаление из буфера синхронно с витриной |
| Пусто | Empty state | Короткий текст вроде «Ничего не выбрано — добавьте в Товарах» | Без псевдо-дашборда |
| Badge на иконке rail | Число | Count позиций | Видно, когда панель закрыта |
| CTA | Primary-кнопка | **«Вставить на лист»** | Главное действие буфера; не прятать |

Смысл для дизайна: это **корзина**, не второй каталог.

---

### 4.3 TOC · Кому

**Задача:** привязать покупателя документа (якорь для подстановки имени/реквизитов в текст и PDF).

| Что | Вид данных | Содержимое списка / карточки | Поведение |
|-----|------------|------------------------------|-----------|
| **Клиент** | **Одиночный выбор** из справочника (select / searchable picker) | Название контрагента (юрлицо/имя); в списке — понятная подпись | Первый пункт: **«— не выбрано —»** (явный сброс). После выбора — chip/строка «выбрано: …» |
| **Плательщик** | То же, но **вторично** | Тот же тип сущности (контрагент) | По умолчанию **скрыт** за disclosure: «Указать плательщика отдельно». Если уже задан — блок открыт. Если не указан — в жизни плательщик = клиент (не дублировать два одинаковых селекта без нужды) |

**Вид данных:** не витрина-сетка; это **1 выбранная сущность** (singleton), не корзина товаров.

---

### 4.4 TOC · Связи

**Задача:** связать лист с уже существующим **КП** или **Заказом**, чтобы подтянуть номер и/или строки в таблицы.

| Что | Вид данных | Что видно в опции | Поведение |
|-----|------------|-------------------|-----------|
| **КП** | Одиночный select / picker | Номер + краткий контекст (клиент/дата — если есть в API) | Label строго **«КП»**. Пункт сброса «— не выбрано —» |
| **Статус КП** | Селект статусов (когда релевантно) | Черновик / на проверке / принято (или актуальный набор продукта) | Показывать только если сценарий документа это требует (`showKpStatus`) |
| **Заказ** | Одиночный select / picker | Номер заказа + краткий контекст | Сброс «— не выбрано —» |
| Подсказка | Одна строка helper-text | Смысл: «подставятся номер и строки» | Не эссе; не графики |

**Каскад (логика продукта, учесть в UX):** выбор КП/заказа может **автозаполнить Клиента**, если клиент ещё пуст — не пугать менеджера «магией»; достаточно тихого обновления в «Кому».

**Вид данных:** связи = **документы-ссылки** (один к одному), не каталог и не multi-select корзина.

---

### 4.5 TOC · Ещё

**Задача:** редкое и служебное — не отвлекать от КП.

| Что | Вид данных | Поля | Поведение |
|-----|------------|------|-----------|
| **Поставщик** | Одиночный select / picker | Контрагент или организация | Hint: «редко для КП» |
| **Наша фирма** | **Read-only строка** | Имя организации | **Не** селект; задаётся системой. Подпись вроде «Наша фирма: …» |

## 5. Главный сценарий менеджера (проверь макет на нём)

1. Открыл студию → **Данные** → **Товары**.  
2. Добавил 3–5 позиций (кнопки явные).  
3. Открыл **Выбрано** → видит список → **Вставить на лист**.  
4. При необходимости **Кому** → выбрал Клиента.  
5. Если документ из существующего КП — **Связи** → выбрал КП (клиент подтянулся сам, если был пуст).  
6. **Ещё** почти не открывает.

Если макет заставляет прыгать по пяти экранам ради шага 1–3 — пересобери иерархию внутри этих же вкладок (не добавляя новых сущностей).

---

## 6. Что сознательно НЕ входит в этот бриф

- Правый rail, свойства таблицы, формулы, rich-text, PDF-кнопки.  
- Авто-вставка таблицы при каждом «Добавить» без клика (шум).  
- Новые поля «на вырост» (договор, счёт, invoice…) без отдельного запроса.  
- Перенос legacy Builder / старого doc-constructor.  
- Смена бизнес-имён (Клиент ≠ Organization и т.д.).

---

## 7. Глобальные законы UI нашего продукта (обязательны)

1. **Русский UI.** Короткие подписи. «КП», не «Коммерческое предложение».  
2. **Важные данные не прятать ради «воздуха».** Плотность > декоративный whitespace.  
3. **Light и dark** должны оставаться читаемыми (контраст текста/иконок). Ориентир палитры продукта: холодный paper/graphite + сдержанный акцент (золото/teal по скрину), без фиолетовых SaaS-градиентов.  
4. **Hairline, не тени.** Разделение секций — тонкие линии / tonal lift, не тяжёлый Material elevation.  
5. **Углы:** интерактив (кнопки, inputs, badges) — слегка скруглённые; структурные панели — спокойнее, без «пилюль everywhere».  
6. **Иконки:** линейные (Lucide-класс), тонкий stroke; не filled Material-каша.  
7. **Панель = overlay.** Не проектируй layout, где открытие «Данные» сдвигает/сжимает лист A4.  
8. **Destructive / сброс** — осознанный (пустой пункт «не выбрано», снятие chip), без случайных жестов.  
9. **Одна явная обратная связь** на действие (добавил / убрал / вставил) — состояние меняется заметно.  
10. **Формы плотные:** ширина контроля ≈ содержимому; не растягивать селект на всю wide-панель «для красоты».  
11. **Валидация без прыжков layout** (если покажешь ошибку у поля — не выталкивать сетку).  
12. **Студийная витрина = магазин:** явные Добавить/Убрать; карточки компактные.

Детали визуальной системы (если нужно углубиться): `docs/design-spec.md`, `docs/paper-and-ink.md`, `docs/DARK-THEME.md`, геометрия студии: `docs/pages/kp-workspace-geometry.md`.

## 8. Антипаттерны (reject на ревью)

- Всё в одну простыню: витрина + клиент + КП без TOC.  
- «Выбрано» снова спрятано третьей вкладкой внутри «Данные».  
- Карточки каталога как огромные marketing-tiles.  
- Горизонтальный скролл в витрине из-за длинных названий.  
- Длинные английские labels / жаргон (`Counterparty`, `Quotation`) на UI.  
- Дашборд со статистикой, графиками, «insight chips» в этой панели.  
- Второй способ выбрать клиента в трёх разных местах панели.

---

## 9. Ожидаемые артефакты от дизайнера

1. **Макет панели «Данные»** — все 4 TOC-состояния (Товары / Кому / Связи / Ещё).  
2. **Макет «Выбрано»** — пусто + 3–7 позиций + CTA.  
3. **Состояния карточки витрины:** обычная / в буфере / hover (если уместно).  
4. **Краткая заметка** (½ страницы): почему так сгруппировал и какой паттерн для singleton vs multi.  
5. Опционально: dark-вариант одной ключевой вкладки (Товары).

Формат: Figma / аналог. Привязка к нашему скриншоту по цвету и плотности важнее «нового бренда с нуля».

## 10. Промпт одной вставкой (скопировать дизайнеру)

```
Ты UI-дизайнер. Продукт — цеховой ERP. Экран: Документ-студия (лист A4 по центру).
Спроектируй ТОЛЬКО левые панели «Данные» и «Выбрано» (icon-rail слева, overlay поверх листа; лист не сжимать).

Каркас (не менять смысл):
— «Данные» = широкая панель с TOC: Товары | Кому | Связи | Ещё (дефолт Товары).
— «Выбрано» = отдельная иконка под «Данные», badge с числом, буфер + кнопка «Вставить на лист».

Данные и вид:
1) Товары — витрина каталога (сегмент Изделия/Модули/Детали/Материалы): компактные карточки (фото, название ≤2 строк, артикул 1 строка), явные Добавить/Убрать, только вертикальный скролл.
2) Выбрано — корзина chips/строк + empty state + primary CTA «Вставить на лист».
3) Кому — одиночный выбор Клиента (select/picker + сброс «не выбрано»); Плательщик вторично, за disclosure «Указать отдельно».
4) Связи — одиночный выбор «КП» (коротко так) и «Заказ» + сброс; опционально статус КП; одна строка-подсказка про номер/строки.
5) Ещё — Поставщик (редко) + read-only «Наша фирма: …».

Словарь: Клиент = покупатель; КП ≠ Заказ; Наша фирма ≠ Клиент.

Стиль: ориентируйся на приложенный скриншот нашего UI. Плотность, русский язык, hairline вместо теней, без фиолетового SaaS-глянца, без дашборд-виджетов. Важные данные не прятать. Витрина как магазин.

Не трогай правый rail и сам лист A4. Не добавляй новые сущности «на вырост».
Отдай: 4 состояния TOC + Выбрано (пусто/заполнено) + состояния карточки витрины.
```
