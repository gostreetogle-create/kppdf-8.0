## Acceptance criteria

- Both list endpoints return `{ items, total, page, limit }`.
- Missing and invalid pagination inputs resolve to safe defaults/clamps.
- Search is applied before pagination and `total` matches the filtered set.
- Empty pages return an empty `items` array with valid metadata.
- Both pages render server-side pagination and total/range information.
- Search resets to page 1; page navigation requests the selected page.
- Existing loading/error/empty states and users/roles mutations remain functional.
- A single page action does not create uncontrolled duplicate list requests.
- Targeted tests, backend/frontend typechecks, frontend development build,
  `git diff --check`, and `bash OrchestratorKit/verify-status.sh` are recorded.
