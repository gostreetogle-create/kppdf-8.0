=== ШАГ 1: Aliases (FE+BE parity) ===

BE `COLUMN_ALIASES.price` (studio-data-resolver.ts): added `listprice`,
`list_price`, `baseprice`, `base_price`, `priceperunit`, `price_per_unit`
(the exact catalog field names `fetchLiveRows` itself reads via
`item['listPrice'] ?? item['basePrice'] ?? item['pricePerUnit']`) — a
manually-typed or registry-template column using one of those names used to
silently fail to bind (only `price`/`unitPrice` matched before).

FE `STUDIO_STANDARD_COLUMN_ALIASES` (studio-table-defaults.ts): same price
additions for parity; added `name` (BE parity, was missing) and `sum`
(`sum`/`total`/`amount`/`сумма`, BE already had it) groups — both needed
for `isKnownStudioColumnKey`'s type-select lock (ШАГ4) to cover every
standard key, not just the ones offered as quick-add chips.

=== ШАГ 2: Quick-add «+ Сумма» ===

`STUDIO_STANDARD_COLUMN_FIELDS` gained `{ key: 'sum', label: 'Сумма', type:
'currency', align: 'right' }`. `missingStandardColumnFields`/
`createStandardStudioTableColumn` are already generic over this array (no
code change needed beyond the new entry) — the chip appears only when no
existing column key matches a sum-alias, exactly mirroring how «+ Цена»
already worked.

=== ШАГ 3: Heal labels on add/rehydrate ===

New `healStudioTableColumns(columns)` in `studio-table-defaults.ts`: for
each column, if the (trimmed, case-insensitive) label is empty or exactly
"цена" AND the key is a sum-alias -> label becomes "Сумма"; if empty/"цена"
AND the key is a price-alias -> label becomes "Цена". A deliberate custom
label (anything else) and any unrecognized key are left untouched — this
directly reproduces-then-fixes the PO screenshot bug: two columns both
titled "Цена" (one actually price, one actually sum) heal into "Цена" +
"Сумма" respectively. Wired into the single existing choke point for every
column-structure change, `emitColumnStructure()` in
`studio-table-properties.component.ts` (add/remove/reorder/rename-key/
rename-label all funnel through it already) — the same path S47's
live-rows rehydrate already runs through, per the TZ's own instruction.
Also folds in ШАГ4's type-canon (below) into the same function/call site.

=== ШАГ 4: Type-select lock ===

New `isKnownStudioColumnKey(key)` — true for any key recognized by a
standard alias group (name/qty/price/sum/unit/sku/photo/description).
`lineValue` (backend hydrate) and the canvas both bind purely by
`column.key`; `column.type` is never read for these — the FE select made it
look like a working control that silently did nothing when changed for a
standard key. The type `<select>` in `studio-table-properties.component.ts`
is now `[disabled]` when `isKnownColumnKey(col.key)` is true (kept, not
hidden, to avoid reflowing the column-row's fixed CSS grid columns per-row)
and carries a `title` hint ("Тип не влияет на подстановку из каталога —
определяется по ключу колонки"), true for every type-select regardless of
disabled state since the underlying fact is universal. `healStudioTableColumns`
also canonicalizes `type` for known keys on every structure change (qty ->
number, price/sum -> currency, every other known key -> text); an
unrecognized/custom key's type is left exactly as the operator set it via
the still-live select.
