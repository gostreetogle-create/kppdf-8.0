=== ЭТАП C — dead controls / col-width apply (absorbs TZ-NX-DOCSTUDIO-TABLE-COL-WIDTH-APPLY, 2026-09-13) ===

`col.width` (1-100) was saved by the Свойства column editor since it existed but
never read anywhere: BE `renderStudioTableHtml` always did `Math.round(100 /
columns.length)` (pure equal split); canvas `<th>`/`<td>` had no width styling
at all. A genuinely dead control per the necessity matrix ("либо apply, либо
убрать поле").

Fix (apply, not remove — TZ's own preferred branch when apply is feasible):
- `columnWidthPercents(columns)` — new helper, mirrored identically on BE
  (`studio-data-resolver.ts`) and FE (`studio-table-defaults.ts`): clamps each
  `col.width` to [1,100], falls back to the previous equal-split when no column
  has a width set at all (sum 0 — the common case for existing tables, so no
  silent behavior change for anyone who never touched this field), otherwise
  scales proportionally to sum to exactly 100 (last column absorbs the
  rounding remainder).
- BE `renderStudioTableHtml`: `th`/`td` `style="...;width:${pct}%"` from the
  helper (PDF/preview HTML).
- FE canvas (`studio-blocks-canvas.component.ts`): `[style.width.%]` on
  `th`/`td` via a new `colWidthPct(block, index)` method; added `table-layout:
  fixed` to `.table-preview table` (previously auto layout, which would have
  let long cell content silently override the percentages — matches BE's own
  inline `table-layout:fixed`, canvas and PDF/preview now agree).
- Properties UI: width input gets `aria-label`/`title="Ширина, %"` +
  `placeholder="%"`, plus one hint line under "Структура колонок": "Ширина
  колонок, % — сумма ≈ 100%". No new layout — reused the existing `.table-props__hint`
  style.

≤1 active template assert (necessity matrix: "Несколько одинаковых «Продукты»
active → DELETE data; при checkout — assert ≤1 active per canon name/dataSource"):
live Mongo check (local dev, same DB as this whole wave's evidence) —
4 total `table_templates` documents (2 inactive, presumably the old duplicates
from the prior KINDS-DISCOVER migration), exactly 2 ACTIVE, grouped by
