=== ЭТАП B — SoT + source round-trip (2026-09-13) ===

Merged `onTableSourceChange` and `setBlockCatalogSource` (near-duplicate write
paths per the source-select audit) into one `applyTableSource(blockId, source)`,
queued via `enqueueDocumentWrite` (the same wave-1 `catalogWriteChain`) since it
carries a document `expectedRevision` just like addPage/hydrate. `patchTableSettingsForBlock`
was converted to `async`/`Promise<boolean>` so Insert can await the template-apply
step before firing the catalog-source `putDataSet` write.

Fixes (source-select audit B1-B3):
- B1: switching to `manual` now explicitly sets `liveRows: null` (not left as a
  stale array, even `[]`) — canvas's `Array.isArray` check was keeping an empty
  table rendered forever instead of falling back to the manual sample rows.
- B2: `dataSource` is now persisted to the block via `blocksService.update`
  (`patchTableSettingsForBlock`), not only the local `blocks` signal + the
  document's `dataSets` entry — previously the block and the dataSet could
  disagree after F5.
- B3: switching to a catalog kind with an empty «Выбрано» now toasts an honest
  error ("в «Выбрано» нет товаров этого вида") instead of a success message that
  implied rows arrived.

Insert->registry-template SoT (kind-vs-source audit):
- Insert (`insertCatalogTable`) now looks up the registry's active `TableTemplate`
  matching this catalog kind's `dataSource` and applies its columns via
  `patchTableSettingsForBlock`, instead of silently leaving `STUDIO_DEFAULT_TABLE_COLUMNS`
  (3 hardcoded columns) as the outcome. No match -> `toast.error` pointing at
  Реестры -> Виды таблиц (source is still wired; a missing template doesn't
  block Insert entirely).
- **Live Mongo check caught a real bug before it shipped**: the actual seeded
  "Продукты" template is tagged `dataSource: "product"` (singular, no `catalog-`
  prefix) — an exact `=== 'catalog-products'` match (the initial implementation)
  would NEVER have fired against real registry data, silently defeating the
  whole fix. Replaced with `normalizeCatalogDataSourceKey()` (strips `catalog-`
  prefix and a trailing `s` on both sides before comparing), tolerant of
  whatever singular/plural/prefix convention was used when a template was
  tagged in the registry UI. New unit test locks in this exact real-world value.
