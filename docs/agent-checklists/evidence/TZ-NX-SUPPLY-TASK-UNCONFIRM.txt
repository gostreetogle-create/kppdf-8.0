=== ШАГ 1: BE reverse ===

`STATUS_FLOW['confirmed']` extended from `['ordered']` to `['ordered', 'draft']`
— `assertTransition()` (already used by `confirm`/`markOrdered`/`markReceived`)
now also permits `confirmed -> draft`, reusing the exact same guard mechanism
and error message format instead of a bespoke check.

New `SupplyTaskService.unconfirm(id, organizationId?)`:
  - `assertTransition(doc.status, 'draft')` — only succeeds from `confirmed`.
  - `doc.status = 'draft'`, `doc.confirmedBy = undefined`,
    `doc.confirmedAt = undefined`, `doc.save()` (same unset-via-undefined
    pattern already used elsewhere in the codebase, e.g.
    `product-module.service.ts`'s `mainPhotoId`).

New `POST /api/supply-tasks/:id/unconfirm` controller endpoint, same
`@Roles('admin','manager')` + `@AuditAction` shape as `confirm`/`ordered`/`received`.

=== ШАГ 2: FE ===

`PiSupplyTasksService.unconfirm(id)` — `POST /supply-tasks/:id/unconfirm`,
mirrors `confirm()`.

`supply.page.ts`: on a `confirmed` row, a new outline button **"В черновик"**
(`data-test="supply-unconfirm-<id>"`, `aria-label`/`title` "Отменить
подтверждение, вернуть в черновик") sits next to "Заказано" — `onUnconfirm()`
calls the new service method and reloads on success.

=== ШАГ 3: UX accidental-confirm guard ===

`onConfirm()` no longer calls the API directly on click. It opens
`AlertDialogComponent` (same `dialog.open()` + `onDialogCloseOnce()` pattern
as `confirmDirtyClose` in `dirty-dialog.guard.ts` — the project's existing
no-native-`confirm()` canon) with title "Подтвердить задачу снабжения?" /
confirmLabel "Подтвердить" / cancelLabel "Отмена", and only calls
`supplyApi.confirm()` if the dialog resolves `true`.
