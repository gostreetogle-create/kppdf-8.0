=== ШАГ 1: Чипы токенов (default path) ===

Root cause confirmed by reading, matching the audit exactly: S44 added CSS
for `.substitution-token` (color/margin), but `studio-blocks-canvas.component.ts`'s
`textHtml()` was a bare `bypassSecurityTrustHtml(raw)` — it never called
`migratePlainTokensToNodes` (the function that wraps `{{…}}` in that span),
so the class never existed in the DOM. The RTE dialog already called it
(`pi-rich-text-editor.component.ts` line 418/445) — only the CANVAS view
never did.

Fix: `textHtml()` now calls the new `studioTextDisplayHtml(raw, mode, bag)`
helper (`studio-block-helpers.ts`), which chips via the SAME
`migratePlainTokensToNodes` the RTE already uses (re-exported from
`@kppdf/ui/rich-text`'s barrel — was previously internal to
`substitution-token.extension.ts`, not part of the public API surface) in
`tokens` mode.

Canvas CSS upgraded from color+margin only to the full chip look (mono
font, padding, background, border, border-radius) — copied from the RTE's
own `.substitution-token` style (`pi-rich-text-editor.component.ts`) so a
token looks identical whether being edited or just viewed, per the TZ's
"mono + фон/бордер + info" wording. Uses `em` for font-size (not RTE's
fixed `11px`) since canvas text blocks have variable per-block font sizes.

Confirmed via reading `studio-editor.page.ts`'s template that
`pi-studio-blocks-canvas` only ever renders in the `@else` branch of
`viewMode() === 'preview'` — Просмотр is a completely separate
server-rendered `<iframe [srcdoc]>` fed by `documents.preview()`. The new
canvas-only CSS therefore cannot leak into Просмотр/PDF by construction,
not just by convention.

=== ШАГ 2: Toggle in Свойства текста ===

New segment `data-test="studio-token-display-mode"` (`Токены` |
`Значения`) at the TOP of `studio-text-properties.component.ts`, always
visible for a selected text block. State lives in `studio-editor.page.ts`
as a plain session signal (`tokenDisplayMode`) — NOT per-block, NOT
persisted to Mongo (resets to default `tokens` on F5, per ACCEPT #4).
Threaded through the existing `StudioPropertiesPanelComponent` wrapper
(pass-through `@Input`/`@Output`, no new logic there) down to
`StudioTextPropertiesComponent`, and separately down to
`StudioBlocksCanvasComponent` (canvas reads it directly as an `@Input`,
does not go through the properties panel).

=== ШАГ 3: «Значения» mode — display-only, no write-path ===

New pure functions in `studio-block-helpers.ts`:
  - `resolveStudioTokenValue(bag, path)` — dotted-path walk into a flat
    bag, deliberately mirroring `DocumentRenderService.renderHtml`'s inner
    `substitute()` regex/reduce walk exactly (same key.path semantics,
    same array-index support) so a token that resolves in Preview/PDF
    resolves the same way here. Returns `null` (not `''`) for an
    unresolved path.
  - `renderStudioTokensAsValues(html, bag)` — replaces each `{{token}}`
    with its resolved value as plain escaped ink (TZ's own "не chip"
    wording for resolved values); an UNRESOLVED token keeps the exact same
    chip markup `migratePlainTokensToNodes` would give it — the chosen
    option between "оставить chip или «—»" (documented here per the TZ's
    "выбрать одно, задокументировать" instruction): a resolved token
    turning to plain ink next to an unresolved one still wearing its chip
    IS the signal that it didn't resolve, no separate "—" placeholder
    needed.
  - `studioTextDisplayHtml(raw, mode, bag)` — the single entry point
    `textHtml()` calls; `tokens` -> `migratePlainTokensToNodes`, `values`
    -> `renderStudioTokensAsValues`.

Bag source, per the TZ's own preference order (Domain preflight): NOT a
new backend resolve API. `editorSubstitutionBag` in `studio-editor.page.ts`
is a `computed()` built ENTIRELY from context this editor session already
loads (`issuerOrgs`/`issuerOrgId` -> `organization`; `counterparties`/
`counterpartyId`/`payerId`/`supplierId` -> `counterparty` + `anchor.client|
payer|supplier`; `quotations`/`quotationId` -> `quotation`;
`orders`/`orderId` -> `order`) — covers exactly the token namespaces the
audit's own repro used (`{{organization.shortName}}`). Deeper/rarer paths
(server-side cascade fallbacks, fields this editor never fetches like
`organization.logoUrl`) are an explicit, documented known_limitation, not
silently wrong — they render as an unresolved chip.

dblclick-to-edit (`openTextBlock` -> RTE dialog) needed ZERO code change to
satisfy "always edits tokens (source), regardless of canvas mode" — the
RTE is a structurally separate component with its own independent
`migratePlainTokensToNodes` call on `block.content` (the raw source, never
touched by the canvas's display-only substitution) — live-verified below.

=== Live verification (local dev, admin/admin123) ===

Real browser (Playwright), one throwaway document with a text block
`"Klient: {{counterparty.shortName}}"` and `context.counterpartyId` set to
a real Counterparty ("ООО «Загородный Дом»", shortName "Загородный Дом"):
  1. Default load: canvas `.substitution-token` chip count = 1, chip text
     = the raw token — confirmed chips-by-default (ACCEPT #1).
  2. Opened Свойства via the Слои panel's «Свойства» row-jump (canvas
     click is unreliable — the Данные flyout overlaps it by default,
     same finding as the PRICE-SUM TZ's live check). Segment control
     present.
  3. Clicked «Значения»: canvas text became "Klient: Загородный Дом" —
     the REAL counterparty's shortName, resolved live — chip count = 0
     (ACCEPT #2, plain ink not chip, confirmed exactly).
  4. Double-clicked the block to open the RTE dialog: RTE content STILL
     read "Klient: {{counterparty.shortName}}" (raw token) — confirmed
     dblclick-to-edit is completely independent of canvas display mode,
     with zero special-casing needed in the implementation.
  5. Clicked back to «Токены»: canvas reverted to the chip (count = 1)
     without a page reload — ACCEPT #3 confirmed.
  Cleanup: `db.studio_documents.deleteOne` + `db.template_blocks.deleteMany`
  via `docker exec kppdf-mongo mongosh` immediately after.

An EARLIER attempt in this same session tried to use `{{organization.*}}`
by PATCHing the throwaway doc's `organizationId` to a non-fallback
`isOurCompany` org for the live repro — this immediately reproduced
TZ-NX-DOCSTUDIO-ISSUER-SELECT's own documented known_limitation (403
"belongs to another organization scope" self-lockout on the very next
request), so that document was abandoned and deleted via direct Mongo
before any further calls; the counterparty-anchor scenario above was used
instead specifically BECAUSE it carries none of that scope-lockout risk
(counterparty selection only touches `document.context`, never
`document.organizationId`).

Просмотр/PDF chip-isolation was NOT separately live-verified (no code
change touches `document-render.service.ts`'s `substitute()`, which never
wraps a resolved value in any span at all, chip or otherwise — confirmed
by reading, not assumed) — a live PDF/Просмотр round-trip would only be
re-confirming pre-existing, untouched behavior.
