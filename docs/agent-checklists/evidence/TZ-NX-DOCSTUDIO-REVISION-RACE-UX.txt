=== ШАГ 1: One queue for every revision-gated write ===

New `private enqueueDocumentWriteAndWait<T>(run): Promise<T>` (alongside
the existing `enqueueDocumentWrite`) for callers that need the queued
write's own result (`createTableBlock`/`createImageLayer`'s `.then()`
activates the new layer) — same `catalogWriteChain`, kept as `Promise<void>`
internally via `.then(() => undefined)`.

`saveLayouts` is now called via a new `enqueueLayoutSave()` wrapper that
resolves an explicit `Promise<boolean>` from inside a queued run —
`schedule()`/`flushLayouts()`'s EXTERNAL contract (debounce timer,
"already pending → return that promise", "not dirty → resolve true") is
byte-for-byte unchanged; only what actually fires when the timer elapses
is now serialized against every other document write.

Every bare `firstValueFrom(this.documents.update/putDataSet/...)` outside
the queue (createTableBlock/createTextLayer/createImageLayer/onDocTypeChange/
patchDocumentContext/openRenameDialog/toggleOrientation/
rehydrateLiveRowsAfterColumnChange) is now wrapped in
`enqueueDocumentWrite`/`enqueueDocumentWriteAndWait`.

=== ШАГ 2: Honest dialog vs toast ===

New module-level `isRevisionConflict(result: SilentResult<unknown>): boolean`
— `status === 409` (sufficient on its own: grepped the ENTIRE
studio-document + template-block backend modules, confirmed exactly ONE
`ConflictException` throw site in the whole domain,
`STUDIO_DOCUMENT_REVISION_CONFLICT` — no other 409 flavor exists here to
misclassify), with the body `code` matched too when present as a
belt-and-suspenders check.

New `private reportWriteFailure(result, fallback?)`: routes to `conflict()`
only when `isRevisionConflict(result)`; every other failure is
`toast.error(extractErrorMessage(result.error) || fallback)`. This is now
the ONLY way any of the 23 audited call sites reaches `conflict()` — a
final grep for `this.conflict()` after all edits shows exactly one call
site left: inside `reportWriteFailure` itself.

Every non-revision-gated block PATCH site (`patchImageBlock`,
`patchBlockStyle`, `applyBlockContent`, `patchBlockTitle`, `toggleLock`,
`toggleVisible`, `deleteLayerById`, `patchTableSettingsForBlock`) now
routes its failure through `reportWriteFailure` too — structurally these
endpoints don't send `expectedRevision` so `isRevisionConflict` can never
fire true for them, meaning they always toast (defense-in-depth: correct
even if one of these endpoints were ever given a revision gate later).

=== ШАГ 3: One soft retry ===

New `private async attemptWithRevisionRetry<T>(request: (doc) =>
Observable<SilentResult<T>>): Promise<SilentResult<T> | null>`: reads
`this.document()`, fires `request(doc)` once; if the result is a genuine
revision conflict, `getById` → `document.set` → fires `request(refreshed)`
ONE more time and returns THAT result (success, still-conflict, or a
different error) — never more than one retry.

Every caller's `request` callback rebuilds its OWN payload from the `doc`
parameter it receives (not a variable captured before the retry), so a
retry genuinely reflects current state, not a stale snapshot:
  - `saveLayouts`'s `updates` is rebuilt from `this.blocks()` INSIDE the
    retryable closure (ШАГ3's explicit requirement: a drag that landed
    during the network round-trip must not be lost).
  - `toggleOrientation`'s toggle direction is recomputed from `current.orientation`
    each time (not a stale pre-computed target).
  - `addPage`'s `manualPageCount` re-reads the live `this.pageCount()`
    computed (which itself reads `this.document()`, already updated by the
    retry's own `document.set` before the retry's `request` fires).

non-409 failure toasts and is never retried; (c) layout save (drag commit)

FE `studio-editor-catalog-queue.spec.ts` (3 tests, was 3): the existing "a
real 409 from another tab still opens the conflict dialog" test had the
exact same stale-mock problem — its `{message:'conflict'}` no longer

which under the new retry logic would let the SECOND (retry) attempt

`TypeError: this.documents.getById is not a function` against the old,
incomplete mock object).

       (0.1, 0.1) to (0.246, 0.177) server-side, confirming the drag
