Confirms exactly the TZ's own domain-preflight hypothesis: `app-pi-input`'s
CVA writes the native `<input>`'s `.value` (always a string) back into the
FormControl — a cleared "Порядок" is the literal string `''`, sent as-is in
JSON since `tableTemplatePayload()` never wrapped it in `Number()`.
`CreateTableTemplateDto.sortOrder` (`@IsOptional() @IsNumber() @Min(0)`, no
`@Type`) validates the raw string as-is: `@IsOptional()` only skips
null/undefined, not `''`, so both `@IsNumber()` and `@Min(0)` fail against a
string value, producing both RU messages together.

Same exact field/pattern (`app-pi-input type="number" formControlName="sortOrder"`,
`sortOrder: [0]`, no Number() wrap) also exists in
`text-block-form-dialog.component.ts`, sharing the same
`doc-studio-payloads.ts` builder file — `CreateTextBlockDto.sortOrder` has
`@IsOptional() @IsNumber()` (no `@Min`), so it would 400 with just "Должно
быть числом" on an empty Порядок, not the exact PO-reported message, but
the same root defect. Fixed for free by fixing the shared builder (see
known_limitation below for what was NOT touched).

=== Fix ===

ШАГ 1 (FE, primary): `doc-studio-payloads.ts` — new `finiteSortOrderOrUndefined()`
helper; both `textBlockPayload()` and `tableTemplatePayload()` now pass
`sortOrder` through it instead of forwarding the raw FormGroup value.
`''`/`null`/`undefined`/non-finite -> omitted from the payload (not sent,
`JSON.stringify` drops `undefined` properties, same as the existing
`description`/`dataSource` omit-when-empty pattern in the same functions).
A numeric string (e.g. from a differently-behaving CVA) is coerced via
`Number()` rather than blindly omitted, so a real value still gets through.

ШАГ 2 (BE belt): `create-table-template.dto.ts` — `sortOrder` gains
`@Transform(emptyOrNanToUndefined)` before its existing `@IsOptional()
@IsNumber() @Min(0)`, normalizing `''`/`null`/`NaN` to `undefined` so
`@IsOptional()` actually takes effect for any client that still sends the
raw empty value. `UpdateTableTemplateDto extends PartialType(CreateTableTemplateDto)`,
so the same behavior applies to PATCH without touching that file.
`CreateTextBlockDto` was NOT given the same `@Transform` — it has no
`@Min`, so the FE fix alone (which the shared builder file already
provides) closes its instance of the bug without needing a matching BE
belt; adding one anyway would be untested scope beyond what ШАГ 0
reproduced.

=== Specs ===

FE `doc-studio-payloads.spec.ts` (+5 tests): empty string -> omitted (both
payload builders); explicit 0 and 5 preserved; a non-numeric string ('abc')
-> omitted (not sent as NaN); a numeric string ('3') -> coerced to the real
number 3.

BE `create-table-template.dto.spec.ts` (new file, 5 tests): empty string ->
no validation error, `dto.sortOrder` is `undefined`; omitted field -> valid;
explicit 0 -> valid, preserved; `-1` -> still rejected (Min(0) not
weakened); `'abc'` -> still rejected (non-numeric, non-empty is a real
error, not silently accepted).
