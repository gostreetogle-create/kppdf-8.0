# PO ↔ агенты: общее понимание (канон)

> Устойчивые правила совместной работы. Не стенограмма чата.

> Ревью очереди: [`audits/2026-09-05-tz-queue-necessity-review.md`](./audits/2026-09-05-tz-queue-necessity-review.md).  
> Архитектура: [`architecture/MASTER-CORE.md`](./architecture/MASTER-CORE.md).

## 1. Куда идём

- **Продукт для людей** в финале = один фронт: `frontend-nx/`.
- Папка `frontend/` до cutover — **эталон и склад для переноса**, не второй боевой сайт цеха.
- Сейчас типичный режим — **локальная** разработка. Не выдумывать «коллеги путают два URL» без dual-deploy от PO.
- **Cutover:** старый фронт убирают **целиком** (часто вручную PO). Деплой — только NX.
- Карта доменов [`DOMAIN-MAP.md`](./DOMAIN-MAP.md) — **dual-track**: колонка NX ведётся **параллельно** с портами, не «потом после cutover».
- **Частично вырезать** старые разделы агентами «по пути» — по умолчанию **не делаем**.

## 2. Придумывать — да; лишнее — нет

**Нужно:** тупики оператора на NX; security с evidence; тонкие TZ по скрину/тесту/канону; упрощения пути пользователя.

**Не нужно в continuous / втихаря:** чистка ради агента; гипотезы; фичи «на вырост»; partial legacy UI delete; перестраховка перед PO.

**Тест перед TZ:** (1) пользователь = оператор NX или безопасность данных? (2) факт, не гипотеза? (3) нет дешевле? (4) не раздуваем продукт?  
Нет → не изобретать работу. Да → думать полноценно и писать тонкую TZ.

## 3. Как говорить с PO

- Кардинальное — простым русским ([`PO-PLAIN-LANGUAGE-CHANGES.md`](./PO-PLAIN-LANGUAGE-CHANGES.md)).
- Wipe / новый модуль / ломающая schema — один короткий вопрос.

## 4. Роли

- Cursor думает широко, выдаёт через фильтр §2.  
- Freebuff / Claude исполняют TZ.  
- Следующий **модуль** называет только PO.

## 5. Режим «отчёт → сразу промпт» (основной)

1. Волны и `PROMPT-*.md` готовим **заранее в файлах** (можно).  
2. PO кидает отчёт агента сюда.  
3. Cursor кратко сверяет (факт / WAVE / не лишняя работа).  
4. **В чат PO — только то, что можно сразу отдать агенту.** Без «скажи Да».  
5. Цепочка кончилась →: **«Задачи закончили, всё чисто. Промптов нет — ждём следующие ТЗ / замечания с экрана.»**

### 5b. Поток скринов (2026-09-06)

Рабочий конвейер с PO:

| PO делает | Cursor делает |
|-----------|----------------|
| Скрин + «что не так» | Быстро TZ + строка в [`STREAM-QUEUE.md`](./agent-checklists/STREAM-QUEUE.md) (колонка **Freebuff** или **Claude**). В чат — короткое «занёс», **без** промпта, если слот занят. |
| Отчёт Freebuff / Claude (DONE) | Сверка → **сразу** copy-paste следующего промпта этому агенту из очереди потока. |
| Ничего готового в потоке | «Промптов нет — ждём скрин / ТЗ.» |

Два потока ведём **волнами** параллельно, пока conflict keys не пересекаются. Доска: `docs/agent-checklists/STREAM-QUEUE.md` + `_NOW.md`.

### 5a. Один промпт в чат, если нужна очередь

PO **часто не читает мелкий текст** («жди / IDLE») — видит блок и **сразу отдаёт**.

| Ситуация | В чат PO |
|----------|----------|
| Два агента **реально** параллельны (разные conflict keys / папки, оба стартуют сейчас) | Два промпта: **кому + блок** каждому. Карта зон обязательна (кто `app.routes`, кто `production/**`) |
| Второй **только после** первого (общий файл / один `production/**` WIP) | **Только промпт первого.** Второй — после отчёта |
| «Заготовка на потом» | Путь к файлу одной строкой, **без** copy-paste блока |

Пример параллели 2026-09-05: Freebuff = Gantt/реестры; Claude = Сделки — `docs/agent-checklists/PARALLEL-SLOTS-2026-09-05.md`.

Нарушение §5a = вина Cursor, не PO.

## 6. Цепочки ТЗ: мелочь vs крупное

Канон калибра: `docs/TZ-AUTHORING.md` §2a (`SIZE: S` | `SIZE: L`).

- PO «дай задачи / ТЗ» → Cursor даёт **цепочку** (таблица: SIZE · id · путь) + при готовности **один промпт на цепочку**.  
- Несколько **S** одной зоны → один continuous.  
- **L** → отдельно или WAVE из нескольких L с чеклистом.  
- Не мешать в одном промпте несвязанные модули.

## 7. Гант и реестры

Справочники, без которых Гант не настраивается с NX (**Виды работ**, **Люди**, **виды работ в модуле**), живут в `/registries` с полным CRUD — не «только read с Ганта» и не второй полу-экран.  
Аудит: `docs/audits/2026-09-05-gantt-registries-data-audit.md`.

## 8. Сделки (NX порт)

Порт как Гант: аудит → peer Claude → WAVE TZ. Рабочее место = **hub на `/orders`** (не `/desk` в первой волне); `/desk` — отдельное решение PO.  
WAVE: `docs/agent-checklists/WAVE-NX-DEALS.md` · TZ `tasks/_ready/nx-deals/` · промпт `tasks/PROMPT-FREEBUFF-NX-DEALS.md`.
