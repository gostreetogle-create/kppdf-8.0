# Опасные операции — спрашивать PO по-русски

> Для **любого** агента (Cursor / Buffy / Gemini / local).  
> Цель: PO не обязан понимать английский (`wipe`, `drop`, `rm -rf`) и не должен случайно «Approve».

## 1. Правило красной кнопки

Перед действием, которое **нельзя легко отменить**, агент **останавливается** и пишет PO **на русском**, в таком духе:

> **Осторожно, опасность.**  
> Я собираюсь: … (что именно по-русски).  
> Пострадает: … (какие данные / сайт / пароли).  
> Это **не** обычное обновление.  
> Могу ли я это сделать? Напишите точно: **«да, разрешаю …»** или **«нет»**.

Без такой фразы PO — **не выполнять**.  
Молчание / «ок» / Approve в английском диалоге Freebuff на `net stop` / wipe — **не** считать разрешением на удаление данных.

## 2. Что считается опасным (минимум)

| Действие | По-русски для PO |
|----------|------------------|
| `deploy.ps1 -Wipe` / `WIPE=true` / `--wipe` | «Полностью стереть базу и файлы сайта и поставить с нуля» |
| Удаление Mongo / `dropDatabase` / чистка `/var/lib/kppdf80` | «Удалить все заказы, КП, материалы…» |
| `rm -rf` прод-каталогов, docker volume prune | «Удалить файлы на сервере без отката» |
| Смена/сброс паролей всем / ротация JWT с выкидыванием сессий без предупреждения | «Всех выкинет из системы / пароли сбросятся» |
| Правка nginx/SSL так, что сайт ляжет надолго | «Сайт может стать недоступен» |
| Остановка VPN / сетевых служб на ПК PO | Уже ок спрашивать; формулировать по-русски: «Выключить VPN, чтобы зайти в домашний сервер?» |

Обычный **warm deploy** (обновить код, `WIPE=false`) — **не** красная кнопка, если PO сказал «деплой».

## 3. Деплой по умолчанию

**Канон:** обновить сайт, **данные не трогать**.

```powershell
.\deploy\synology\deploy.ps1
# = WIPE=false
```

Слова PO «деплой» / «задеплой» / «кати» = **только** warm update.  
Слова «wipe» / «сотри базу» / «чистая установка» = отдельное явное разрешение.

## 4. Если wipe всё же нужен — безопасный порядок

Такая «переправочная» схема **существует** и у нас уже есть заготовка бэкапа: `deploy/synology/backup.sh`.

**Порядок (агент предлагает PO до любых удалений):**

1. **Сохранить копию** на VM:  
   `cd /opt/kppdf-8.0 && sudo bash backup.sh`  
   → `/var/lib/kppdf80/backups/mongo-…` (+ uploads при наличии).
2. Сообщить PO путь и дату бэкапа по-русски.
3. Только после «да, разрешаю wipe после бэкапа от …» — выполнять wipe/seed.
4. После проверки: либо жить с чистой базой, либо **восстановить из копии** (mongorestore / копирование uploads — по runbook; не импровизировать без записи в отчёт).

Если бэкап не сделался — **wipe запрещён**, даже если PO сказал wipe вскользь.

## 5. Как PO отвечает (короткие формулы)

| Хочет | Пишет |
|-------|--------|
| Обычное обновление | `деплой` |
| Стереть всё после бэкапа | `да, разрешаю wipe после бэкапа` |
| Запрет | `нет` / `не трогай данные` |
| Выключить VPN для агента | `да, выключи VPN` / `VPN off` |
