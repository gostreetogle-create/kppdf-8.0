════════════════════════════════════
КОНТЕКСТ ПРОДУКТА
════════════════════════════════════
- Цеховой ERP ~10 пользователей (свои люди).
- Стек: Angular + Nest + Mongo; Desktop/Tauri + MCP (Bearer JWT на /api).
- Хостинг: Ubuntu VM на Synology (LAN 192.168.1.103:3000) ← SSH reverse tunnel ← VPS nginx

════════════════════════════════════
ЧТО ХОЧЕТ PO (UX)
════════════════════════════════════
1) Как админ в UI: «создать пользователя» → сгенерировать ключ ИЛИ ссылку (срок действия,

3) Человек ОДИН раз вводит ключ или переходит по ссылке.

5) Роль из приглашения; потом роль можно менять внутри ERP.
6) Метафора «как SSH-ключ»: выдал секрет → устройство своё → работаешь. (Настоящий SSH для

сказал: жёсткий IP-allowlist для дома/мобилки — плохая идея (DHCP, 4G, CGNAT, смена Wi‑Fi).

Альтернатива, которую предлагали: mTLS (клиентский .p12 на VPS nginx) — сильная крипта,
но без красивой кнопки в админке и с возней установкой сертификата.

Долгосрок в доках: Tailscale / сайт не торчит в публичный интернет.

- Канон уже в репо: docs/ops/home-host-access.md (Basic сделан; IP как стратегия отвергнут;
  обсуждается invite+device-cookie vs mTLS).

════════════════════════════════════
ВАРИАНТЫ ДЛЯ СРАВНЕНИЯ (обязательно все)
════════════════════════════════════
A) Оставить Basic Auth (status quo)
B) mTLS / клиентские сертификаты на VPS nginx, снять Basic с UI
C) Продукт: one-time invite (код или magic link) → HttpOnly Secure device/session cookie
   (без IP-замочка) → снять Basic; роль = User в ERP
D) То же что C, но плюс мягкая/жёсткая привязка IP после активации
E) Tailscale/VPN only (убрать или сузить публичный веб)
F) Cloudflare Access (потребует смены моста на CF)
G) Гибрид (например invite+cookie сейчас, Tailscale потом) — если предлагаешь, опиши фазы
