# Keyboard-only pass — чеклист (PO + agent)

> Источник: PO ловит 90% a11y-дыр на показе одним правилом «отложи мышь».
> До этого файла результат уходил в чат и терялся. Канон:
> `docs/audits/2026-08-23-ui-war-room-program.md` (war-room, Post-WR ROI).

## Правило

Мышь **запрещена** на весь прогон. Только:

- `Tab` / `Shift+Tab` — перемещение фокуса
- `Enter` / `Space` — активация
- `Esc` — закрытие/отмена

Если в любой момент тянет взять мышь, потому что фокус не виден или не туда
попал — это **FAIL**, даже если действие технически выполнимо.

## Как прогонять

1. Открой страницу, кликни один раз мышью только чтобы попасть в документ
   (или `Tab` с адресной строки), дальше — только клавиатура.
2. Пройди сценарий по шагам, отмечай PASS/FAIL в колонке.
3. При FAIL — коротко опиши, что увидел («стыд»): где потерялся фокус, что
   не открылось Enter/Space, куда убежал Esc.
4. Не чини в этом заходе — FAIL уходит в список ниже, чинит successor TZ.

## Сценарий A — `/desk`

| Шаг | Действие | PASS/FAIL + стыд |
|-----|----------|-------------------|
| A1 | `Tab` до строки заказа в очереди, `Enter`/`Space` — открыть строку | |
| A2 | `Tab` внутрь tray/flyout, дойти до первого интерактивного поля | |
| A3 | `Tab`/`Shift+Tab` по всем полям и кнопкам — фокус не выходит за пределы flyout, не теряется (не улетает в `body`/невидимый элемент) | |
| A4 | `Esc` — flyout закрывается | |
| A5 | После `Esc` фокус возвращается на строку заказа, с которой открывали (не в начало страницы, не потерян) | |

## Сценарий B — КП create (`/commercial/proposals` create)

| Шаг | Действие | PASS/FAIL + стыд |
|-----|----------|-------------------|
| B1 | `Tab` до кнопки открытия диалога/flyout состава или свойств позиции, `Enter`/`Space` | |
