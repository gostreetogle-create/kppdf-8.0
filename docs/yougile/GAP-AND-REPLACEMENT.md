## 1. Что на самом деле лежит в карточке YouGile

На скрине кажется «товар с картинкой». По API это **два слоя**:

| Слой | Где в YouGile | Пример |
|------|---------------|--------|
| **Очередь чертежа / работы** | колонка, дедлайн, приоритет-стикер, код `D-64`, исполнитель | «На распределении» → «В работе» → «Завершены» |
| **Паспорт изделия** | **чат** карточки (не title!) | артикул `3101`, название «Пергола…», габариты, монтаж, RAL/масло, фото |

Title карточки часто только: `Чертежи 3101 ЗНП 3-26 поз 1`.  
Нормальное имя и артикул — в первом сообщении чата, строки примерно:

```
поз
артикул
(пусто)
название изделия
кол-во
ед.
габариты Д×Ш×В
монтаж / примечание
отделка (Мет: RAL … / Дерево: …)
опции
фото → /user-data/{uuid}/image.png
```

Фото скачивается read-only:

`GET https://ru.yougile.com/user-data/{uuid}/image.png`  
заголовок `Authorization: Bearer <YOUGILE_TOKEN>` → PNG.

## 2. Сопоставление с kppdf (что уже умеем)

| Нужда из YouGile | В kppdf уже есть? | Где |
|------------------|-------------------|-----|
| Артикул, имя, описание, габариты, RAL, единица | **Да** | `/products` + форма изделия (`sku`, `name`, `description`, `dimensions`, `ralCode`, `unit`, `installation`/`notes`) |
| Фото изделия | **Да** | та же форма: блок «Изображения» → `PhotosService.upload` → `photoIds` / `productphotos` |
| Состав (модули/материалы) | **Да** (каталог) | `/products/:id` — состав / composition |
| Очередь «на распределении / в работе / готово» | **Частично** | Production Cockpit `/production` — заказы + Гант по видам работ, **не** канбан чертежей |
| Дедлайн + исполнитель на чертеже | **Частично** | люди/workTypes на Ганте; отдельной «карточки чертежа D-*» нет |
| Чат по задаче | **Нет** (и не копируем 1:1) | в ERP обычно хватает полей + вложений, не мессенджера |
| Код задачи `D-64` / ЗНП | **Нет отдельной сущности** | можно хранить в `notes` / будущем `externalRefs.yougileTaskId` |

**Вывод:** каталог товаров + фото — это страница **Продукция**.  
Канбан «Чертежи» YouGile — это **не** дубль `/products`, а **очередь работ/чертежей**, ближе к производству/заказам.

## 3. Чего не хватает, чтобы отказаться от YouGile

Минимальный набор, без которого коллеги останутся в UGL:

1. **Канбан чертежей** (4 колонки как на «Рабочая») с карточкой: изделие → артикул → фото → дедлайн → исполнитель → статус.
2. Связь **чертеж ↔ Product** (один артикул 3101 может иметь несколько позиций ЗНП / `D-*`).
3. Импорт/синхрон read-only из YouGile (разовый JSON → Mongo) — переходный костыль, не вечная фича.
4. (Позже) вкладка «Сопроводительная», Гант только если нужен тот же смысл, что в UGL.

Красиво и грамотно **не** строить второй YouGile внутри ERP, а:

- **Продукция** = правда об изделии (артикул, фото, габариты, состав).
- **Производство / заказы** = правда о работе (статус чертежа, кто делает, срок, ЗНП).

Север PO уже это говорит: КП → заказ → Гант → склад. Доска «Чертежи» садится между **заказом** и **Гантом** (этап «проектирование / чертежи»).

## 4. Где реализовать в UI (рекомендация)

### A. Сейчас (без нового экрана) — заполнение каталога

| Шаг | Страница | Действие |
|-----|----------|----------|
| 1 | `/products` | Создать/обновить изделие: `sku` = артикул из чата (`3101`), имя без слова «Чертежи», описание из отделки/опций, габариты, `hasDrawing: true` |
| 2 | форма изделия | Загрузить фото из снимка `data/yougile-import/photos/` |
| 3 | `/products/:id` | При необходимости состав (позже, не блокер импорта) |

Это закрывает «товары с фото и грамотными артикулами».  
**Не** заменяет канбан статусов.

### B. Следующий вертикальный кусок (отказ от UGL)

Вариант 1 (предпочтительный по северу):  
**в Production Cockpit** — левый/средний блок «Чертежи» (канбан или список со статусами) + справа уже существующий inspector заказа.  
Карточка чертежа ссылается на Product; статусы = колонки YouGile.

Вариант 2: отдельная страница `/drawings` или `/td` — только если cockpit раздуется.  
Сейчас **не** плодить третье меню, пока не проверим на 63 карточках.

### C. Чего не делать

- Не парсить YouGile в UI каждый день.
- Не хранить пароль UGL в git.
- Не тащить чат YouGile как продукт-фичу.
- Не класть «ЗНП 18-26 поз 1» в `sku` — sku = **артикул изделия** (`3101`), ЗНП/поз — в заказ/позицию.

## 6. Порядок работ (локально)

1. Снять снимок YouGile → JSON + photos (**один раз**).
2. Сверить с локальной Mongo → `gap-report.json`.
3. Аккуратно upsert в `products` + upload фото в `/uploads` (только local).
4. PO смотрит `/products` в браузере.
5. После OK — тот же JSON/архив готов к будущему деплою (отдельная команда).

Импорт в production — **только** по явной команде PO.
