## 1. Независимый разбор (без слов PO)

### Зачем Гант в цехе ~10 чел

Два вопроса оператора:

1. **Что стоит на сроках?** Какие изделия/модули когда должны быть готовы (горизонт цеха).
2. **Кто чем занят?** Загрузка людей по дням (горизонт рабочего).

Комбайн уже отвечает на «где модуль по стадии» (колонки = `boardLane` изделий). Гант должен отвечать на **календарь**, не дублировать Комбайн один-в-один.

### Что есть в данных (уже)

```
Order → OrderItem (Product) → Module (composition) → WorkType (+ days, workers via People×WT)
```

`GanttBar` уже несёт `productName`, `moduleName`, `workTypeName`, `workerLabel`.  
**Экран** сегодня режет дерево так: `Order summary → WorkType bars` (плоско). Изделие/модуль — только в `title`/легенде.  
«По рабочим»: `Worker summary → WorkType bars` (всегда раскрыто, без ▸, лейбл = вид работ).

Итог: данные позволяют правильный каскад; **подстановка в дерево — неверная для цеха**.

## 3. Вывод архитектора (решение)

### Канон иерархии на Ганте

```
Заказ (summary, полный span)
  └─ Изделие / позиция заказа (summary позиции)
       └─ Модуль (основная полоса цеха)
            └─ Вид работ (лист: дни, люди, resize) — только после ▸ модуля
```

Если у изделия **нет** модулей: одна строка «изделие целиком» на уровне модуля (pseudo-module = product), лист WT как сейчас из legacy/пустого состава — по правилам estimate (уже skip без модулей — не ломать 337/skip toast).

### Два режима (один canvas)

| Режим (RU) | Было | Станет |
|------------|------|--------|
| **По заказам** | Order → WT | Order → Product → Module → WT |
| **По рабочим** | Worker → WT (всегда open) | Worker → Module(+контекст) → WT; ▸ на worker и module |

Контекст на строке модуля у рабочего: `З-2026-006 · Стеллаж · Рама` (коротко, truncated).

### Почему не «убрать заказы»

PO сам сказал, что полный срок заказа нужен; Комбайн и фильтры — заказные. Убрать заказ = потеря горизонта и связки с цехом. **Тройной каскад** сложнее плоского, но совместим с текущим expand-state (несколько Set / path keys) и уже знакомым UX.

### Почему не два полотна

Два режима переключателем уже закрывают «сроки изделий» vs «загрузка людей». Второе приложение Ганта — лишний chrome и рассинхрон.

### Сборка

Не кодировать спец-сущность. Заметка: WT «Сборка» в справочнике + назначение людей — достаточно для будущего «изделие собрано». Отдельная TZ только когда PO скажет сценарий статусов.
