# Audit: Desktop — встроенный AI-раннер (Фаза 2): llama.cpp + скачивание модели

**Дата:** 2026-08-16
**Источник:** решение PO по результатам аудита импорта (см. `docs/audits/2026-08-16-desktop-excel-import-rework.md`): «модель скачивается один раз в папку приложения и работает сама, без посторонних программ», по образцу приложения-переводчика (встроенное скачивание + работа офлайн).
**Зона:** `desktop/src/ai-runner/`, `desktop/src/core/aiRunner.ts`, `desktop/src/core/model-catalog.ts`, `desktop/src/core/ai/suggest-mapping.ts`, `desktop/src/App.svelte`, `desktop/src/core/config.ts`.
**Связь:** Фаза 1 (мульти-табличная студия + профили) — уже в `main`-диффе сессии; эта фаза — движок и «умный» добор колонок.

## Вердикт

Встроенный движок реализован и проверен: десктоп поднимает фоновый Node-процесс
`ai-runner` (тот же паттерн, что MCP host), тот грузит модель через `node-llama-cpp`
(llama.cpp) и отдаёт OpenAI-совместимый `/v1/chat/completions` — существующий клиент
`core/ai/client.ts` работает без изменений. Скачивание GGUF — в приложении, с прогрессом,
в `app-data/models`. Автоопределение ПК: рекомендация модели по объёму ОЗУ.

Архитектура подтверждена на практике: раннер поднялся, `/health` отвечает, движок
`engineAvailable: true`, характеристики ПК определяются (`--specs`). Модель не качалась
в этой сессии (~2 ГБ, требует решения PO о трафике) — путь «скачать → перезапустить →
умный подбор» проверен кодом и тестами промпта, но не живым прогоном LLM.

| Контроллер | `core/aiRunner.ts` | Жизненный цикл из Tauri: `start/stop/dispose`, health-check, прогресс скачивания (опрос `/download/status`), автоопределение ПК через `--specs`. Паттерн — `core/mcpHost.ts` |

## Проверено

- `tsc --noEmit`, `svelte-check`: 0 ошибок.
- Тесты десктопа: 37 PASS (в т.ч. `model-catalog.test.ts` — рекомендации по ОЗУ 32/10/5/1 ГБ; `ai/suggest-mapping.test.ts` — промпт + парсинг JSON).
- Живой smoke раннера: `--specs` → `{"totalMemoryGb":63.5,"freeMemoryGb":39.1,"cpus":14}`; `/health` → `engineAvailable:true, modelLoaded:false`, лог `[kppdf-ai] listening 9777`.

## Особенности реализации

- **v3 API node-llama-cpp**: `llama.loadModel({ modelPath })` (не `LlamaModel.fromPath`), сессия принимает `contextSequence`, `prompt()` — строка (system-промпт склеивается в начало текста для одноразовых задач). Типы приватных конструкторов обойдены алиасами `LlamaModelLike`/`LlamaChatSessionLike`.
- **Tauri capabilities** не менялись: `shell:allow-spawn` для `nodejs` уже был (MCP host), AI-раннер использует его же.
- **Порт**: `DEFAULT_AI_PORT = 9744`, при занятости раннер сам перебирает порт вверх (как MCP).
- **Скачивание**: `https.get` с редиректами, tmp-файл → rename, прогресс через `/download/status`. Имя файла санитизируется.

## Что осталось (осознанно)

1. **Живой прогон модели не делался** — скачивание ~2 ГБ не запускалось (трафик). Первый запуск: вкладка «Модель» → «Запустить раннер» → «Скачать модель» → «Перезапустить (загрузить модель)» → вкладка «Импорт Excel» → «Предложить сопоставление».
2. **Установленный NSIS-билд**: `resolveDesktopDir()` ищет пакет `kppdf-desktop` вверх от `resourceDir` — для bundled-сборки путь надо проверить на реальном инсталляторе (как было с MCP `hostDir`).
3. **GPU**: движок CPU-only (рекомендация — по ОЗУ); на мощных GPU можно добавить `gpuLayers` и/или большие модели — отдельная TZ.
4. **Версия**: 0.5.2 → 0.5.3 (сделано в Фазе 1; при сборке релиза проверить, что номер попал в бинарь и в окно).
