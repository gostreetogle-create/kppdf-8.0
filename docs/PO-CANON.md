# PO CANON — короткий обязательный контекст

> Source of truth для характера PO, планки качества и рабочего режима агента.
> Читать этот файл вместо полного `PO-DIARY.md`. История — `PO-DIARY.md` §5.

## Кто такой PO

- Владелец небольшого цехового ERP примерно на 10 пользователей.
- Сам показывает продукт коллегам: цель — рабочий продукт без стыда, не демо-заглушка.
- Говорит потоком; агент сам структурирует намерение и не заставляет повторять.
- Ценит дожатую вертикаль больше длинного списка будущих функций.
- После поверхностного фикса — соседний рабочий шаг пользователя.
- Смысл статуса/поля везде — `docs/COUPLING-MAP.md`; локальный «активный» запрещён.

## Планка продукта

- UI на русском, light/dark читаемы, клики и состояния однозначны.
- Важные данные не прятать ради макета; destructive — с подтверждением.
- Сессия переживает F5/сбой; ошибки не исчезают бесследно.
- Доверие на показе (ROI): keyboard-only + dirty-close важнее WebSocket/offline/MF; native `<select>` ок, пока нет поиска по 1000+.
- Один write-path на сущность; preview смотрит, не редактирует; FE+BE согласованно.
- Формы плотные: ширина поля = содержимое. Функции «на будущее» без сценария сотрудника — нет.
- Плотные студии (КП, Гант): icon-rail + flyout **overlay** поверх превью; лист A4 **не reflow** при open/close (portrait **и** landscape); rail слева и в альбоме; toolbar не крадёт высоту. **КП геометрия:** `docs/pages/kp-workspace-geometry.md` — закон, не обсуждается.
- Гант: правка в **списке-каскаде**; ▸ крупно; Заказ→Изделие→Модуль→WT; «По рабочим»=модуль; ФИО=цвет вида работ; без людей — громко+CTA; сборка/упаковка скрыты.
- Page-tools широко — в `app-chrome-rail` под ←→; history ≠ действия страницы.
- Комбайн: **ряд = изделие**; стадии внутри; метод `docs/methods/combine-product-row-kanban.md`; отгрузка целым заказом.
- Стол `/desk`: expand-in-row = **рабочее место заказа**; из tray не navigates; cross-page только chips с `orderId`; КП из заказа = наследование данных; статусы дальше confirmed — от процессов/документов; reuse-first.
- Отгрузка без документа: «Отгружено» в tray → POST ship + метаданные; документ опционален позже.
- **Undo:** движения откатываются там, где есть список и это безопасно (отмена отгрузки до dispatch — `/shipping` + tray); после списания со склада — отдельный процесс.
- Reuse-first: баг в источнике до копии на стол; не второй write-path.
- **Одна страница — один контекст:** на экране, где оператор работает (снабжение, КП, стол), максимум действий inline: добавить / выбрать / скопировать / подправить **без** ухода в другой раздел «только ради +». Справочник — SoT и rename; форма — write-through + autofill из карточки.

## Север продукта

- **Стек/архитектура/бизнес-канон закрыты и не переоткрываются без нового TZ:** `docs/architecture/MASTER-CORE.md` (2026-08-30). Конфликт нового TZ с этим файлом → 1 вопрос Да/Нет PO, не молчаливая правка.
- ERP: продажи/КП → заказ → снабжение/производство → склад/отгрузка.
- Покупатель = `Counterparty`; `Organization` = наша фирма.
- Почта: **фирма** = `Counterparty.email`; **человек** = `Person.email`.
- КП = коммерческий snapshot; не меняет каталог молча. Каталог/состав = SoT будущих документов.
- Desktop/MCP — импорт с HITL, не автономная публикация. UI: **Подключение | Импорт | AI** (чат GGUF/API; не Ollama). Сайт = SoT; ПДн клиентов через API не гонять.
- Массовое заполнение: **Excel из Desktop**, не Google Sheets. Вход: device grant; hidden owner один.
- **Склад — один.** Внутри — разделы (металл листовой, металлопрофиль, метизы, …). Мультисклад/ячейки/зоны из старого проекта не переносим: структура простая и читаемая.

## Как работать с PO

0. **Язык:** коротко, по-русски. **Промпт исполнителю или вопрос** — без отчётов. PO судит по **живому сайту**; «какие классы поменяли» — только в archive `.done.md`, не в чат.
0a. **Качество > скорость.** Не гнать «быстро сделали». Сдача = экран как эталон глазом (тот же «+», та же плотность), не «в коде похоже».
0b. **Раскладку, которую PO уже принял, не менять молча.** Конфликт с каноном / скрином → один вопрос Да/Нет, потом TZ.
0c. **«Можно запускать?»** — только если `tasks/_active/` пуст и `nx build kppdf-web` exit 0 на HEAD; иначе «ещё нет». Канон: `docs/TZ-NX-BUILD-INTEGRITY.md`.
1. Намерение + живой код/экран, потом TZ. Не спрашивать «продолжать?» внутри волны.
1a. **Замечание PO по ходу = TZ в бэклог, не смена курса.** PO часто диктует правку («тут неоднотипно», «эту кнопку убрать») посреди другой волны. Агент фиксирует её отдельной TZ в `tasks/_backlog/<тема>/` + строка в `_backlog/QUEUE.md` и **продолжает текущую работу**, не переспрашивая и не бросая начатое. Потерять замечание — хуже, чем отложить.
2. Сообщение в **этот** чат прерывает, не параллелит. Пока собираю TZ: «не пиши сюда, пока не дам путь».
3. Выбор/wipe/секреты — STOP. Warm deploy: Cursor **«подготовь к деплою»** → любому ИИ **«сделай деплой по документации»** (`deploy/synology/README.md` только). Wipe — отдельная русская фраза + `docs/ops/DANGEROUS-OPS.md`.
4. Git — `docs/GIT-POLICY.md`. Параллель: ≤**2 Freebuff + 1 Claude terminal**, разные keys; `QUEUE-LIVE.md`; один промпт/сессию. **Исключение:** два TZ на `apps/kppdf-web/src/**` — только последовательно (build green между ними).
5. Freebuff = рутина. Сайт → Perplexity; сложное/152-ФЗ → MCP `claude_code` analysis-only, потом TZ.
6. Новый инсайт PO → `PO-DIARY.md` §5 (+ этот файл, если стабильно). Docs hygiene — по evidence без построчного согласования.
7. **Nx-миграция модулей:** очередь страниц/таблиц задаёт только PO — что переносим, что режем, что меняем. Агент не предлагает «следующий модуль» и не спрашивает «что добавить»; после фундамента (F3 auth) ждёт явного указания на вертикальный срез.
7a. **Модуль диктует таблицы, не наоборот.** PO называет модуль → из модуля выводим минимально необходимые таблицы/поля. Таблицы «на будущее», наброски и заготовки без модуля-потребителя — запрещены. Новая таблица входит в продукт **через реестр** (`/registries`), и только потом подключается к модулям.
8. **Документация:** код + docs = один PR/TZ (`docs/DOCS-INTEGRITY.md`); auth в nx — `docs/architecture/nx-auth-platform.md`; Integrity slot обязателен перед archive.

## Compliance (152-ФЗ)

- Уже оператор ПДn — «учебный» на `/login` не заменяет политику/РКН.
- Без TZ+юрист: foreign analytics, marketing SMS/email, публичный register, трансгран SaaS с ПДн.
- Без рекламы; вход device-invite; закрытость = VPN/периметр. Канон: `docs/compliance/COMPLIANCE-RULES.md`.

## Антипаттерны

- Длинный полутехнический отчёт; half-baked экран; второй write-path; EN-лейблы; случайный disabled.
- Автодеплой/wipe/каталог из КП без решения; стенограммы между агентами вместо git+checklist.
- WebSocket / micro-frontends / offline-mutation sync «на вырост» при ~10 пользователях.
