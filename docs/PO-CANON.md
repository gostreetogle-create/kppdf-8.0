# PO CANON — короткий обязательный контекст

> Source of truth для характера PO, планки качества и рабочего режима агента.
> Читать этот файл вместо полного `PO-DIARY.md`. История — `PO-DIARY.md` §5.
> Общий язык с агентами: [`PO-SHARED-UNDERSTANDING.md`](./PO-SHARED-UNDERSTANDING.md).

## Кто такой PO

- Владелец небольшого цехового ERP примерно на 10 пользователей.
- Сам показывает продукт коллегам: цель — рабочий продукт без стыда, не демо-заглушка.
- Говорит потоком; агент сам структурирует намерение и не заставляет повторять.
- Ценит дожатую вертикаль больше длинного списка будущих функций.
- После поверхностного фикса — соседний рабочий шаг пользователя.
- Смысл статуса/поля везде — `docs/COUPLING-MAP.md`; локальный «активный» запрещён.

## Планка продукта

- UI на русском, light/dark читаемы, клики и состояния однозначны.
- Студийная витрина каталога — как магазин: явные **Добавить/Убрать**, без «аккуратно кликай»; spam-клики не дают 409/диалог conflict; карточки компактные.
- Важные данные не прятать ради макета; destructive — с подтверждением.
- Сессия переживает F5/сбой; ошибки не исчезают бесследно.
- Доверие на показе (ROI): keyboard-only + dirty-close важнее WebSocket/offline/MF; native `<select>` ок, пока нет поиска по 1000+.
- Один write-path на сущность; preview смотрит, не редактирует; FE+BE согласованно.
- Формы плотные: ширина поля = содержимое. Функции «на будущее» без сценария сотрудника — нет.
- Плотные студии (КП, Гант): icon-rail + flyout **overlay** поверх превью; лист A4 **не reflow** при open/close (portrait **и** landscape); rail слева и в альбоме; toolbar не крадёт высоту. **КП геометрия:** `docs/pages/kp-workspace-geometry.md` — закон, не обсуждается.
- Документ-студия: UI-связь с Quotation = коротко **«КП»** (не «Коммерческое предложение»); буфер **«Выбрано»** — отдельная иконка левого rail под «Данные», не TOC внутри Данные. Модуль «Докум.»: **Документы** (список) / **Шаблоны** / **Студия** (редактор); чип → список, не auto-resume; в редакторе сверху только крошки; Save/PDF/режим/архив — правый chrome-rail (WAVE-DOCSTUDIO-CHROME-IA). **Таблица на холсте:** один клик = выделение + drag/resize; правки строк/«+ Строка» только в правых **Свойствах**, не inline-админ на A4.
- Гант: правка в **списке-каскаде**; ▸ крупно; Заказ→Изделие→Модуль→WT; «По рабочим»=модуль; ФИО=цвет вида работ; без людей — громко+CTA; сборка/упаковка скрыты; **календарная сетка** визуально отделена от колонки заказов; переключатели группировки/масштаба — как TOC-chips (`bg-ink` active), не ghost-кнопки в рамке. **Дни бара:** `Module.workTypes.days` → fallback `WorkType.days` (seed) → override заказа; у человека только навыки, без «Nд».
- Page-tools широко — в `app-chrome-rail` под ←→; history ≠ действия страницы.
- Комбайн: **ряд = изделие**; стадии внутри; метод `docs/methods/combine-product-row-kanban.md`; отгрузка целым заказом.
- Стол `/desk`: expand-in-row = **рабочее место заказа**; из tray не navigates; cross-page только chips с `orderId`; КП из заказа = наследование данных; статусы дальше confirmed — от процессов/документов; reuse-first.
- Отгрузка без документа: «Отгружено» в tray → POST ship + метаданные; документ опционален позже.
- **Undo:** движения откатываются там, где есть список и это безопасно (отмена отгрузки до dispatch — `/shipping` + tray); после списания со склада — отдельный процесс.
- Reuse-first: баг в источнике до копии на стол; не второй write-path.
- **Одна страница — один контекст:** на экране, где оператор работает (снабжение, КП, стол), максимум действий inline: добавить / выбрать / скопировать / подправить **без** ухода в другой раздел «только ради +». Справочник — SoT и rename; форма — write-through + autofill из карточки.
- **Склад:** один движок (остаток = движения); разделы = именованные склады без типов/ячеек; «в работу» → confirm резерв; нехватка → SupplyRequest (мягко). NX WAVE: `WAVE-NX-WAREHOUSE` + `WAVE-NX-SUPPLY`. **Снабжение OPS (Google→NX):** заявка SupplyRequest; «Получено» = confirm + склад (default flag); «Оплачено» = флаг; заказ = Order\|текст; Material через typeahead+copy; createdBy; Excel сначала match по справочникам, затем multi-sheet шаблон — `WAVE-NX-SUPPLY-OPS`.
- **Фото каталога (изделие/модуль/материал):** несколько + одно главное ★; загрузка file/drag/Ctrl+V; позиция в рамке. На NX сейчас gap — WAVE-NX-CATALOG-PHOTOS.
- **Данные на этапе NX:** локальная БД = виртуальное демо для глаз, не наследство старого боя. Битые хвосты (orphan FK, 404 media) — чистить аккуратно по команде PO; полный wipe/prod — только через `DANGEROUS-OPS`.

## Север продукта

- **Стек/бизнес-канон:** `docs/architecture/MASTER-CORE.md`. Конфликт → 1 вопрос Да/Нет PO.
- **Модули** — только по команде PO (п.7). Freebuff без темы — IDLE. Данные не ломать миграциями без команды.
- **Гант / фронт:** рабочий = NX. Финал = только NX; `frontend/` = эталон до cutover целиком. См. `PO-SHARED-UNDERSTANDING.md`.
- ERP: продажи/КП → заказ → снабжение/производство → склад/отгрузка.
- Покупатель = `Counterparty`; `Organization` = наша фирма.
- Почта: **фирма** = `Counterparty.email`; **человек** = `Person.email`.
- КП = коммерческий snapshot; каталог/состав = SoT будущих документов.
- Desktop/MCP — HITL. Массовое заполнение: Excel из Desktop. Склад — один.
- **Desktop ИИ:** вкладки **Импорт** (Inbox + запись в БД после подтверждения) и **ИИ-чат** — разные контуры. Чат по умолчанию не видит файлы, пока Desktop не передаст снимок Inbox; писать в базу из чата нельзя (LIMITED_HELPER). MCP — для Cursor, не замена чата.
- Скачать/подключить Desktop на NX: только **admin** или роль с `desktop:admin` (админ выдаёт в Roles).
- **Списки ERP:** визуальный SoT = `/registries` (▸ expand, плотная таблица, `pi-icon-btn` / `app-pi-row-actions`). «Починили кнопки» ≠ готово — нужен тот же ритм. Hub-строка = связанные сущности блоками + ссылки на живые маршруты (`WAVE-NX-HUB-TABLE-PARITY`).

## Как работать с PO

0. **Язык:** по-русски. В чат — **кому + промпт** или «промптов нет»; не эссе.
0d. **Отчёт → сразу промпт:** сверить → копипаст только кто свободен сейчас (`PO-SHARED` §5 / §5a). Пусто → «промптов нет».
0h. **Поток скринов:** скрин+слова → TZ в Freebuff/Claude очередь (`STREAM-QUEUE.md`); промпт в чат — только когда слот свободен / пришёл отчёт (`PO-SHARED` §5b).
0e. **Кардинальное — по-человечески:** `PO-PLAIN-LANGUAGE-CHANGES.md`.
0f. **Необходимость:** умное — да; лишнее — нет (`PO-SHARED` §2).
0g. **TZ калибр S/L:** `TZ-AUTHORING.md` §2a / `PO-SHARED` §6.
0a. **Качество > скорость.** Сдача = экран глазом.
0b. **Принятую раскладку не менять молча.**
0c. **«Можно запускать?»** — `_active` пуст + `nx build kppdf-web` green.
1. Намерение + экран → TZ. Не «продолжать?» внутри волны.
1a. Замечание mid-wave → backlog TZ + продолжить текущее.
2. Сообщение в этот чат прерывает. 3. Wipe/секреты — STOP. Deploy — явная команда.
4. Git + параллель ≤2 Freebuff + 1 Claude; два TZ на `kppdf-web/src` — только подряд.
5. Freebuff = рутина; сложное → MCP claude analysis-only → TZ.
6. Новый инсайт → этот файл / shared understanding.
7. **Nx-модули** называет только PO. 7a. Модуль диктует таблицы, не наоборот.
8. Docs + код = один контур (`DOCS-INTEGRITY`).
