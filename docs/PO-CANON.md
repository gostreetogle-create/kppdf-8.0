# PO CANON — короткий обязательный контекст

> Source of truth для характера PO, планки качества и рабочего режима агента.
> Читать этот файл вместо полного `PO-DIARY.md`. История решений остаётся в
> `PO-DIARY.md` §5 и читается только адресно.

## Кто такой PO

- Владелец небольшого цехового ERP примерно на 10 пользователей.
- Сам показывает продукт коллегам: цель — рабочий продукт без стыда, не демо-заглушка.
- Говорит потоком; агент обязан сам структурировать намерение и не заставлять повторять.
- Ценит дожатую вертикаль больше длинного списка будущих функций.
- После поверхностного исправления агент проверяет соседний рабочий шаг пользователя.
- Смысл статуса/поля на всех экранах — `docs/COUPLING-MAP.md`; локальный «активный» запрещён.

## Планка продукта

- UI на русском, light/dark читаемы, клики и состояния однозначны.
- Важные данные нельзя прятать ради чистого макета; destructive действия подтверждаются.
- Сессия переживает F5 и короткий сбой; ошибки не исчезают бесследно.
- Один write-path на сущность; preview показывает результат, но не становится вторым редактором.
- FE и BE поставляются согласованно; новый UI со старым API недопустим.
- Рабочие формы плотные и логичные: ширина поля соответствует содержимому.
- Плотные студии (КП, Гант): icon-rail + flyout, центр не сжимать панелями; toolbar не красть высоту у рабочей плоскости.
- Гант: правка в **списке-каскаде**, не оверлей; ▸ крупно; уровни Заказ→Изделие→Модуль→WT; «По рабочим» = модуль; ФИО = цвет вида работ; без людей — громко + CTA Люди; сборка/упаковка на Ганте скрыты.
- Page-tools на широком экране — в `app-chrome-rail` под ←→ (не локальная колонка 48px); history ≠ действия страницы (зазор + лёгкий visual split).
- Не создавать функции «на будущее» без сценария реального сотрудника.
- Комбайн: **ряд = изделие** (OrderItem); стадии внутри ряда; метод: `docs/methods/combine-product-row-kanban.md`; отгрузка целым заказом.
- Стол `/desk`: expand-in-row, workflow chips (КП·Комбайн·Гант·Снабж·Отгрузка), reuse-first host; chrome = **одна** group-workspace row (`page-chrome.md`), не второй nav.
- Reuse-first: баги чинить в источнике до копии на стол; не второй write-path.

## Север продукта

- ERP для цеха: продажи/КП → заказ → снабжение/производство → склад/отгрузка.
- Покупатель = `Counterparty`; `Organization` = наша фирма.
- Почта: **фирма** = `Counterparty.email`; **человек** = `Person.email` (разные поля).
- КП хранит коммерческий snapshot; цена/скидка конкретного КП не меняют каталог молча.
- Каталог и состав — источники правды для будущих документов.
- Desktop/MCP — управляемый импорт с проверкой человеком, не автономная публикация.
- Desktop UI: три двери **Подключение | Импорт | AI** (тяжёлое на ПК; сайт — SoT).
- Массовое заполнение справочников/каталога: **Excel-форма из Desktop** (категория→таблица→скачал→загрузил→HITL), не Google Sheets как SoT.
- Вход для приглашённого компьютера passwordless через device grant; hidden owner один.

## Как работать с PO

0. **Язык ответа:** коротко, по-русски, без жаргона. Сначала — **что делать тебе** (1–3 пункта). Не простыня про агентов/TZ/SHA. Одно сообщение — одно действие, если можно.
1. Сначала понять намерение и проверить живой код/экран, потом писать TZ.
2. Не спрашивать «продолжать?» между задачами одной подтверждённой волны.
3. Реальный выбор, wipe и секреты — обязательный STOP. Production **warm** deploy
   можно выполнять без повторного «ок» в чате, если PO явно сказал «деплой» /
   «задеплой» / «кати» **или** «деплой по умолчанию» / «меня не будет — задеплой».
4. Деплой = warm (`WIPE=false`); wipe — только отдельная русская фраза по DANGEROUS-OPS.
5. Коммиты и push — строго по `docs/GIT-POLICY.md`.
6. Параллельно держать максимум 1–2 продуктовых потока без пересечения conflict keys.
7. **Freebuff** = дешёвая модель: короткие шаги, явные пути, жёсткий НЕ, один TZ
   за чат; без «разберись сам по всему приложению».
8. **Токены кончатся = нельзя работать с Cursor.** Рутина (форма 400, `Number()`,
   CRUD) — только Freebuff. Gemini Pro / Opus — архитектура, 152-ФЗ, неизвестный
   сложный баг. Не жечь дорогую модель на coerce строки в число.
9. Новое устойчивое понимание PO: короткая запись сверху `PO-DIARY.md` §5;
   стабильный принцип также обновляет этот файл.
10. Docs/rules hygiene архитектор может существенно упрощать по evidence без
    построчного согласования; product/deploy permissions от этого не расширяются.

## Compliance (152-ФЗ)

- ERP уже оператор ПДn (сотрудники, клиенты, cookies) — «учебный» текст на `/login` **не** заменяет политику и уведомление РКН.
- Запрещено без TZ+юрист: foreign analytics, marketing SMS/email, публичный register, трансгран SaaS с ПДn.
- Рекламы не будет. Вход — как device-invite, без Google/OAuth. Закрытость = техника (VPN или узкий периметр), не табличка «учебный».
- Канон: `docs/compliance/COMPLIANCE-RULES.md`. Путь A/B: `docs/compliance/2026-08-18-DECISION-MEMO.md`.

## Антипаттерны

- Длинный отчёт, полутехнический язык, списки «сделай A потом B потом C» в одном сообщении.
- Half-baked экран, второй CRUD/write-path, дубли меню и сущностей.
- Английские UI-лейблы, микротекст, случайные disabled/empty states.
- Автодеплой, wipe или изменение каталога из КП без явного решения.
- Перетаскивание стенограмм между агентами вместо git + checklist + task.
