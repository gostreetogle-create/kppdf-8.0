> Для PO. Не юридическая консультация. Код не менять, пока PO не выберет путь A или B.  
> Дата: 2026-08-18.  
> Рецензенты: GPT 5.6 Terra (право), Gemini 3.1 Pro (архитектура). Исходник: `2026-08-18-PDN-REVIEW-FOR-COUNSEL.md`.

## Согласие двух сторон

- Приложение — внутренняя ИС сотрудников, не витрина и не реклама. Это правильно и это надо **писать честно**, не «учебный проект».
- 401 на `/` **не** делает сайт невидимым: с улицы видны `/enroll`, API login, health, домен.
- Реклама, GA, OAuth Google/VK, Cloudflare Access, Sentry — **не брать**. Это чужие кабинеты и лишние проверки.
- VPN не отменяет 152-ФЗ по сотрудникам и клиентам в базе. Он убирает **публичную форму** и сканеры.

## Два пути (выбрать один)

| | **A. Остаёмся на kppdf-crm.ru** (текущий UX) | **B. VPN-only** (максимально «внутри компании») |
|--|--|--|
| Смысл | Device-invite как сейчас; домен в интернете | Сайт не отвечает из интернета; только своя сеть |
| Сотрудник | Ссылка → имя компьютера, как сейчас | Сначала VPN, потом тот же kppdf |
| Кафе / телефон «с улицы» | Работает | Не работает без VPN-приложения |
| Политика ПДн с улицы | **Нужна** `/legal/privacy` = 200 без cookie | Достаточно внутри ИС / на бумаге с юристом |
| Чужие кабинеты | Нет | WireGuard = свои ключи; Tailscale = аккаунт у них |

**Стиль PO (без регистраций в Google/Cloudflare):** если B — лучше **свой WireGuard**, не Cloudflare Access и не Google. Tailscale проще, но это ещё один кабинет.

**Выбор PO 2026-08-18: путь A.** VPN не делаем. Вход — device-invite на разрешённые компьютеры. Живая TZ: `tasks/TZ-COMP-401.md`.

## Что теряем / получаем

### Если путь A (домен остаётся)

| Делаем | Теряем | Получаем |
|--------|--------|----------|
| Страница политики + текст на enroll | Ничего из ERP | Честное информирование; не прячем политику за 401 |
| `robots.txt` Disallow | Ничего | Меньше индексации (сканерам всё равно) |
| Пароль owner только из LAN/VPN | Break-glass с чужого 4G | Нет перебора пароля с улицы |
| Не трогать device-invite | — | Тот же вход для цеха |

ERP, КП, Гант, Desktop — **как сейчас**.

### Если путь B (VPN-only)

| Делаем | Теряем | Получаем |
|--------|--------|----------|
| Снять сайт с публичного HTTP | Вход без VPN; показ КП с чужого ПК клиента; внешний Uptime | Нет формы с улицы, нет Shodan, нет брутфорса login |
| Device-invite **внутри** VPN | — | Тот же удобный вход, уже в закрытой сети |
| Политика внутри / на бумаге | Публичную страницу | Меньше «сайта для всех» |

Desktop, роли, каталог — **сохраняются**. Меняется только **дорога до сайта**.

## Чего не делаем ни на A, ни на B

Публичная регистрация, рассылки, пиксели, «принимаю всё», Google/VK OAuth, Cloudflare Access как замок, включение Sentry.

## Шаги человека (пока без кода)

1. PO выбирает **A или B** одной фразой.
2. С юристом: кто оператор (ИП/ООО), нужно ли уведомление РКН, текст политики. Формула: «внутренняя ИС, доступ уполномоченным по приглашению».
3. Назначить ответственного за ПДн и за звонок при утечке (24/72 ч).
4. Если **A** — потом TZ: политика 200, ссылка на enroll, robots, login API не с улицы.
5. Если **B** — сначала VPN на сервер и телефоны/ПК (~10), проверка что ERP открывается только из VPN, потом выключить публичный проброс. Политику на улицу не выставлять.
6. Сроки хранения логов — после выбора пути, не раньше.

Внедрение — только после шага 1.
