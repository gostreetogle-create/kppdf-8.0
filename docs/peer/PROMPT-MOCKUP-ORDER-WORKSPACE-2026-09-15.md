> Скопировать целиком в дизайн-ИИ (Claude Artifacts / Stitch / Figma AI / Gemini).  
> Задача: **только макет UI** (экраны + состояния). Код / Angular / API — не писать.  
> Источник продукта: цеховой ERP KPPDF 8.0 (RU, light UI, Paper & Ink).

---

## Роль

Ты — senior product designer ERP. Сделай **полный рабочий экран одного заказа** (`/orders/:id`), чтобы менеджер цеха мог **видеть всё связанное и работать с заказом** без блуждания по разделам «только ради +».

Сейчас:
- `/home` — очередь + expand-hub (сводка связей) — **не** место глубокого редактирования.
- `/orders/:id` — тонкая карточка (номер, статус-баннер, заказчик/объект, список позиций ×qty, КП-чип, чекбокс «Оплачен»). **Состав не редактируется**, нет статусов/удаления линий/связей.

Нужен макет **целевой** страницы заказа: один заказ = одно рабочее место.

## Контекст продукта (обязательно учесть)

- ERP цеха ~10 пользователей. UI на русском. Light theme. Без purple/glow/карточного дашборда.
- Визуальный ритм списков: плотная таблица, hairline, `bg-paper` / `bg-paper-2`, золотой акцент слева у активного/раскрытого (как на Главной).
- Оболочка сайта уже есть: верхние категории (Клиенты / Сделки / …), **L/R chrome-rails** всегда на месте (← история слева, → справа; page-tools только живые).
- Хлебные крошки **вверху контента**, как везде: `eyebrow` → `h1`. Пример: `Сделки` / `Заказ №ORD-2026-022`. Не выдумывать «рабочий день» как крошку на карточке заказа.
- Related-entities канон: на **списке** — expand-in-row hub; на **карточке одного заказа** — полный workspace (не дублировать весь сайт графом/Finder/kanban).
- Один write-path на сущность. Destructive — с подтверждением.
- Отгрузка — **целым заказом**, не построчно.
- Покупатель = Counterparty; наша фирма = Organization; объект = Site.
- КП = snapshot; каталог/состав изделия = SoT будущих документов. Карандаш в дереве состава каталога ≠ правка snapshot линий заказа (разделить в UI явно).

## Обязательный инвентарь блоков (ВСЁ должно попасть в макет)

Расположи грамотно (секции / tabs / sticky summary — на твоё решение, но **ничего не выкидывай** без пометки «omit v1»).

### A. Шапка заказа (identity + actions)

| Элемент | Зачем |
|--------|--------|
| Номер заказа | SoT identity (`Order.number`) |
| Lifecycle-статус | RU: Черновик / Подтверждён / В производстве / Готов / Отгружен / Доставлен / Отменён |
| Дата создания / план.дата | ориентация |
| Оплата | факт `Оплачен` / `Не оплачен` (+ когда, если есть) |
| Наша фирма (Organization) | optional на заказе |
| Заказчик (Counterparty) + ссылка в карточку клиента | обязателен |
| Объект (Site) | обязателен при create |
| КП / Quotation | номер + «КП в студии» **или** «Без КП» (без фейкового «создать stub») |
| Primary actions | Сохранить / Подтвердить заказ (draft→confirmed) / Отменить заказ (destructive) |
| Secondary | Назад к списку `/orders`, На Главную |

### B. Состав заказа (ядро — сейчас главная боль)

| Элемент | Зачем |
|--------|--------|
| Список линий (изделия) | name × qty × unit; readyForWork (готово / не готово) |
| Добавить позицию | выбор изделия из каталога + qty |
| Изменить qty / удалить линию | с confirm на delete |
| Раскрыть состав линии | дерево Изделие → Модули → материалы / workTypes (как composition-tree) |
| Явная кнопка «Редактировать состав» | куда ведёт: правка **линий заказа** vs «открыть изделие в каталоге» — два разных CTA, подписать |
| Freeze состава | после входа в цех/комбайн состав может быть заморожен — показать lock + пояснение |
| Готовность | «X из Y» + per-line ready |

### C. Исполнение

| Элемент | Зачем |
|--------|--------|
| Снабжение | счётчики: заказано / получено / всего; список заявок по orderId; CTA «Подтвердить материалы» (kit-reserve); deep-link `/supply?orderId=` |
| Дефицит / stop-factor | честный short/дефицит — если нет сигнала, не рисовать зелёный «всё ОК» |
| Производство / Гант | оценка в цехе, plannedDate / estimate; deep-link `/production?orderId=` |
| Комбайн (если есть живой route) | статус линий boardLane; иначе omit с пометкой |
| Ответственный / дата отгрузки по линии | если есть в домене — показать |

### D. Логистика

| Элемент | Зачем |
|--------|--------|
| Склад / резервы | active/total броней; deep-link склад |
| Отгрузка | статус shipment; «Отгружено» (confirm meta); «Отменить отгрузку» (до dispatch); «Документ не оформлен»; deep-link `/shipping?orderId=` |

### E. Документы и связи

| Элемент | Зачем |
|--------|--------|
| Шаблоны / печать от заказа | deep-link конструктор `source=order&sourceId=` |
| Связанные документы студии | список если есть; иначе empty honest |
| История / audit | только если можно честно; иначе omit (не fake toast log) |

### F. Навигация workflow (chips, как на Главной)

Чипы с `orderId` в контексте: Главная · КП · Гант · Снабжение · Отгрузка · (Заказы список).  
Активный = текущая страница заказа. Не тащить Админ/Реестры в эту полосу.

## Состояния, которые обязательны в макете

1. Заказ loaded (happy path, 2–3 линии, есть КП, есть дефицит снабжения).  
2. Черновик — CTA «Подтвердить», состав редактируемый.  
3. Состав пуст — empty + «Добавить изделие».  
4. Состав заморожен — lock UI.  
5. Отгружен — ship block read-only + отмена недоступна после dispatch.  
6. Loading / Error+Повторить.  
7. Mobile/узкая ширина: одна колонка, actions не теряются.
