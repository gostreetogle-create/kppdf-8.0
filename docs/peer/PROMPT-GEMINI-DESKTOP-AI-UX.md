## ПРОМПТ 1 — дизайн (это отдай Gemini)

```text
Ты UI/UX дизайнер продукта. Сделай концепт экрана «ИИ» для десктоп-приложения KPPDF Desktop (Windows, цеховой ERP ~10 человек, стиль Paper & Ink: светлая бумага, тёмные hairline, без фиолетового AI-клише, без неона).

Контекст продукта (не меняй смысл):
1) Паринг с сайтом уже на другой вкладке «Подключение» — сюда не тащи.
2) Импорт Excel на вкладке «Импорт» — сюда не тащи.
3) На вкладке «ИИ» два разных контура:
   A. MCP для Cursor/агентов — ЭТО ГЛАВНОЕ, что реально работает (статус, URL, копировать mcp.json, стоп/перезапуск).
   B. Локальный чат с моделью на ПК (~2 ГБ GGUF) — ВТОРИЧНО, сейчас часто ломается; пока может быть «скоро» или один понятный мастер.
4) Не использовать слово «раннер». Человечески: «Локальный помощник» / «Чат на этом компьютере».

Проблема сейчас: экран как админ-панель 2008 — стены текста, 3 одинаковые ошибки, кнопки как попало, чат не похож на современный AI-чат.

Задача:
- Опиши layout одним экраном (desktop ~1100×700): зоны, иерархия, что сверху.
- Чат (когда готов): как у современных AI-приложений — лента сообщений, поле ввода снизу, статус модели одной строкой, без простыней.
- MCP: компактная карточка «для Cursor», не конкурирует с чатом визуально, но всегда доступна.
- Состояния: (1) помощник не установлен, (2) качается модель, (3) готов, (4) ошибка — ОДНО спокойное сообщение + одна кнопка.
- RU-копирайт кнопок/заголовков (коротко).
- Что УБРАТЬ с первого экрана (спеки ПК, каталог моделей, API TokenRouter — куда спрятать).

Формат ответа:
1) Wireframe текстом (ASCII или блоки).
2) Список компонентов.
3) 10 строк microcopy на русском.
4) Что НЕ делать (антипаттерны).
Без кода. Без Nest/Angular. Без «добавьте дашборд».
```

## ПРОМПТ 2 — как реализовать локальный помощник (это отдай Gemini)

```text
Ты senior desktop engineer (Tauri + Node sidecar). Продукт KPPDF Desktop уже умеет:
- MCP host на порту (работает);
- отдельный ai-runner (node-llama-cpp / GGUF), UI пишет «раннер перестал отвечать на порту», «не удалось связаться», папка моделей не открывается, файлов .gguf = 0, «Скачать модель» тоже ошибка.

Нужен ЧЕСТНЫЙ план, не фантазия.

Ограничения:
- Windows, офлайн GGUF ок;
- не ломать MCP;
- PO не технарь — шаги должны быть проверяемы глазом;
- если локальный чат пока ненадёжен — скажи «спрятать до готовности», не «ещё одна кнопка Перезапустить».

Ответь по-русски структурой:
1) Диагноз: 3 самые вероятные причины (процесс не стартанул / нет .gguf / health на неверном порту / bundling ai-runner.mjs в NSIS / Node PATH).
2) Минимальный happy-path для пользователя (5 шагов максимум) от нуля до первого ответа в чате.
3) Что проверить разработчику (логи, health URL, путь к .gguf, spawn command) — чеклист.
4) Нужен ли отдельный UX «Скоро» пока нестабильно — да/нет и почему.
5) Критерии DONE локального чата (acceptance), без которых нельзя показывать кнопки скачивания.

Без микросервисов. Без «перепишите на Electron». Код — только если 5–15 строк псевдокода spawn/health, не больше.
```
