# Тест Gemma (LM Studio :1234) ↔ KPPDF MCP

PO 2026-09-07. Цель: проверить, помогает ли локальная модель в **нашем** ERP через MCP, не HuggingFace.

## Важно

Твой пример curl с `integrations → huggingface → model_search` — это поиск моделей на HF.  
К **kppdf** (заказы, склад, снабжение, каталог) он **не** относится.

Нужная связка:

```
LM Studio (Gemma на :1234) ──MCP client──► KPPDF Desktop MCP (:порт/mcp) ──► Nest API
```

Сейчас (проверка Cursor): Gemma на `:1234` **жива**; MCP kppdf на `9743`/`5140` — **не запущен** (Desktop не поднят / не paired).

## Шаги подключения (ты глазом)

1. Запусти **KPPDF Desktop** (лучше 0.5.10).
2. Вкладка **Подключение** — паринг с сайтом (если ещё нет).
3. Вкладка **ИИ** → блок MCP → статус **Запущен** (порт смотри в карточке, часто `9743` или тот что у тебя был `5140`).
4. Кнопка **«Скопировать mcp.json»**.
5. В **LM Studio** → MCP / Servers → вставь как сервер `kppdf` (url + Bearer). Reload.
6. В чате LM Studio включи tools / MCP для сервера `kppdf`.
7. Проверка: `GET http://127.0.0.1:<порт>/healthz` → ok + toolCount.

Не клади HuggingFace MCP в этот тест, пока не закроем kppdf-сценарии.
