## 1. Кто такой PO (канон)

- Владелец небольшого цехового ERP (**~10 пользователей**): сварка / покраска / дерево / отгрузка / КП / офис-документы.
- Сам будет **показывать продукт коллегам** — планка «не позориться завтра на работе», а не «демо для инвесторов».
- Хочет **почти нормальный рабочий продукт** на текущих страницах, а не бесконечный backlog фич.
- Говорит потоком; ценит, когда агент **сам дожимает нюансы**, которые PO назвал бы «мелочью», но которые ломают доверие (контраст, gap, сессия, lock, пустые подсказки).
- После фикса списка/фильтра — **сам зайти глубже** (карточка, detail) и починить очевидный UX, не ждать подсказки.
- Повторять одно и то же ненавидит: после сессии инсайт должен **остаться в репо**, не в голове модели.

## 3. Север продукта (канон)

- ERP для **цеха**, не бухгалтерия и не тяжёлый зоопарк ACL «кнопка×кнопка».
- **Склады цехов** (трубы / лист / дерево…): живой реестр + ответственный; смотрят многие, ведут назначенные — см. warehouse-workshop-vision.
- Документы / конструктор шаблонов — витрина аккуратности: каталог → builder → превью.
- **Жизненный цикл продаж→цех (север):** менеджер в **КП** (витрина из каталога + шаблон дока; скидки только в КП) → «в работу» → **Заказ** (без цен сделки; состав для изготовления). Заказ можно создать и **без КП** (тогда stub-КП для целостности). Дальше: готовность изделия/модуля → **снабжение** (закуп + «материал есть») → **Гант**/задачи людям → склад ГП/модулей → **частичная отгрузка** с привязкой к заказу. Не готов к работе → очередь **проектировщику** (доукомплектовать; модуль можно пустить раньше изделия). Канон: `docs/audits/2026-08-08-sales-to-shop-flow-canon.md`. Гант — гибкий plug-in, не монолит.
- **Desktop/MCP (север наполнения):** оптовый мост из старых Excel/файлов → структурированные сущности SoT (сначала материалы/каталог, потом шире); ImportTask + HITL; не вторая БД. Канон-аудит: `docs/audits/2026-08-08-desktop-bulk-import-vision-audit.md`.
- Вертикали доводить до «можно жить», параллель — максимум 1–2 потока (см. peer/roadmap дискуссии).
- Осознанный отказ лучше недоделки: пример 2026-08-03 — **свободный текст «на лету» в палитре не делаем** (хватает каталога + «Редактировать»).
- Автологин без пароля / «всегда админ» — **нет**.

## 4. Как PO хочет работать с ИИ (канон)

1. **Понять намерение раньше кода.** Технически агент и так может собрать UI; ценность — угадать *зачем* и *насколько чисто*.
2. После обсуждения — **дожать и закрыть день** (полировка + gates), не оставлять «почти».
3. **Очередь TZ:** claim → code → gates → archive → commit/push → next **без** стопов на «ок / поехали».
4. **Очередь пуста:** отчёт «готово предложить деплой». **Не** автозапуск `deploy.ps1`. Деплой — только явная команда («задеплой» / «деплой» / «кати»).
5. Документация живая + skills: `kppdf-executor-continuous` / `kppdf-executor-loop`.
6. Cursor = архитектор/TZ; если PO сказал «сделай / добей» — исполнять по смыслу сессии.
7. Коммиты кода — по executor-loop / когда PO просит; Cursor docs можно пушить.
8. **Desktop + MCP** — зона ответственности Cursor end-to-end (подключение, стабильность, польза менеджеру, аудит стыков). PO не обязан понимать детали; агент сам дожимает до usable.
9. **Перед промптом агенту** — сначала 2–4 строки по-человечески: *что именно сделает этот агент* (без жаргона). Потом блок промпта. Не ждать магическую фразу «дай промпт», если слот свободен — выдавать.
9a. **Идеи → сразу TZ в git** (`tasks/_backlog` + checklist + QUEUE). Не держать план только в чате: PO может забыть; завтра «проверь очередь и выполни» должно хватать файлов в репо.
10. **Commit+push на каждом закрытом TZ** (и осмысленных подэтапах) — чтобы при поломке откатить именно этот кусок, а не всю неделю.
11. **Слои, не монолит:** сначала то, что забетонировано (меню, страницы-заглушки, **поля/таблицы под поток**); UX-кнопки и удобства — после проб PO в браузере, тонкими TZ без переписки раздела. Не требовать ответы A/B заранее, если PO ещё не «пощупал».

### Антипаттерны (раздражают)

- Спросить то, что уже ясно из контекста дня.
- Ждать «поехали» mid-queue (это не gate).
- Сам катить production только потому что «очередь пуста».
- Сделать «фичу ради фичи» без сценария коллеги за монитором.
- Оставить ломающий WIP в `main` / смешать FE-only деплой.
- Оставить готовый shared UI (Group Chips и т.п.) только локально / в stash — на стенде «есть», в `main` «нет».
- Длинный отчёт вместо короткого вердикта + что сделать PO.
- Оверлей-фильтры: затемнять панель вместе с контентом или закрывать по клику на `<select>` — канон в `docs/pages/products.page.md`.

## 5. Лог сессий (новые сверху)

### 2026-08-08 — Один универсальный промпт на смену агентов
- Нужен **один** текст: вставил любому агенту → читает QUEUE/_active-map → делает TZ → фиксирует Checkpoint → при обрыве завтра другой агент с тем же промптом продолжает.

- Цель цепочки — дочистить проект до «можно предлагать деплой»; сам деплой по-прежнему только по явной команде.

Источник: запрос universal continuous prompt.

Источник: чат material URL + module edit / dialog width.
