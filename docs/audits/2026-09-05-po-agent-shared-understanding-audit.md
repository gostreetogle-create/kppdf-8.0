## 2. Вердикт: где согласие, где была ошибка агента

### Согласие (одно направление)

1. **Цель продукта** — один фронт NX; деплой только NX; старый `frontend/` до cutover = эталон/склад для порта, не второй продукт.
2. **Cutover** — удаление старой папки целиком (PO вручную или одна поздняя cutover-задача). **Частично вычищать** старые разделы агентами «по ходу» — обычно **не нужно**.
3. **Умное придумывание Cursor нужно** — UX-дыры, дыры безопасности с evidence, противоречия домена, тонкие TZ по реальным замечаниям PO. Урезать агента «не думай» — вредно.
4. **Вредно** — придумывать работу, которой никто не будет пользоваться; страшилки про «два сайта / люди перепутают» без факта деплоя; тихие фичи «на всякий»; волны ради гигиены агента, а не оператора на NX.

### Ошибка этой сессии (пример)

| Шаг | Что случилось | Почему это плохо |
|-----|----------------|------------------|
| A | После паритета NX Ганта предложен partial delete legacy `/production` | Не ускоряет NX; не требуется MASTER-CORE до полного cutover |
| B | Обоснование «люди откроют оба адреса» | Выдуманный сценарий при локальной работе без dual-deploy |
| C | «PARK → Да» без человеческого абзаца сначала | Жаргон вместо общего контекста; PO вынужден догонять смысл |
| D | Gate «скажи дай промпт» на готовой волне | Ломает копипаст-ритм PO; против договорённости «промпт сразу» |

## 3. Фильтр необходимости (логика на будущее)

Перед новой TZ / шагом волны / «умной» идеей Cursor отвечает себе:

1. **Кто пользователь результата?** Оператор на **NX**, или только «репозиторий станет чище для агента»?
2. **Есть ли факт?** Живой баг, скрин PO, security evidence, конфликт с MASTER-CORE / page.md — или гипотеза?
3. **Нельзя ли дешевле?** Одна строка в backlog / заметка PO / ручной шаг в конце (удалить папку) вместо multi-TZ?
4. **Не раздуваем ли продукт?** Нет ли тихого нового экрана/поля/процесса «на вырост» без сценария цеха (~10 чел)?

Если 1 = только агент, 2 = гипотеза, 3 = да дешевле → **не ставить в continuous**, не тратить Freebuff/Claude.

Если 1 = оператор NX, 2 = факт, 3 = нет дешевле → **придумать тонкое решение и TZ** — это как раз нужное «грандиозное» мышление.
