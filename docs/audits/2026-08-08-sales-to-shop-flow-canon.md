## 0. Что значит «каталог» (простыми словами)

**Каталог** = полка готовых изделий/модулей/материалов/видов работ в системе (цены себест., состав).  
Менеджер **почти не собирает** модуль из труб — она **выбирает** уже подготовленные изделия (или комплексы из изделий) в КП. Лезть в состав — только крайний случай.

Скидки/условия сделки живут в **КП**, не портят полку каталога.

## 1. Вердикт сверки с тем, что уже в репо

| Идея PO | Уже в каноне/коде? | Заметка |
|---------|-------------------|---------|
| КП из витрины + шаблон документа | Частично: `/proposals` есть; «левая витрина / правый документ» — **будущий UX**, не ломает рельсы | TZ витрины КП — later, после склеек заказа |
| Скидки только в КП, каталог не трогаем | ✅ | Держим |
| КП → «в работу» → Заказ без цен сделки | ✅ ORDERS-301 strip | Кнопка/статус — UX polish |
| Номера КП/заказа авто + редкий ручной edit | ✅/🔶 нумерация есть; версии КП `.1/.2` — уточнить | См. Q3 |
| Заказ = что изготовить (состав), не прайс | ✅ | ORDERS-302 = увидеть дерево |
| Прямой заказ без КП + обратная связь для отчётности | Частично: создать заказ можно; **stub-КП от заказа** — нет | D7 ниже |
| «Готов к работе» → авто Гант + виды работ + люди | 🔶 Гант shell; авторазнос/ready-flag — **нет** | Нужны статусы готовности |
| Не готов → задача проектировщику доукомплектовать; можно модуль в работу раньше изделия | ⛔ UI | D8: ready на **модуле и/или линии заказа** |
| Снабжение: задача закупить; метка «материал есть»; без материала не стартовать; приоритет у обеспеченных | ⛔ отдельной страницы | D9: раздел **Снабжение** (не прятать в «остатки») |
| Склад ГП/модулей + частичная отгрузка + документ «что чьё» | 🔶 куски | SHIPPING later; след order↔module обязателен |
| Клик Гант → карточка заказа целиком | 🔶 deep-link желателен | После ORDERS-302 |

**Конфликтов «надо всё выкинуть» нет.** Рассказ = уточнение севера, не смена продукта.

## 2. Поток (как должно быть)

```text
A. Обычный путь (менеджер)
   Каталог (полка) → КП (витрина+шаблон+qty/скидки) → клиент ОКтил/ок
   → «Отдать в работу» → Заказ (без цен сделки, с изделиями)
   → развилка по готовности состава ↓

B. Быстрый путь (директор/производство)
   Заказы → создать заказ (+автономер) → изделия
   → система создаёт связанное КП-основание (отчётность, D7)
   → та же развилка готовности

C. Развилка готовности (на изделии / модуле в контексте заказа)
   ГОТОВ → снабжение (что купить) + Гант (виды работ, авто люди) 
         → работа только если материал ок → склад ГП/модуль → отгрузка (можно частями)
   НЕ ГОТОВ → очередь проектировщику: доукомплектовать спецификацию
         → можно выдать в работу ОТДЕЛЬНЫЙ модуль, когда он готов
         → остальное ждёт
```

## 3. Роли и экраны (цель, не всё сразу кодить)

| Кто | Главный экран | Делает |
|-----|---------------|--------|
| Менеджер продаж | **КП** (будущая витрина) | Собирает сделку, печатает/шлёт, отдаёт в работу |
| Директор/производство | **Заказы** | Быстрый заказ без КП; смотрит Гант |
| Проектировщик | Очередь «доукомплектовать» + карточка изделия/заказа | Ставит готовность; может пускать модуль |
| Снабженец | **Снабжение** (новый раздел) | Закупает по задачам; отмечает поступление |
| Цех | Гант / свои задачи | Видит «материалы ок?»; делает работу |
| Отгрузка | Отгрузка + док | Частичные отгрузки с привязкой заказ↔изделие↔модуль |

## 4. Решения архитектора (зафиксировано из рассказа + проф. default)

| ID | Решение |
|----|---------|
| **D1** | На заказе — состав для изготовления; прайс сделки не жить. |
| **D2** | ORDERS-302: дерево заказа = live каталог (видеть «из чего»). |
| **D7** | Заказ без КП разрешён; при создании — **авто stub-КП** «создано от заказа» (связь двусторонняя), чтобы отчётность не рвалась. |
| **D8** | Готовность к работе — не только на всём изделии: можно **модуль** выдать раньше. Гант показывает кусок с хлебными крошками к заказу. |
| **D9** | Снабжение = **отдельный пункт меню** (не смешивать с «просто остатки»). Задачи закупки из потребности заказа/готовых модулей. |
| **D10** | Старт работы цеха: нужен сигнал «материалы доступны» (хотя бы флаг/статус обеспечения линии или модуля). Без сигнала — в конец очереди / нельзя стартовать. |
| **D11** | Частичная отгрузка модулей — да; документ отгрузки несёт заказ + изделие + модуль. |
| **D12** | Автоназначение людей на Ганте = «свободный раньше закончит» — P1 после ready+материалы; вручную править всегда можно. |
| **D13** | Витрина КП (лево товары / право шаблон) — **отдельная UX-волна**, не блокирует ORDERS-302 / снабжение-скелет. |
| **D14** | Не строим бухгалтерию, CRM-звонки, тендерный зоопарк. |
| **D21** | Несколько КП на те же позиции для **разных наших юрлиц (Organization)**: копировать КП → смена Organization → подтянуть шаблон/наценку фирмы; список изделий+qty сохраняется. UX: «распечатать несколько КП» → multi-select Organization с шаблонами → N КП с разными ценами. **Не** путать Organization с Counterparty-заказчиком. TZ later: SALES-303 (не блокирует ORDERS-302/303). |

## 5. Ответы PO (2026-08-08) → решения

| # | Ответ PO | Канон / TZ |
|---|----------|------------|
| Q1 | Гибко: сотрудники могут пускать сами; критичное — через **чекбоксы в ролях** (сейчас доверяем, потом закрыть пункт менеджеру) | **D15:** capabilities на роли (`release_to_work`, `confirm_procure`, `set_line_ready`…) — заложить в ACCESS-волне; сейчас не блокировать жёстко |
| Q2 | Разбиение КП→много заказов **не нужно** как основной сценарий: один КП → один заказ; разные сроки = **даты отгрузки на позициях/группах** | **D16:** нет split-order из КП в P0; `plannedShipDate` на линии (или группе линий) |
| Q3 | Версии КП = история «что отправили клиенту» при правках; старые можно удалить / мусорное КП удалить | **D17:** при отправке/фиксации — immutable version; edit → новая версия; delete не-сконвертированных — ok. TZ-SALES-302 later |
| Q4 | Снабжение: сначала **подтверждение «можно заказывать»** (зелёный флаг + кто подтвердил), потом закуп. Ответственный — на **изделие в заказе** (не весь заказ); авто → проектировщик/менеджер линии | **D18:** `line.ownerUserId` + avatar; procureConfirm {by, at}; задачи снабжения от линии/модуля |
| Q5 | Жёсткий запрет старта **не** нужен (склад / материал заказчика). Warning + отчётность; галка «материалы заказчика» | **D19:** soft gate; `materialsSource: own\|customer`; mismatch → колокольчик |
| + | Заказ: обязательны **заказчик + объект**; быстрый заказчик (имя/тел) + объект (адрес) с страницы заказа | **D20:** Counterparty + **Site/Object** (дочерняя площадка); order.counterpartyId + order.siteId; quick-create thin |

### Проф. defaults (без доп. вопросов)

- **Объект** = площадка/адрес у заказчика (N объектов на 1 Counterparty), не «юрлицо».  
- Один КП → один Order; частичная отгрузка и даты линий закрывают «сделайте часть сейчас».  
- Ответственный на **линии заказа** (изделие), иконка/аватар в UI заказа.

## 6. Что НЕ делаем в ближайших TZ

- Витрина КП мечты (лево/право)  
- AI-авторазнос людей до ready+материалы  
- Жёсткий блок цеха без материала  
- Split одного КП на много заказов  
- Бухгалтерия
