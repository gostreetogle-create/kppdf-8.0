## 2. Вердикт: ты понимаешь правильно

Твоя картинка **совпадает** с тем, как студия уже устроена внутри — плохо только **упаковка на экране**.

| Ты говоришь | Как в системе уже есть |
|-------------|-------------------------|
| Выбрал товары → они копятся | `context.catalogSelections` + чипы «Выбрано» |
| На A4 появятся после таблицы, которая это умеет | `dataSet.source.type`: `catalog-products` / modules / parts / materials |
| Система должна подсказать таблицу | **Сейчас слабо:** есть выбор источника в **Свойствах** таблицы справа; из «Данные» явного «вставить таблицу под эти товары» нет. Уже выбранные товары **подтягиваются** в *существующую* таблицу с тем же источником (S41 queue), но **новую** таблицу сам не предлагает |
| Формулы/суммы — в настройках таблицы | Уже так (S21–S24) |

**Клиент / плательщик / поставщик / КП / заказ** — это не «ещё товары», а **якоря документа** (кто продаёт, кому, из какого КП/заказа брать строки). На одном экране с витриной они выглядят как мусор — отсюда ощущение «всё в кучу».

Словарь для человека:

| На экране сейчас | Смысл для менеджера | Код |
|------------------|---------------------|-----|
| Исполнитель | Наша фирма (обычно уже задана) | `Organization` / anchor `issuer` |
| Клиент | Кому продаём | `Counterparty` |
| Плательщик | Кто платит (часто = клиент; нужно не всегда) | `Counterparty` |
| Поставщик | Редко для КП; чаще другие типы документов | counterparty/org |
| Коммерческое предложение | Связать лист с уже существующим КП | `Quotation` |

**D56 implementation note:** в production UI буфер `Выбрано` открывается отдельным левым rail-инструментом; в TOC «Данные» остаются только `Товары`, `Кому`, `Связи`, `Ещё`. Это осознанное исключение прежнего TOC-only ограничения по прямому override PO.
| Статус КП | Черновик / на проверке / принято | lifecycle |
| Заказ | Связать с заказом (строки из заказа) | `Order` |

Для **нового КП** менеджеру почти всегда нужны: **товары + клиент (+ наша фирма уже есть)**. КП/заказ/плательщик/поставщик — второй ряд.

## 3. Целевой сценарий (канон UX)

```
Левый chrome-rail
  ├─ «Данные» → wide TOC: Товары | Кому | Связи | Ещё
  └─ «Выбрано» → overlay буфер + «Вставить на лист» (PO override 2026-09-05 / D56)
Центр A4 — пусто, пока не вставили блок
Право — Элементы / Свойства (как сейчас; формулы таблицы там)
```

**Не делаем:** авто-вставку таблицы при каждом «Добавить» без клика (шум, ломает пустой шаблон).
**Делаем:** явная кнопка/список у буфера «Вставить на лист…».

**PO override (2026-09-05):** буфер «Выбрано» — отдельная иконка под «Данные», не TOC внутри Данные; D56 реализует это как второй left `ShellToolRailItem` с тонким count badge. Остальные категории остаются TOC (не плодить chrome-иконки). WAVE `WAVE-DOCSTUDIO-DATA-IA-2` · D55 + D56.

## 4. Рекомендуемые категории (по востребованности для КП)

| # | Где | Содержимое | Зачем |
|---|-----|------------|-------|
| 1 | TOC **Товары** | Витрина изделия/модули/детали/материалы | Главный вход |
| 2 | Rail **Выбрано** (D56) | Буфер + CTA вставки; empty «ничего не выбрано» | Сердце сценария |
| 3 | TOC **Кому** | Клиент (+ плательщик disclosure) | Якорь покупателя |
| 4 | TOC **Связи** | **КП** (не «Коммерческое предложение»), статус КП, заказ — с пунктом сброса (D55) | Источник строк/номера |
| 5 | TOC **Ещё** | Поставщик; Исполнитель read-only | Редкое |

Порядок TOC можно чуть сдвигать по `docType` (КП vs паспорт) — тонкий follow-up, не блокер D50.
