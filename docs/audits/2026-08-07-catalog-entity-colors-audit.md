# Аудит — цвета оформления каталога (изделие / модуль / материал)

**Дата:** 2026-08-07  
**Запрос PO:** как у видов работ (`accentHue` на Ганте) — визуально различать
товар / модуль / деталь / материал везде, где они встречаются; где ставить
выбор цвета; что ещё положить в такую «панель оформления».

**Не путать:**

| Понятие | Что это | Где сейчас |
|---------|---------|------------|
| **RAL / цвет изделия** | Физический цвет покраски / справочник | `color_references`, поле `ralCode` у Product |
| **Цвет вида работ** | UI-акцент полоски на Ганте | `WorkType.accentHue` + `workTypeOklch` |
| **Цвет сущности каталога (новое)** | UI-акцент **типа** (и опционально экземпляра) в дереве состава, списках, инспекторе | **нет** |

---

## 1. Что PO хочет по смыслу

Не «ещё один RAL», а **легенда каталога**: взглянул на дерево / список —
сразу видно, где изделие, где модуль, где деталь/материал.

Уже есть зачатки: бейджи `изд` / `мод` / `мат` в `app-composition-tree`.
Не хватает **согласованной палитры** и единого места настройки.

---

## 2. Где лучше ставить выбор цвета

### Рекомендация (канон для TZ)

**Сначала — цвета по ТИПУ сущности (kind), одно место «Оформление каталога».**  
Не размазывать палитру по каждой карточке Product/Module/Material.

| Вариант | Плюсы | Минусы | Вердикт |
|---------|-------|--------|---------|
| **A. Справочник «Оформление каталога»** (новый chip / пункт Справочники или Каталог) | Одна панель; как легенда; не захламляет формы товара | Ещё один экран | **Да — P0** |
| **B. Поле accentHue в каждой форме изделия/модуля/материала** | Как виды работ | 100 товаров = 100 цветов; хаос; дубли с kind | **Нет как основа** |
| **C. Только хардкод в CSS по kind** | Быстро | PO не крутит пресеты «как на Ганте» | Промежуточно до A |
| **D. Подмешать в color_references** | Уже есть UI | Смешает RAL и UI-акцент — путаница для цеха | **Нет** |

**Почему не в форме каждого товара:** PO сказал «понятие сущности» — тип, не каждый SKU.  
Виды работ — другая история (мало записей, каждая = полоска на Ганте).

**Опционально позже (P2):** `accentHue` на экземпляре **только** Product/Module,
если нужен «этот модуль особенный» — override поверх kind. Не в первом TZ.

### Куда в IA

Предпочтительно:

```
Каталог → [chips…] → Оформление
```

или

```
Справочники → Оформление каталога
```

Не Админ (это не ACL). Не внутри RAL-справочника.

Экран: пресеты hue (тот же UI, что у видов работ) на строки:

| Роль UI | Kind / ключ |
|---------|-------------|
| Изделие | `product` |
| Модуль | `module` |
| Деталь | `material` + `materialKind=part` (и fastener/purchased/other — см. ниже) |
| Материал / сырьё | `material` + `materialKind=raw` (и purchased если «покупное как материал») |

**Минимум P0:** 3 слота — Изделие / Модуль / Материал (все materialKind одним тоном).  
**P1:** развести Деталь vs Сырьё vs Метиз (как в composition vision).

## 3. Где показывать цвет (карта поверхностей)

| Поверхность | Как применить | Приоритет |
|-------------|---------------|-----------|
| **Дерево состава** (`composition-tree`) | wash фона строки + цвет бейджа по kind | **P0** |
| Инспектор BOM | полоска / точка у «Выбрано» | P0 |
| Списки Products / Modules / Materials | тонкая полоска слева или точка у имени | P1 |
| Picker «Добавить в состав» | цвет бейджа вкладки / строки | P1 |
| Карточка изделия (паспорт) | опционально рамка фото по kind | P2 |
| Гант / заказы | **не** смешивать с accentHue видов работ | — |
| Документы / КП | не трогать в первой волне | — |

Единый helper по аналогии с `workTypeOklch`:  
`catalogKindOklch(kind, materialKind?, chroma, lightness)` + чтение пресетов из settings API или seed defaults.

---

## 4. Что ещё положить в «Оформление каталога» (пока открыли панель)

Имеет смысл сразу (тонко, без зоопарка):

| Настройка | Зачем | Волна |
|-----------|-------|-------|
| **Палитра kind → hue** | Главный запрос | P0 |
| **Короткие подписи** изд / мод / мат (редактируемые?) | Обычно хватает канона; не давать править в P0 | — |
| **Легенда на дереве** (вкл/выкл) | «что значит цвет» для новичка | P1 |
| **Плотность строк дерева** (compact / comfortable) | Клики/состав | P1 |
| **Показывать qty в строке** всегда / только ≠1 | Сейчас только ≠1 | P1 |
| **Глубина авто-раскрытия** (1–3) | Меньше кликов | P2 |
| Иконки вместо текста бейджа | Красиво, но спорно для цеха | backlog |

**Не класть сюда:** RAL, цены, единицы, права, складские правила.

## 5. Технический контур (для TZ)

1. **Defaults в коде** (7 hue buckets как у work types) — работают без БД.
2. **Persist:** либо `Organization.settings.catalogAppearance`, либо маленькая
   коллекция `catalog_ui_presets` — выбрать в TZ после audit schema org settings.
3. **FE:** shared swatch control (вынести из work-type form → `PiAccentHueField`).
4. **Consumers:** composition-tree + BOM inspector в первом PR; списки — второй.

**НЕ:** Part entity; путать с `color_references`.

## 7. Вердикт одной фразой

**Не в форму каждого товара и не в RAL.**  
Отдельное **Оформление каталога** (цвета по типу сущности) → сначала дерево состава;
UI выбора — клон пресетов с видов работ; опционально плотность/легенда/qty в той же панели.
