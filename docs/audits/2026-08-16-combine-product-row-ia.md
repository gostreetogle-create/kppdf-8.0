# Audit + proposal: Комбайн — изделие-ряд (accordion), 2026-08-16

**Источник:** диктовка PO + скрины с красной разметкой (горизонтальные блоки).  
**Код сейчас:** `/design/combine` = классический канбан **колонка → карточки изделий** (`DashboardPage`, CDK DnD по `boardLane` / `moduleLanes`).

---

## 1. Независимый разбор

### Боль текущего UI

Глобальные колонки смешивают **разные заказы и изделия** в одной куче. DnD модулей + expand карточек → коллапсы, потеря контекста «это модуль какого мангала?». PO хочет **контекст изделия** первичным, стадии — вторичными.

### Что в данных уже правильно (не ломать)

| Канон | Остаётся |
|-------|----------|
| Колонки = `boardLane` (prep / design / shop / to_ship / shipped) | Да |
| Карточка = `OrderItem` (изделие на заказе) | Да — станет **рядом** |
| Модули = `Order.moduleLanes` + PATCH lane | Да — DnD внутри раскрытого ряда |
| Отгрузка = целый заказ (`POST /ship`), не PATCH shipped | Да |
| Rollup `Order.status` | Да |

### Предложение архитектора (синтез + доработка)

**A. Список = горизонтальные ряды изделий** (на всю ширину), не карточки в колонках.

**B. Sticky шапка стадий** над списком (Комплектация … Отгружены) — выравнивание колонок при раскрытии; без горизонтального скролла доски (5 равных долей ширины).

**C. Свёрнутый ряд:** № заказа · имя изделия · qty · **индикатор стадий** (5 тонких сегментов: загорается, если в стадии есть модуль; для изделия без модулей — один сегмент = где стоит «целиком»).

**D. Раскрытие ▸ / клик по ряду:** под рядом — мини-комбайн: 5 ячеек под шапкой, тонкие вертикальные линии; внутри — чипы модулей. DnD **только горизонтально** между ячейками этого изделия (не между изделиями).

**E. Без модулей:** один чип «Изделие целиком» в эффективной lane (как Гант 345) — drag по стадиям.

**F. Группировка (опционально V1.1):** визуальный подзаголовок по `orderId`, чтобы мангалы одного заказа шли рядом — не обязательно в первом TZ.

**G. Не делать сейчас:** отдельное «меню модуля» / полный drawer — park; клик по модулю → позже (карточка `/modules/:id` или flyout).

### Почему не «заказ = ряд»

На скрине PO обводит **изделия** (мангал / стеллаж / забор). Один заказ = несколько изделий с разным прогрессом. Ряд = **OrderItem**. Заказ — бейдж на ряду.
