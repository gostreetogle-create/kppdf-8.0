## 1. Вопрос PO простым языком

Сейчас два переключателя. Хочется **одно место**, где видно и сроки заказов, и **кому** работа назначена, и можно **перекинуть** работу между людьми — без прыжка «сначала заказы, потом рабочие».

## 2. Что есть сейчас (факт)

| Режим | Дерево слева | Календарь | Правка сроков / сдвигов |
|-------|--------------|-----------|-------------------------|
| **По заказам** | Заказ → изделие → модуль → вид работ | Сводная + бары | Да (менеджер) |
| **По рабочим** | Рабочий → модуль (с контекстом заказ·изделие) → вид работ | Сводные tinted dominant WT | **Нет** (спека: read-only, без PATCH) |

Назначение людей уже живёт на **виде работ** (не на всём заказе целиком). В подвале экрана: «клик вида работ = дни и люди». «По рабочим» = **срез нагрузки**, не второй редактор заказа.

## 3. Почему «склеить в одно дерево» опасно

1. **Разные вопросы.**  
   - Заказы: «когда сдадим З-2026-002?»  
   - Рабочие: «кто перегружен на следующей неделе?»  
   Одно дерево не может быть одновременно «главный ключ = заказ» и «главный ключ = ФИО» без каши или огромных дублей строк.

2. **«Переместить заказ между рабочими»** — формулировка скользкая.  
   У заказа обычно **несколько** видов работ и **несколько** людей. Переносят не заказ целиком, а **конкретный вид работ / модуль** (или пачку). Иначе менеджер думает, что перетащил весь З-…, а сдвинулась только сварка.

3. **Два write-path.**  
   Сейчас правка сроков — в режиме заказов. Назначение людей — через карточку/клик WT. Если сделать drag «бар → другая ФИО» в объединённом виде — это **новый** write-path (L1-ish), его надо проектировать отдельно, не «просто убрать переключатель».

4. **Масштаб цеха ~10 чел.**  
   Два чипа переключения дёшевы. Тяжёлый гибрид «всё редактируется везде» дороже пользы, пока назначение ещё не доведено как продукт L1.

## 4. Варианты (Cursor)

### A — Оставить два режима (база)

Плюс: уже понятно, спека соблюдена.  
Минус: не видно людей, не раскрыв WT / не переключившись.  
Вердикт: минимум; PO уже чувствует дыру.

### B — **Рекомендация Cursor:** один **главный** режим «По заказам» + люди на виду; «По рабочим» оставить как **обзор нагрузки** (можно read-only)

Что сделать по смыслу (не код сейчас):

- В дереве заказов на строке **вида работ** (и/или модуля) всегда показывать **ФИО / «Не назначен»** (громко, как канон).  
- Клик WT по-прежнему = дни и люди (редактирование назначения там, один write-path).  
- Опционально: фильтр «только неназначенные».  
- «По рабочим» не убивать: планирование смены / перегруз — отдельный взгляд; правку сроков туда **не** тащить.

Удобнее ли? Для ежедневной работы менеджера — **да**, почти всё в одном месте, без ложной метафоры «перетащил заказ».  
Грамотно ли? **Да** — совпадает с каноном «правка в каскаде» и с тем, что люди привязаны к WT.

### C — Настоящее объединение: editable «По рабочим» + drag между ФИО

Плюс: мечта «перекинул полоску Иванову».  
Минус: новая модель DnD, конфликты с multi-assignee, дубли баров, риск сломать G4/G5. Это уже **волна L1 (назначение)**, не polish.  
Вердикт: не сейчас, пока нет явного L1 ТЗ на assign.

### D — Два календаря рядом / split view

Плюс: оба вопроса на одном экране.  
Минус: узкий ноут, закон плотности студий, дорого.  
Вердикт: не для ~10 чел. и текущего Ганта.

## 5. Предварительный вывод Cursor (до ответа Claude)

**Полностью склеивать два режима в одно editable-дерево — некорректно и не удобнее.**  
**Корректно и удобнее:** усилить «По заказам» видимостью и правкой людей на уровне вида работ; «По рабочим» оставить вторым чипом как карта загрузки (read-only).  
Финальный вердикт — после вставки ответа Claude в этот чат.
