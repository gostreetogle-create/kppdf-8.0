# UX — Состав как «вложенные рамки» (containment outline)

**Дата:** 2026-08-08  
**Источник:** наброски PO (изделие → модуль/деталь → материал; рамки принадлежности; module-in-module).  
**Не брать с эскиза:** цвета заливок, штриховки, толщину рамок, шрифты — это wireframe.  
**Взять с эскиза:** *смысл* — кто внутри кого; несколько детей у одного родителя; разная глубина.

Связано: [`ui-composition-tree.md`](../pages/ui-composition-tree.md) · kind colors 330/331 · cost rollup COST-302.

---

## 1. Что хочет PO (канон смысла)

1. Слева направо читается **уровень роли**: изделие → модуль/деталь → материал.  
2. **Рамка** вокруг группы = «это всё принадлежит родителю».  
3. Один родитель → много детей (два модуля в изделии; два материала в модуле).  
4. Глубже: модуль в модуле + детали/материалы — без ломки модели.  
5. Легко **раскрывать / сворачивать**, если веток много.

---

## 2. Почему не «жёсткие 3 колонки таблицы»

Фиксированные колонки «Изделие | Модуль | Материал» красивы на 1–2 уровнях, но:

- module → module → material ломает «ровно 3 колонки»;
- rowspan как в Excel плохо живёт с expand/collapse и длинными именами;
- наш домен уже tree API + `app-composition-tree`.

**Решение:** не spreadsheet, а **containment outline** — те же рамки, но через вложенные панели + kind-цвета (уже в каталоге).

---

## 3. Вариант исполнения (канон UI)

### 3.1 Метафора

Каждый **раскрытый** узел рисует вокруг своих детей мягкую карточку-контейнер:

```
┌─ изделие (корень страницы — без дубля строки, опц.) ─────────┐
│  ┌─ модуль A ─────────────────────────────────────────────┐  │
│  │   · материал 1                                        │  │
│  │   · материал 2                                        │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌─ модуль B ─────────────────────────────────────────────┐  │
│  │   ┌─ модуль B.1 ─────────────────────────────────────┐ │  │
│  │   │   · материал …                                   │ │  │
│  │   └──────────────────────────────────────────────────┘ │  │
│  └───────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

Это ровно «рамочки» PO, без Excel-span.

### 3.2 Поведение (сохраняем composition-tree)

| Правило | Как |
|---------|-----|
| Клик по всей строке | select + expand / collapse (канон) |
| Свёрнуто | видна только строка узла + ›; рамка детей скрыта |
| Раскрыто | строка + **вложенная панель** детей с hairline border + wash kind родителя |
| Лист (материал) | без панели детей |
| Глубина | indent 12–16px / уровень; max визуальный комфорт ~4–5; глубже — те же рамки, скролл |
| Много детей | список внутри рамки, не горизонтальный «ряд колонок» |

### 3.3 Цвет и плотность (Paper & Ink + kind)

- Не коричневый/синий/зелёный с эскиза — **`catalogKindOklch`** (изделие / модуль / материал / сырьё), light+dark.  
- Рамка: `1px` hairline + лёгкий wash фона родителя (как tree wash 330), не толстая чёрная обводка.  
- Слева у строки — kind rail / marker (332).  
- Легенда над деревом (компактно): цветные точки «Изделие · Модуль · Деталь/мат · Материал».  
- Qty — справа в строке; вклад в себест. — later (COST-303), не в этом TZ обязательно.

### 3.4 Размеры (ориентиры)

| Элемент | Значение |
|---------|----------|
| Высота строки | 36–40px |
| Padding панели детей | 8px 8px 8px 4px |
| Gap между sibling-рамками | 6–8px |
| Radius | 6–8px (как pi cards) |
| Max width имени | truncate + title tooltip |
| Сцена состава | min-height ~320px; скролл внутри панели BOM, не всей страницы |

### 3.5 Module-in-module / «деталь»

- **Деталь** = Material kind (part/…) — лист или узел с материалами по домену; визуально kind marker «деталь», не отдельная колонка.  
- Вложенный модуль = та же рамка, глубже на 1 indent.  
- Не вводить новую сущность Part.

### 3.6 Что не делаем

- Отдельный «колоночный kanban» состава.  
- Карточки-радуга / тяжёлые тени.  
- Ломать инспектор справа (+ из каталога в выбранный узел).  
- Дублировать корень «ИЗД» если паспорт уже показывает имя (смягчить label корня).

---

## 4. Технический путь

1. Расширить `app-composition-tree`: при `expanded` дети рендерятся **внутри** `.comp-tree__nest` (рамка + wash по `kind` родителя).  
2. `ProductBomPanel` — легенда + docs.  
3. Specs: expand рисует nest; collapse убирает; light/dark snapshot optional.  
4. Не трогать BE composition API.

## 6. Acceptance (смысл для PO)

На карточке изделия в «Состав» при раскрытии модуля видно: материалы **внутри его рамки**; два модуля = две рамки рядом по вертикали; модуль в модуле = рамка в рамке; клик по строке по-прежнему раскрывает без прицеливания в ›.
