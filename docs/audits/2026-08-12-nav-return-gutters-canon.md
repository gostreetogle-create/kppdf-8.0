# Навигация: возврат + системные ←→ в полях (канон PO 2026-08-12)

## Как пользоваться сейчас (коротко)

| Что делаете | Что должно быть | Что сейчас |
|-------------|-----------------|------------|
| Create КП → выбрать шаблон | Превью A4 этого бланка | OK (если шаблон выбран) |
| Create КП → «Редактировать шаблон» | Сразу **конструктор** `/doc-constructor/builder/:id` | **БАГ:** уходит на **список** `/templates?templateId=…` (query никто не открывает) |
| После правок шаблона | Вернуться в Create КП (откуда ушли) | Builder «← Шаблоны» всегда на список |
| Системные ← / → | Как история браузера, красиво в полях слева/справа от колонки контента | **Нет** (page-chrome раньше запрещал; PO отменяет) |

Паттерн возврата уже есть для каталога: `CatalogReturnStore` (TZ-UX-313) — `Location.back()` если знаем previous same-app URL, иначе fallback. Нужно **обобщить** на весь сайт + явный `returnUrl` при уходе в builder.

## Север UX

1. **Deep-link в редактор** всегда на конкретный ресурс (`/builder/:id`), не на список с «надеждой на query».
2. **Возврат после edit/save:** приоритет  
   a) явный `returnUrl` / `source` в query при уходе;  
   b) иначе smart history (`previousUrl`);  
   c) иначе fallback раздела (Шаблоны / Каталог / …).
3. **Глобальные ← →** в **полях** (пустое поле слева/справа от max-width колонки), на всём сайте, в app shell — не внутри page content и не дубль жёлтого меню.  
   На узких экранах — компактно / скрыть вперёд или оба в одну сторону без ломания A4-студий.
4. Контекстные кнопки в полях могут появляться/пропадать по разделу — v1 только ← →.

## Не путать

- Крошки = структура IA, **не** history.  
- Studio Create КП rails (Шаблон/Товары/…) = инструменты страницы, **не** системный history chrome.
