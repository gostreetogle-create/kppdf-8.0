## 1. Для PO простым языком

**На скрине «Люди: Петров…, Сидоров…» — это не «кто делает сварку на этом заказе».**

Сейчас система показывает: **кто в справочнике Люди умеет вид работ «Сварка»** (галочки видов работ в карточке человека).  
Те же два ФИО появятся на **любой** сварке **любого** заказа.

Поэтому ты «не нашёл, как передать работу другому»: **передачи работы на конкретный заказ в продукте ещё нет.** Есть только настройка «Петров умеет сварку» в карточке человека (раздел **Люди**, сейчас полноценно на старом фронте `:4200/people`; на NX Гант ведёт ссылку `/people`, **страницы Люди в NX пока нет** — ссылка с баннера на NX может вести в никуда).

**Чип ФИО прямо на строке «Сварка» без клика — не делаем** (ты прав: испортит компактность). G11 chip отменён.

## 2. Что ты хочешь (и это правильно)

Работа (сварка на этом заказе/модуле) → **выбрать, кому поручаем** → список людей → сохранить.  
Место: уже открытая фиолетовая панель под видом работ — идеальный UX.

Это **новая** способность продукта (job assignment), не косметика.

## 3. Варианты

| | Вариант | Вердикт |
|---|---------|---------|
| A | Только улучшить ссылки в «Люди» + пояснить, что это навыки | Мало; не закрывает «кому эту сварку» |
| B | **Рекомендация:** в панели WT — multi-select исполнителей **на эту строку заказа** (override), писать в Order рядом с estimate days/start | Да — твой сценарий |
| C | Drag между «По рабочим» | Позже / нет; ложные метафоры |
| D | Редактировать только навыки в Людях | Оставить как справочник «кто умеет», не как поручение |

**Модель данных (предложение B):**  
как `estimateDayOverrides` — массив на заказе, ключ `(orderItemIndex, moduleId, workTypeId)` → `workerIds[]`.  
Пусто = показывать как сейчас (из навыков) **или** «Не назначен» — **решение по умолчанию:** пустой override = «Не назначен» на Ганте для планирования; навыки остаются в Людях для фильтра «кого можно выбрать в списке».  
(Так менеджер явно поручает; не путает «умеет» и «назначен».)
