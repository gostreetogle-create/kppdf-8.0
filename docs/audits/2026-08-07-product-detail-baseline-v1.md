## 1. Что это за страница

Не «просто просмотр». Это **панель управления изделием**: паспорт + дерево состава
(товар → модули/детали/дочерние изделия) + фото + себестоимость.

Вход: Каталог → Продукция → клик по строке/карточке → `/products/:id`.

Крошки: `Каталог / <имя изделия>`.

---

## 2. Бизнес-модель состава (уже в коде / каноне)

Источник: `docs/compose/plans/2026-08-04-catalog-composition-vision.md` (D1–D4).

| Родитель | Можно добавить | Нельзя |
|----------|----------------|--------|
| **Изделие (Product)** | модуль; материал≠сырьё (деталь/метиз/покупное); **другое изделие** → комплекс | сырьё напрямую; self-ref; циклы |
| **Модуль** | дочерний модуль; любой материал (в т.ч. сырьё) | изделие внутрь модуля |
| **Материал** | — (лист) | — |

Связь = **ref + quantity** (не deep-clone). Глубина hard max **8**, UI warn после 5.

---

## 3. Состояние UI на baseline v1

### Layout

1. `PiPageChrome` — крошки без гигантского H1.
2. Split `xl`: слева sticky-карточка (фото, имя, бейджи RU, цены 2×2, габариты).
3. Справа: панель **Состав** (`CompositionEditor` + дерево + поиск/select + «Добавить из каталога»).
4. Аккордеон: Фото · Себестоимость.

### Состав (технически OK, визуально слабо)

- Lazy tree: `GET /products/:id/tree`.
- Add: picker-диалог (модуль / деталь / изделие) + inline select с поиском.
- ObjectId как основной UX — убран.
- Добавление в **контекст выбранного узла дерева** (модуль внутри модуля с этой страницы) — **не доведено**: inline/picker добавляют на **корневой** product parent; вложенный модуль правится уходом на `/modules/:id` или через дерево без полного in-place inspector.

## 4. Что PO уже отверг / боль baseline

- Гигантский `text-5xl` заголовок на длинных именах.
- Пустые секции «Основное / Габариты» на полэкрана.
- ObjectId вместо выбора из каталога.
- Нет ясной **иерархии** «это изделие → это модуль → это деталь» на одном взгляде.
- Не ощущается единая **панель сборки**, а набор секций + техредактор.
