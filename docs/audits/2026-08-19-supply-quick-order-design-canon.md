# Supply Quick Order — design canon (UX audit)

**Дата:** 2026-08-19  
**Источник:** `tasks/PROMPT-SUPPLY-304-quick-order-design.md`  
**Эталон данных:** Excel PO 2026-08-19 (метизы, оснастка, profrezi.ru, Кубаньподшипник)  
**Статус:** **PASS** — готово к `TZ-SUPPLY-304` (mock UI), затем `TZ-SUPPLY-305` (API)

---

## 1. Север (одной фразой)

**«Быстрый заказ»** — это блокнот снабженца: за утро набить десять позиций «что · у кого · сколько · когда · срочно ли» без обхода каталога и организаций, а **«Реестр»** — тот же реестр контроля, куда строки попадают, когда их пора отслеживать по статусам закупки.

---

## 2. IA — навигация, URL, входы

### URL-канон

| URL | Режим | Default |
|-----|--------|---------|
| `/supply` | Быстрый заказ | **да** (redirect/query `view=quick`) |
| `/supply?view=quick` | Быстрый заказ | явный |
| `/supply?view=registry` | Реестр SupplyTask (таблица 301/302) | нет |
| `/supply?view=quick&orderId=` | Быстрый заказ с предзаполненным контекстом заказа | из стола/tray |

Query `orderId` **сохраняется** при переключении Быстрый заказ ↔ Реестр.

### Два режима — зачем одному человеку

| Режим | Когда | Ментальная модель |
|-------|--------|-------------------|
| **Быстрый заказ** | Утро, входящие устные/листовые заявки, срочные дозаказы | «Записная книжка на сегодня» — плотный ввод, expand-in-row |
| **Реестр** | Обзор недели, фильтр «Заказано», сверка с производством, confirm/received | «Журнал исполнения» — таблица, lifecycle SupplyTask |

Не смешивать: быстрый режим **не** показывает колонки confirm/ordered/received actions — только свой статус заявки. Реестр **не** меняет UX создания — «+ Задача» и BOM explode остаются.

### Chip-строки (sticky, сверху вниз)

```
┌─────────────────────────────────────────────────────────────┐
│ [ Закупки ] [ Отгрузка ]     ← group-workspace (как сейчас) │
├─────────────────────────────────────────────────────────────┤
│ [ Быстрый заказ ● ] [ Реестр ]   ← view mode (новое)        │
│  🔍 Поиск…  │ Статус ▾ │ Приоритет ▾ │  12 заявок │ + Создать│
└─────────────────────────────────────────────────────────────┘
```

- **Row A:** `LOGISTICS_SECTION_CHIPS` — без изменений (`Закупки` / `Отгрузка`).
- **Row B:** segmented chips **«Быстрый заказ» | «Реестр»** + toolbar в той же sticky-зоне (dense, как `/desk` tools).
- Default при открытии `/supply` — chip **«Быстрый заказ»** активен.

### Точки входа

| Откуда | Куда | Контекст |
|--------|------|----------|
| Desk workflow chip **«Снабжение»** | `/supply?view=quick` | без orderId |
| Desk tray **«Открыть снабжение»** (`onOpenSupply`) | `/supply?view=quick&orderId={expanded}` | если строка заказа раскрыта |
| Меню **Снабжение** | `/supply` → quick | — |
| Supply chip **«Реестр»** | `/supply?view=registry` | таблица как сейчас |
| Orders hub / deep-link (будущее) | `/supply?view=registry&orderId=` | фильтр реестра (HUB-303, уже есть) |

Flyout `panel=supply` на столе **не** дублирует форму v1 — только navigate наружу (reuse-first: один write-surface на `/supply`).

- Disclosure **▸ / ▾** — крупно, как на `/desk` (reuse визуального языка).

## 4. Плитка: свёрнута vs развёрнута

### 4.1 Свёрнута (summary row)

Одна строка, слева направо (truncate с ellipsis на длинных):

```
▸  19.08  ·  Оснастка  ·  Цанга ER16  ·  1 шт  ·  [В работе]  ·  🔴 Срочно  ·  profrezi.ru
```

| Элемент | Источник | Примечание |
|---------|----------|------------|
| Дата | `createdAt` или дата строки | `dd.MM` |
| Категория | справочник категорий заявки | короткий label |
| Наименование | `title` * | главный якорь |
| Qty + ед. | `qty` + `unit` * | «4 шт» |
| Статус | badge | цвет из EntityStatus (mock: palette) |
| Приоритет | chip/dot | 🔴 urgent / ○ normal / 🟢 low |
| Поставщик | short name | домен или 12 символов |

\* обязательны для «сохраняемого» черновика (mock: локально).

Клик по строке или ▸ — expand. Отдельная кнопка «Удалить» — только в развёрнутом виде (destructive + confirm).

### 4.2 Развёрнута (форма по блокам)

```
▾  19.08 · Оснастка · Цанга ER16 · …                    [ Удалить ]

┌─ Что заказать ─────────────────────────────────────────────┐
│ Категория ▾          Наименование * [________________]      │
│ Артикул [_______]    Цвет [_______]   Фото [thumb][+загр.] │
│ Кол-во * [__]        Ед. изм. * ▾                           │
└────────────────────────────────────────────────────────────┘

┌─ Откуда купить ────────────────────────────────────────────┐
│ Поставщик ▾  [+ Новый]    Ссылка на товар [https://…]      │
└────────────────────────────────────────────────────────────┘

┌─ Контекст ─────────────────────────────────────────────────┐
│ Наша компания ▾     Кто просил ▾ или [__________]            │
│ Связь с заказом ▾ (необяз.)   Нужно к [__.__.____]          │
└────────────────────────────────────────────────────────────┘

┌─ Статус и приоритет ───────────────────────────────────────┐
│ Статус ▾            Приоритет ▾                              │
│ Примечание [________________________________ multiline]      │
└────────────────────────────────────────────────────────────┘

▸ Ещё (свернуто по умолчанию)
   Ориентир. цена · Сумма строки · Дата заказа у поставщика · Ответственный
```

**Grid:** 2–3 колонки на широком экране, 1 колонка &lt;768px. Блоки — `pi-dashed-panel` / hairline, **не** карточки SaaS.

**«+ Создать»:** новая плитка вверху списка, `expandedId` = новая, focus в **«Наименование»**, статус default **«В работе»**, приоритет **«Обычный»**, наша компания = текущая org user (mock: первая в списке).

## 7. Связь с Реестром (концепт, без API в 304)

```
Быстрый заказ (SupplyRequest)          Реестр (SupplyTask)
─────────────────────────────          ────────────────────
Черновик «В работе»        ──stay──►  (не виден в реестре)
Статус «Заказано»          ──spawn──►  строка SupplyTask draft/ordered
                                       + link supplyRequestId
С BOM explode (302)        ─────────►  только реестр (как сейчас)
```

**Правило PO для 305:**

1. Пока статус ∈ {В работе, Запрошено} — строка **только** в быстром режиме.
2. При переходе в **«Заказано»** — опционально создаётся `SupplyTask` (или обновляется linked) для реестра; в quick-строке badge «В реестре» + link «Открыть в реестре».
3. Реестр **не удаляется** — audit и order-linked tasks остаются каноном для производства.

Поле `source=excel|manual` — только backend, не в UI.

## 8. Антипаттерны (запрет v1)

1. **Обязательный materialId/productId** перед save — свободный текст + артикул достаточно.  
2. **Канбан / drag статусов** — только dropdown.  
3. **Замена табличного реестра** быстрым режимом — два chip, два write-path с разной зоной ответственности (305 синхронизирует).  
4. **Navigate-away create** (организации, каталог) — inline only.  
5. **SaaS-dashboard cards**, фиолетовые градиенты, EN labels — против PO-CANON.

## 9. Критерии приёмки дизайна (PO «показать цеху»)

1. [ ] `/supply` по умолчанию открывает **Быстрый заказ**, не таблицу.  
2. [ ] Chip **«Реестр»** показывает текущую таблицу SupplyTask без регрессии.  
3. [ ] Desk chip **«Снабжение»** → быстрый заказ; tray **«Открыть»** → quick + `orderId` если expand.  
4. [ ] Плитки: summary строка читается без expand (дата, кат, название, qty, статус, приоритет, поставщик).  
5. [ ] Expand показывает **4 блока** полей, не простыню 16 полей.  
6. [ ] **«+ Создать»** → новая плитка развёрнута, focus в «Наименование».  
7. [ ] **«+ Новый» поставщик** — inline, без ухода со страницы (mock OK).  
8. [ ] Статус и приоритет — **dropdown**, цвет приоритета виден в свёрнутой строке.  
9. [ ] Toolbar: поиск + фильтры статус/приоритет + счётчик «N заявок».  
10. [ ] Empty state RU понятен без обучения.  
11. [ ] Light + dark: badge/chip контрастны.  
12. [ ] Сценарий «5 заявок утром → 3 срочных → profrezi.ru → свернул → Реестр» проходится без тупиков (mock data).
