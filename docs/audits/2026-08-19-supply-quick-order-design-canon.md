# Supply Quick Order — design canon (UX audit)

**Дата:** 2026-08-19  
**Источник:** `tasks/PROMPT-SUPPLY-304-quick-order-design.md`  
**Эталон данных:** Excel PO 2026-08-19 (метизы, оснастка, profrezi.ru, Кубаньподшипник)  
**Статус:** **PASS** — готово к `TZ-SUPPLY-304` (mock UI), затем `TZ-SUPPLY-305` (API)

---

## 1. Север (одной фразой)

**«Быстрый заказ»** — это блокнот снабженца: за утро набить десять позиций «что · у кого · сколько · когда · срочно ли» без обхода каталога и организаций, а **«Реестр»** — тот же реестр контроля, куда строки попадают, когда их пора отслеживать по статусам закупки.

---

## 2. IA — навигация, URL, входы

### URL-канон

| URL | Режим | Default |
|-----|--------|---------|
| `/supply` | Быстрый заказ | **да** (redirect/query `view=quick`) |
| `/supply?view=quick` | Быстрый заказ | явный |
| `/supply?view=registry` | Реестр SupplyTask (таблица 301/302) | нет |
| `/supply?view=quick&orderId=` | Быстрый заказ с предзаполненным контекстом заказа | из стола/tray |

Query `orderId` **сохраняется** при переключении Быстрый заказ ↔ Реестр.

### Два режима — зачем одному человеку

| Режим | Когда | Ментальная модель |
|-------|--------|-------------------|
| **Быстрый заказ** | Утро, входящие устные/листовые заявки, срочные дозаказы | «Записная книжка на сегодня» — плотный ввод, expand-in-row |
| **Реестр** | Обзор недели, фильтр «Заказано», сверка с производством, confirm/received | «Журнал исполнения» — таблица, lifecycle SupplyTask |

Не смешивать: быстрый режим **не** показывает колонки confirm/ordered/received actions — только свой статус заявки. Реестр **не** меняет UX создания — «+ Задача» и BOM explode остаются.

### Chip-строки (sticky, сверху вниз)

```
┌─────────────────────────────────────────────────────────────┐
│ [ Закупки ] [ Отгрузка ]     ← group-workspace (как сейчас) │
├─────────────────────────────────────────────────────────────┤
│ [ Быстрый заказ ● ] [ Реестр ]   ← view mode (новое)        │
│  🔍 Поиск…  │ Статус ▾ │ Приоритет ▾ │  12 заявок │ + Создать│
└─────────────────────────────────────────────────────────────┘
```

- **Row A:** `LOGISTICS_SECTION_CHIPS` — без изменений (`Закупки` / `Отгрузка`).
- **Row B:** segmented chips **«Быстрый заказ» | «Реестр»** + toolbar в той же sticky-зоне (dense, как `/desk` tools).
- Default при открытии `/supply` — chip **«Быстрый заказ»** активен.

### Точки входа

| Откуда | Куда | Контекст |
|--------|------|----------|
| Desk workflow chip **«Снабжение»** | `/supply?view=quick` | без orderId |
| Desk tray **«Открыть снабжение»** (`onOpenSupply`) | `/supply?view=quick&orderId={expanded}` | если строка заказа раскрыта |
| Меню **Снабжение** | `/supply` → quick | — |
| Supply chip **«Реестр»** | `/supply?view=registry` | таблица как сейчас |
| Orders hub / deep-link (будущее) | `/supply?view=registry&orderId=` | фильтр реестра (HUB-303, уже есть) |

Flyout `panel=supply` на столе **не** дублирует форму v1 — только navigate наружу (reuse-first: один write-surface на `/supply`).

## 4. Плитка: свёрнута vs развёрнута

### 4.1 Свёрнута (summary row)

Одна строка, слева направо (truncate с ellipsis на длинных):

```
▸  19.08  ·  Оснастка  ·  Цанга ER16  ·  1 шт  ·  [В работе]  ·  🔴 Срочно  ·  profrezi.ru
```

| Элемент | Источник | Примечание |
|---------|----------|------------|
| Дата | `createdAt` или дата строки | `dd.MM.yyyy` |
| Категория | справочник категорий заявки | короткий label |
| Наименование | `title` * | главный якорь |
| Qty + ед. | `qty` + `unit` * | «4 шт» |
| Статус | badge | цвет из EntityStatus (mock: palette) |
| Приоритет | chip/dot | 🔴 urgent / ○ normal / 🟢 low |
| Поставщик | short name | домен или 12 символов |
| Менеджер | supplier contact | короткая фамилия/инициалы; виден в однострочном summary |

\* обязательны для «сохраняемого» черновика (mock: локально).

Клик по строке или ▸ — expand. Отдельная кнопка «Удалить» — только в развёрнутом виде (destructive + confirm).

### 4.2 Развёрнута (форма по блокам)

```
▾  19.08 · Оснастка · Цанга ER16 · …                    [ Удалить ]

┌─ Что заказать ─────────────────────────────────────────────┐
│ Категория ▾ +  Материал ▾ +  Ссылка на товар [https://…]   │
│ Артикул [_______]  Цвет [_______]  Кол-во * [__]  Ед. изм. ▾│
└────────────────────────────────────────────────────────────┘

┌─ Откуда купить ────────────────────────────────────────────┐
│ Поставщик ▾ +  Менеджер ▾ +  Сайт  Почта поставщика       │
│ Почта менеджера                                             │
└────────────────────────────────────────────────────────────┘

┌─ Контекст ─────────────────────────────────────────────────┐
│ Наша компания ▾     Кто просил ▾ или [__________]            │
│ Связь с заказом ▾ (необяз.)   Нужно к [__.__.____]          │
└────────────────────────────────────────────────────────────┘

┌─ Статус и приоритет ───────────────────────────────────────┐
│ Статус ▾            Приоритет ▾                              │
│ Примечание [________________________________ multiline]      │
└────────────────────────────────────────────────────────────┘

▸ Ещё (свернуто по умолчанию)
   Ориентир. цена · Сумма строки · Дата заказа у поставщика · Ответственный
```

**Grid:** на широком экране раскрытая заявка использует 3 смысловые колонки: `Позиция` | `Поставщик` | `Контекст + Статус`; внутри колонок поля выровнены по общей вертикальной сетке. На узком экране — одна колонка. Блоки — Paper & Ink / hairline, **не** карточки SaaS.

**«+ Создать»:** новая плитка вверху списка, `expandedId` = новая, focus в **«Наименование»**, статус default **«В работе»**, приоритет **«Обычный»**, наша компания = текущая org user (mock: первая в списке).

## 7. Связь с Реестром (концепт, без API в 304)

```
Быстрый заказ (SupplyRequest)          Реестр (SupplyTask)
─────────────────────────────          ────────────────────
Черновик «В работе»        ──stay──►  (не виден в реестре)
Статус «Заказано»          ──spawn──►  строка SupplyTask draft/ordered
                                       + link supplyRequestId
С BOM explode (302)        ─────────►  только реестр (как сейчас)
```

**Правило PO для 305:**

1. Пока статус ∈ {В работе, Запрошено} — строка **только** в быстром режиме.
2. При переходе в **«Заказано»** — опционально создаётся `SupplyTask` (или обновляется linked) для реестра; в quick-строке badge «В реестре» + link «Открыть в реестре».
3. Реестр **не удаляется** — audit и order-linked tasks остаются каноном для производства.

Поле `source=excel|manual` — только backend, не в UI.

## 12. Compact strip layout (TZ-SUPPLY-306, PO review 2026-08-19)

PO отклонил рыхлый expand из 304: четыре `pi-dashed-panel p-4` читались как четыре
страницы, а `qty` / `ед. изм.` / короткие select растягивались на колонку грида.
Канон развёрнутой плитки — **полосы, а не панели**.

```
▾ 19.08 · Оснастка · Цанга ER16 · 1 шт · [В работе] · 🔴 · profrezi.ru   [Удалить]
┌─ ПОЗИЦИЯ ──────────────────────────────────────────────────┐
│ Категория▾ +  Материал▾ +  Ссылка на товар····  Кол-во  Ед.│
├─ ПОСТАВЩИК ─────────────────────────────────────────────────┤
│ Поставщик▾ +  Менеджер▾ +  Сайт  Почта поставщика  Почта менеджера │
├─ КОНТЕКСТ ──────────────────────────────────────────────────┤
│ Наша компания▾  Кто просил▾  Связь с заказом····  Нужно к  │
├─ СТАТУС ────────────────────────────────────────────────────┤
│ Статус▾  Приоритет▾  Примечание··························  │
└─────────────────────────────────────────────────────────────┘
▸ Ещё
```

**Правила**

1. **Одна полоса = один блок.** Полосы живут в общем контейнере
   `.supply-quick-order__strips` (hairline + `border-radius: 2px`), делятся
   внутренним hairline; собственных отступов-«карточек» нет. Padding полосы —
   `0.3rem 0.6rem 0.4rem`, gap полей — `0.4rem 0.5rem`.
2. **Заголовок блока — отдельная верхняя строка** (11px uppercase, hairline снизу),
   а поля идут ниже на полной ширине. Это освобождает место для данных и визуально
   разделяет «Позицию», «Поставщика», «Контекст» и «Статус».
3. **Цветовая идентификация** — 2px левый акцент + tint фона, оба через
   `color-mix(... , var(--color-paper-raised))`: `what` = sunrise, `where` =
   info, `ctx` = ink-neutral, `status` = success, `Ещё` = paper-2. Внутри
   `Позиция` подгруппы `Категория` / `Материал` / `Количество`, внутри
   `Поставщик` подгруппы `Поставщик` / `Менеджер`; подгруппы имеют тонкую
   вертикальную границу и слабый tint своего назначения. Одна формула работает
   в light и dark, второй палитры нет.
4. **Ширина поля = содержимое.** `qty` 4.5rem (right-aligned, tabular, без
   спиннеров), `ед. изм.` 5.5rem, `категория` 9rem, `артикул` 7rem, `цвет` 6rem,
   `менеджер` 13rem, `сайт` 12rem, `почта` 14rem; материал / ссылка / примечание
   получают flex-остаток с `min-width: 0`. Визуальный порядок поставщика —
   организация (поставщик, сайт, почта) → контакт (менеджер, почта). Ссылка на
   товар относится к «Позиции», почта менеджера — к контакту, почта поставщика —
   к организации.
5. **Контролы в полосе — 30px** (`height: 1.875rem`, 13px), micro-label 10px
   uppercase над полем.
6. **«Удалить» — в summary-строке справа** (native кнопка, destructive-цвет,
   confirm сохранён). Отдельный ряд над формой запрещён: он крал высоту.
7. **Примечание — одна строка** (`input`, полный текст в `title`), textarea в
   быстром вводе запрещён.
8. **Фото — 1.75rem thumb + «+»** inline в полосе «Что заказать», без панели.
9. **Inline-create** («+ Новая» / «+ Новый») — dashed-панель на всю ширину
   полосы, поля и кнопки в одну строку; логика 304 не менялась.
10. **&lt;900px** — полоса разворачивается в колонку, чип-заголовок уходит
    наверх, длинные поля занимают 100%.

**Мера приёмки:** развёрнутая плитка на 1440px — табличная summary-шапка + 3 смысловые колонки + «Ещё»; поля внутри каждой колонки не прыгают по горизонтали, вертикальный скролл для одной заявки не нужен.

## 13. Финальная сетка и материал (TZ-SUPPLY-309, PO review 2026-08-19)

PO зафиксировал финальный вид развёрнутой заявки: три карточки в одну линию (равная высота),
лёгкие цветовые подложки для различения блоков, компактные 36px инпуты (как `.pi-input`),
зелёные «+». Карточки разделены `gap: 0.75rem`.

```text
┌─ ПОЗИЦИЯ (sunrise-tint) ───────────────────────────────────┐
│ Категория ▾ +   Материал ▾ + ✎ ⧉   Ссылка на товар [https…] │
│ Артикул [6205-2RS]   Цвет ▾ +   Кол-во * [4]   Ед. изм. ▾   │
├─ ПОСТАВЩИК (info-tint) ─────────────────────────────────────┤
│ Организация ▾ +   Сайт   Почта поставщика                    │
│ Контакт ▾ +   Телефон менеджера   Почта менеджера            │
├─ ДЕТАЛИ И СТАТУС (success-tint) ────────────────────────────┤
│ Контекст: Наша компания ▾  Кто просил ▾  Связь  Нужно к      │
│ Статус: Состояние ▾  Приоритет ▾   Примечание [одной строкой] │
└─────────────────────────────────────────────────────────────┘
▸ Ещё
```

**Изменения 309 относительно §12:**

1. **Цвет материала — select, а не readonly.** Рядом с артикулом выпадающий список цветов
