# Канон: таблица позиций в Create КП

**Дата:** 2026-08-09  
**Route:** `/proposals/create` + `/doc-constructor/tables`  
**Статус:** канон после ответов PO (этот чат)  
**Связано:** wave2 preview (`…-preview-wave2.md`) · bind **TZ-SALES-325** · чат *Commercial proposal table settings*

---

## 1. VERDICT (30 сек)

| Слой | Где | Что |
|------|-----|-----|
| **Пресет (рыба колонок)** | Документы → Шаблоны таблиц | Категория **КП** + готовый набор колонок; можно вешать пресеты и на другие категории |
| **Вид этой сделки** | Create КП → правая панель «Таблица» | Порядок / показ столбцов, простые манипуляции; **не** ломает общий пресет |
| **Деньги сделки** | Create КП → «Параметры» | Наценка/скидка фирмы **фоном** → меняет цену на листе; каталог не трогает |
| **НДС / Итого** | Подвал таблицы позиций | Только на **всё КП**; тексты подвала — блоки/лейблы внизу справа |

**Антипаттерн:** второй полный конструктор колонок как в Документах *и* тихая перезапись общего `TableTemplate` из Create.

---

## 2. Решения PO (зафиксировано)

1. **Каждое КП редактируемо** — двигать столбцы (и простые show/hide) можно на Create.  
2. **Скидка по строкам — нет.** Колонки «Скидка %» на бланке нет.  
3. **Скидка/наценка** живёт в панели (от Organization / правка вручную) → пересчёт `unitPrice` **только в КП**. Каталог/`listPrice` не меняются. На печати скидка **не обязана** светиться отдельной строкой.  
4. **НДС** — только на всё КП, внизу таблицы (не столбец).  
5. **Пресет КП** — обязателен автоматически при сценарии Create КП. Пресеты можно назначать и другим категориям таблиц.  
6. **Гибкость без запутанности** — настройки по категориям панелей (Таблица / Параметры), не каша.

Старое дневниковое «структура только в Документах, в Create нельзя» — **снято**. Новое правило: Документы = библиотека пресетов; Create = **экземпляр раскладки** сделки.

---

## 3. Модель данных (смысл)

```text
TableTemplate (shared preset)
  category: kp | product-spec | … 
  columns[{ key, label, type, … }]   ← канон ключей как в TZ-SALES-325

Create KP session / later Quotation
  kpTableLayout: { columns: [{ key, visible, order }] }  ← copy-on-write
  draftLines / items: { product…, quantity, unitPrice }  ← unitPrice уже «после наценки»
  dealVatPercent?: number                                 ← на всё КП
```

- Правка порядка в Create → только `kpTableLayout`.  
- «Править пресет» → deep-link в `/doc-constructor/tables?editId=…`.  
- После Save (successor): layout уходит в snapshot КП вместе с бланком — later, не блокирует MVP preview.

## 4. Пресет колонок КП (default)

| # | key (канон) | label RU | type |
|---|-------------|----------|------|
| 1 | `index` | № | number |
| 2 | `productName` | Наименование | text |
| 3 | `quantity` | Кол-во | number |
| 4 | `unit` | Ед. | text |
| 5 | `unitPrice` | Цена | currency |
| 6 | `sum` | Сумма | currency |

Bind строк уже по aliases **325**. Ключ `index` = порядковый номер строки в превью (1…n), не из каталога.

Подвал (отдельный слой, не колонка):

- «Итого» = Σ сумм строк (после наценки).  
- «в т.ч. НДС …%» / сумма НДС — от `dealVatPercent` на всё КП.  
- Тексты формулировок PO может позже заменить текстовыми блоками; MVP = фиксированные RU лейблы в правом нижнем углу таблицы позиций.

## 5. Где живёт UI

### A. Документы → Таблицы

- Тип/категория **«КП»** в enum.  
- Кнопка/действие **«Пресет колонок»** для категории (КП и др.) — вставляет default set, порядок можно править в диалоге таблицы.  
- Одна системная/seed запись «КП — позиции» (или эквивалент) с ключами выше.

### B. Create КП → правый rail

Секции (логика, не обязательно отдельные icon-кнопки сразу):

| Секция | Содержимое |
|--------|------------|
| **Параметры** (уже есть) | Organization, наценка %, оценка; later клиент |
| **Таблица** (новое) | Список столбцов экземпляра: ↑↓, показать/скрыть; ссылка «Пресет в Документах» |

Идентичность панели: всё про геометрию таблицы — в «Таблица»; всё про деньги сделки без колонок — в «Параметры».

### C. Авто при Create

При выборе шаблона документа / первом build:

1. Найти target line-items table (**325**: `kpLineItems` / одна live table).  
2. Скопировать columns пресета/шаблона → `kpTableLayout`.  
3. Если нет обязательных ключей (`productName` + `quantity` + `unitPrice`/`sum`) — **долить** из default пресета КП в экземпляр (не PATCH shared template).  
4. Дальше менеджер двигает только экземпляр.

## 7. Волна исполнения

| ID | Scope |
|----|--------|
| **TZ-DOC-TABLES-307** | Category `kp` + seed «КП — позиции» + apply-preset в диалоге таблиц |
| **TZ-SALES-330** | Create: `kpTableLayout` + панель «Таблица» + build уважает порядок/visible |
| **TZ-SALES-331** | Наценка → цена на листе; VAT %; footer Итого/НДС |

**Не в этой волне:** Save/snapshot layout (**322** зона), печать **320**, скидка-колонка, per-line VAT, BuilderCanvas rewrite.

## 8. Риски

1. Путаница «поправил в Create → пропало у всех» — лечится copy-on-write + явная ссылка на пресет.  
2. Два UI колонок (диалог таблиц vs Create) — разный scope: shared vs instance; копирайт обязан говорить это.  
3. Footer в `preview()` затронет admin preview таблиц — footer только если передан deal-context / line-items target.  
4. `index` без aliases в 325 — добавить в map при 330/331.  
5. CONFLICT: `document-template.service.ts` / `table-template.*` / `proposal-create*` — не параллелить слепо с DOC-343 / DOC-TABLES-305.
