**Источник:** диктовка PO (после «проверки связи»): файл `6104 test Tigran с картинками (1).xlsx` из выгрузки CAD/PDM; жалобы на «колонка 3, 4, 5», английские названия в выпадающем списке и непонятную кнопку «Предложить через ИИ».

## Вердикт

Студия импорта по структуре верная (TZD-36→38), но на реальном файле из CAD/PDM вылезли
два настоящих бага (заголовки и запись состава) и два UX-провала (подписи полей и кнопка ИИ).
Все исправлено в этом проходе; остались осознанные follow-up (имена модулей в выгрузке,
dimensions/weight, editing в превью).

## Найденные баги (исправлено)

| # | Критичность | Баг | Где | Исправление |
|---|-------------|-----|-----|-------------|
| B1 | **Высокая** | Строка заголовков = первая непустая строка листа. Файлы CAD/PDM начинаются с «шапки» документа (ПРЕДВАРИТЕЛЬНЫЙ ПРОСМОТР / Таблица спецификаций), настоящие заголовки — во 2-й строке → колонки получали имена `колонка_3…11`, маппинг не подбирался вообще | `importers/excel.ts` | `findHeaderRow()`: среди первых 10 непустых строк берём первую с числом непустых ячеек ≥ половины максимума (мин. 2). Шапка-заголовок (1–2 ячейки) пропускается. Fallback пустых заголовков — `Колонка N` |
| B2 | **Высокая** | Родитель, выведенный из уровней («1» → «1.1»), сохранялся только на узлах дерева. `confirmSpecification` читает `preview.lines`, где `parentArticle` = null → состав «подтверждался» с **0 связей** (сущности создаются, состав нет) | `core/specification-import.ts` | После сборки дерева синхронизируем выведенный `parentArticle` обратно в `lines` (flatten по article) |
| B3 | Средняя | Опции выпадающего списка — голые английские `article/name/unit…` | `App.svelte` + `core/import-mapping.ts` | `CANONICAL_LABELS` + `canonicalLabel()`: «Артикул (article)», «Наименование (name)», «Ед. изм. (unit)», «Кол-во (qty)», «Код (sku)», «Примечание (notes)», «Категория (categoryId)» |
| B4 | Средняя | Кнопка «Предложить через ИИ» молча `disabled`, если MCP-хост не запущен; результат/ошибка (`mappingMessage`) вообще не выводились в панели сопоставления | `App.svelte` | Кнопка всегда доступна в шаге сопоставления: классификатор локальный и детерминированный — работает без MCP (при запущенном MCP используем его вариант по образцу строк). Сообщение о результате показывается в панели. Подсказка объясняет, как подключить LM Studio/MCP (вкладка MCP) |
| B5 | Средняя | Алиасы не покрывали заголовки CAD/PDM | `core/specification-import.ts`, `core/import-mapping.ts` | `позиция`→level, `к-во`→qty, `вид изделия`→kind, `сортамент`→name, `деталь`→material. «Материал» НЕ алиас имени в спецификации (это марка стали); в плоском маппинге остаётся |
| B6 | Средняя | Позиционные номера «1», «1.1», «1.2» не парсились как уровни (`Number('1.1')` → 0) | `core/specification-import.ts` | Режим «позиционная нотация» по файлу: если хоть одна ячейка уровня содержит точку — уровень = число сегментов − 1 («1» → 0, «1.1» → 1); обычные целые уровни (0,1,2) не тронуты |
| B7 | Низкая | Корень спецификации разрешал только `product`; в выгрузках CAD изделие часто не перечислено, корень — модуль → 83 `invalid_root` | `core/specification-import.ts` | Корень: `product` **или** `module` (материал корнем по-прежнему нельзя) |
| B8 | Низкая | Список issues в превью спецификации выводился целиком (на файле PO — 83 строки) | `App.svelte` | Показываем первые 12 + «…и ещё N» |

## Проверено

- Новые юнит-тесты: `desktop/src/importers/excel.test.ts` (шапка-заголовок, обычный файл, fallback), `desktop/src/core/import-mapping.test.ts` (подписи, CAD-заголовки, конфликты), доп. кейсы в `desktop/src/core/specification-import.test.ts` (позиции, корни-модули, целые уровни, родитель в lines). **27/27 PASS**.
- `tsc --noEmit` и `svelte-check`: 0 ошибок; `vite build` OK.
- Реальный файл `6104 test Tigran с картинками (1).xlsx` (копия, `data/products/`): заголовки `Позиция / Обозначение / Длина / Ширина / Толщина / Масса / Сортамент, ГОСТ / Материал / Вид изделия / К-во`; маппинг: Обозначение→Артикул, К-во→Кол-во, Материал→Наименование; спецификация: 144 строки, 83 корня-модуля, детали получают имя из «Сортамент, ГОСТ», родители синхронизированы (`0000.0001.0001 ← 0000.0001.0000`).

## Что осталось (follow-up, вне этого прохода)

1. **Имена модулей в выгрузке отсутствуют** — в файле PO у корней «Сортамент, ГОСТ» и «Материал» пустые → `missing_name` (83) блокирует подтверждение. `name` в бэкенде обязателен (`create-product-module.dto`). Нужно либо editing имён в превью спецификации, либо мягкий fallback «имя = артикул» с явной пометкой, либо отдельный источник имён (справочник изделий CAD).
2. **Колонки размеров/веса игнорируются** — «Длина/Ширина/Толщина/Масса» не мапятся; DTO модуля уже поддерживает `dimensions {width,height,depth,unit}` и `weight` → следующий шаг: сопоставление габаритов при создании модулей.
3. **Кнопка «Предложить сопоставление» пока детерминированная** — модуль `desktop/src/core/ai/` (Ollama/OpenAI-совместимый чат) заготовлен, но не подключён. «Умное» предложение карты через локальную модель (LM Studio/Ollama) — отдельная TZ (TODO(ai-import) в `core/pipeline.ts`).
4. **Плоский маппинг для иерархических файлов** — колонки габаритов остаются красными «Нужно проверить» (нет канонического поля); для чистоты можно авто-игнорировать их, когда файл идёт по пути спецификации.
