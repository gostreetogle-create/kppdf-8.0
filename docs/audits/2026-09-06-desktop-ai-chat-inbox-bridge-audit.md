# Аудит 2026-09-06 — Desktop: чат ИИ ≠ папка импорта

PO скрин: `docs/audits/evidence-desktop-ai/2026-09-06-chat-half-height.png`  
Контекст: локальный OpenAI-совместимый сервер (напр. `:1234`) отвечает в чате; модель говорит «файлов не вижу»; PO ждал связь с Inbox / импортом; красный крест — пустое место под чатом.

## Preflight

- **Context read:** `desktop/docs/AI-PROVIDERS.md`, `desktop/docs/MCP.md`, `desktop/src/ChatPanel.svelte`, `desktop/src/core/ai/prompts.ts`, `desktop/src/core/inbox.ts`, `docs/PO-CANON.md`
- **Key Constraints:** HITL; chat = LIMITED_HELPER (не пишет в БД); MCP write — для Cursor, не для ChatPanel
- **Deliverable:** диагноз + TZ TZD-77 (layout + read-only bridge)
- **Validation:** PO глазом после 0.5.9

## Диагноз (не баг сервера)

Сейчас **три разных контура**:

| Контур | Где | Что умеет |
|--------|-----|-----------|
| **Импорт + Inbox** | вкладка «Импорт» | Папка `%APPDATA%/…/kppdf-desktop/inbox` (или выбранная). Файлы → разбор → сопоставление колонок → подтверждение → API. Кнопка «Открыть папку Inbox». |
| **Чат** | вкладка «ИИ» | Только текст ↔ LLM (`ChatPanel` + system prompt LIMITED_HELPER). **Нет** tools, **нет** чтения диска, **нет** списка Inbox. |
| **MCP** | вкладка «ИИ» (для Cursor/агентов) | Внешний клиент вызывает ERP tools по pairing. **Не** подключен к встроенному чату. |

Поэтому ответ модели «не вижу файлы» — **честный**: ей в контекст ничего из Inbox не передаётся.  
«Предложить сопоставление» на вкладке Импорт — отдельная кнопка (через MCP/раннер), это **не** чат.

Путь Inbox по умолчанию: `appDataDir()/inbox` (`resolveInboxDir` / `defaultInboxDir` в `desktop/src/core/inbox.ts`). Открывается с вкладки **Импорт**, не из чата.

## UX-запах

1. Чат занимает ~половину правой колонки — внизу пусто (скрин PO).  
2. Нет пояснения на экране ИИ: «чат не видит Inbox, пока не прикрепим».  
3. Ожидание PO: польза = видеть файлы агента и помогать с полями — **ещё не сделано**.

## Решение (принятое Cursor)

**Не** обещать «чат сам заливает в базу». HITL остаётся на Импорте.

**TZD-77 (Claude, Desktop):**  
1) Растянуть чат на доступную высоту.  
2) На вкладке ИИ — компактная строка Inbox: путь / N файлов / «Открыть папку».  
3) В контекст чата (system или prepend) — read-only снимок: список имён файлов Inbox + при выбранном файле краткий audit (заголовки/лист), без write.  
4) Копирайт: «Чат подсказывает; запись в базу — только после подтверждения на вкладке Импорт».

**Позже (PARK TZD-78):** кнопка «Прикрепить файл из Inbox» → предложение mapping → открыть Импорт на шаге подтверждения (без silent write).

## Не делать

- Автозапись из чата в Mongo.  
- Путать MCP Cursor с ChatPanel.  
- Возвращать сломанный GGUF-runner UI (TZD-76 отдельно).

## Resolution (2026-09-06, Claude, TZD-77-AI-CHAT-INBOX-BRIDGE)

**DONE**, версия **0.5.9**. Layout: `.ai-chat-card--tall` (`grid-row: 1 / -1`) заставляет
карточку «Чат» занимать всю высоту правой колонки грида вместо одной строки — пустая ячейка
с этого скрина (`evidence-desktop-ai/2026-09-06-chat-half-height.png`) закрыта; внутри
`ChatPanel` лента сообщений теперь `flex:1`, input прижат вниз (`margin-top:auto`).

Inbox на вкладке «ИИ»: компактная строка (путь/N файлов/«Открыть папку»), переиспользует уже
существующий живой `inboxDir`/`inboxFiles` (fs-watcher с вкладки «Импорт», без дублирования).

Read-only bridge: `desktopChatContextPrompt` ($derived в App.svelte) добавляет к системному
промпту снимок Inbox (имена/размер/mtime, до 20 файлов) перед каждым запросом к модели —
чистая строковая конкатенация, без чтения содержимого файлов и без сетевых вызовов. Промпт
(`desktop-chat.md` + fallback `prompts.ts`) явно говорит: список даёт Desktop, это
единственные видимые файлы, запись в базу невозможна — предложить «Импорт».

`ChatPanel.svelte` логически не менялся (только CSS) — LIMITED_HELPER (нет write-пути из чата)
подтверждён. Gates (tsc/svelte-check/tsx --test) PASS, идентично baseline. HEAD `:3000` 200 с
новым zip. Визуальная проверка (PO) — на следующем запуске Desktop.
