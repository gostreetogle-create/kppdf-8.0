# Audit — studio right chrome-rail: одиночные action vs категории (2026-09-12)

## PO

Обвёл верх rail: карандаш / глаз / save / PDF / архив. «Кнопки для открытия меню, а не по одной action». Одна иконка = одно действие — трата места. Нужны **категории**: клик → меню с несколькими кнопками внутри.

## Факт сейчас (C3)

Правый rail = **10** плоских `ShellToolRailItem` с `onClick`:

| id | Роль | Тип |
|----|------|-----|
| mode-editor, mode-preview | режим | **action/toggle** (не меню) |
| save, pdf, archive | lifecycle | **action** |
| elements, layers, pages, properties, template | панели | **категория → flyout** (ок) |

API `ShellToolRailItem` **не умеет** children/menu — только immediate click.

Левый rail (Данные / Выбрано) — уже категории-панели, не трогать без нужды.

## Целевая IA (PO)

1. **Одна** категория на lifecycle, напр. «Документ» / «Файл» (иконка File / Pen):  
   внутри меню ≥2 пункта: Редактор · Просмотр · Сохранить · PDF · В архив (все, что сейчас сверху).  
   Active: режим editor/preview подсвечивает категорию и/или пункт меню.  
2. Панельные категории **оставить** отдельными кнопками rail (Элементы…Шаблон) — они уже открывают меню/flyout с содержимым.  
3. **Запрет:** rail-слот с ровно одним action и без подменю (кроме редкого global — здесь не нужно).

## Проверка смысла кнопок

| Действие | Нужно? | Note |
|----------|--------|------|
| Редактор / Просмотр | да | режимы листа |
| Сохранить | да | |
| PDF | да | |
| В архив | да | draft only |
| Элементы…Шаблон | да | flyout панели |

Лишних «пустых» lifecycle нет; проблема — **раскладка**, не набор.
