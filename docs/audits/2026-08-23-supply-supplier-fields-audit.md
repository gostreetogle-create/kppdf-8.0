# Аудит: блок «Поставщик» в быстром заказе (2026-08-23)

> Для PO. Без жаргона. Что уже задумано, что ломается, что чиним в TZ-SUPPLY-317.

## Как должно быть (ваша логика — верная)

| Поле | Чьё это | При выборе поставщика | При правке |
|------|---------|----------------------|------------|
| Организация | справочник поставщиков | выбираете карточку | — |
| Сайт | **карточка поставщика** | подставить, если есть | писать = править поставщика |
| Почта поставщика | **карточка поставщика** | подставить, если есть | писать = править поставщика |
| Контакт | люди у поставщика | список только его менеджеров; если один — взять его | — |
| Телефон / почта менеджера | **карточка человека** | подставить с контакта | писать = править человека |
| Ссылка на товар (в Позиции) | **эта строка заказа** | не трогать | только в заявке, не у поставщика |

Кнопки «Сохранить» в блоке нет **намеренно**: правка должна уходить в справочник сама. Сейчас это неочевидно и частично ломается.

## Что видно на скрине («Лакокраска-Сервис» выбрана, сайт/почта пустые)

1. Поля **уже привязаны** к поставщику: пусто = в карточке организации сайт/почта пустые (или список ещё не подтянул живые данные). Это не «поля строки», а окно в карточку.
2. Ввод сайт/почта **должен** сохраняться у поставщика (`PATCH` организации). На каждое нажатие клавиши — слишком рано; невалидная почта посреди набора (`a@`) сервер отвергает **молча** → кажется, что «ничего не сохраняется».
3. Нет подписи «сохраняется у поставщика» / «сохранено» — поэтому непонятно, нужна ли кнопка.

## Связки (проверка кода)

| Связь | Статус |
|-------|--------|
| Выбор поставщика → сайт/почта из каталога | OK, если в API у org есть поля |
| Выбор поставщика → контакты с API | OK (`listContacts`) |
| 1 контакт → автовыбор | OK |
| Правка сайт/почта → Organization | Задумано OK, UX/валидация сломаны |
| Правка тел/почта менеджера → Person | Задумано OK, тот же риск silent fail |
| Ссылка на товар → только строка заявки | OK, не путать с сайтом поставщика |
| Материал ↔ категория | Отдельно (SUPPLY-316) |

## Чиним в TZ-SUPPLY-317

- Сохранение сайт/почта (и менеджера) **по blur + debounce**, не на каждый символ.
- Пустая строка не валит API; ошибка сохранения **видна**; при ошибке откат значения.
- При выборе поставщика — догрузить карточку, если сайт/почта ещё не в памяти.
- Короткая подпись у полей: что это правка поставщика / менеджера, без отдельной кнопки «Сохранить» (autosave по blur).
- Тесты на autofill + persist + ошибку email.

Data-fix (проставить сайт/почту у «Лакокраска» в справочнике) — не этот TZ; после фикса пустые поля = реально пустая карточка.
