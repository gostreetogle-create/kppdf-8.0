# NX Студия документов — план объединения (SoT переноса)

> **Статус:** PLAN v1 (2026-08-30), автор Cursor Mode A. Решение PO: это **модуль №1** переноса на NX.
> Дополняет, не отменяет: `docs/architecture/document-studio.md` (ADR legacy, ACCEPTED v1.2),
> `docs/pages/kp-workspace-geometry.md` (закон геометрии), `docs/architecture/document-studio-data-anchors.md`.
> Реализация — только по TZ из § 6. Этот файл — карта, не разрешение кодить.

## 1. Что просил PO

Одна универсальная страница, где оператор создаёт документ любого типа (КП, договор, акт, паспорт изделия):
вставить текст → легко перемещать и править; вставить таблицу → легко перемещать, **подключить к нашим данным**
с выбором полей, настроить колонки **на ходу** и **сохранить настроенный вид** под именем; несколько страниц с
фонами и контролем переноса строк таблицы; сохранить документ как шаблон и потом выбирать шаблон из списка с
автоподстановкой позиций из каталога, заказчика, поставщика. Лист A4 переключается книжный/альбомный, и **меню
не должны сужать лист** — они сверху и по бокам поверх плоскости.

Правило PO: **модуль диктует таблицы**, новая таблица входит через реестр `/registries`, потом подключается к модулю.

## 2. Ключевой факт: это уже почти построено — трижды

В legacy три поверхности решали одну задачу и каждая недоделана:

| **Builder (шаблоны)** | `/doc-constructor/builder/:id` | размер листа, ориентация, **поля страницы** (`builder-inspector.component.ts:207-229,354-382`), палитра вставки, drag/resize, snap-engine | страница зажата на 1 (`docs/pages/builder.page.md:68-69`), нет PDF, нет ротации в инспекторе при наличии её в модели |
| **КП Workspace** | `/proposals/workspace` | наследование организации/контрагента/НДС, таблица позиций с пересчётом, печать/PDF/архив, эталон геометрии | геометрию править нельзя — уводит в Builder через `returnUrl`; нет «сохранить это КП как шаблон» |

ADR legacy (`document-studio.md` § 8) уже объявил «single-page law»: редактор без navigate на texts/tables/builder.
Waves 0–19 закрыты. **Мы не изобретаем платформу — мы собираем одну поверхность из трёх и добиваем три дыры.**

## 4. Backend: минимальная дельта

**Новых коллекций — ноль.** Только добавочные поля и один резолвер.

| # | Что | Где | Зачем именно для этого модуля |
|---|---|---|---|
| D1 | `style { fontFamily, fontSizePt, color, align, lineHeight, bold }` | новое поле на `template_blocks` | Панель шрифтов PO. Сегодня типографика существует только внутри TipTap-HTML, а серверный рендер жёстко прибит к `Times New Roman` (`document-render.service.ts:82`) — то есть выбранный шрифт не доживает до PDF. Блочные поля дают рендеру CSS без разбора HTML; исключения внутри абзаца остаются в HTML. |
| D2 | `pageMargins { top, right, bottom, left }` | добавочно на `document_templates` и `studio_documents` | Поля страницы сегодня живут только в UI Builder и не персистятся; рендер использует `@page{margin:0}` + `padding:20px` (`document-render.service.ts:79,231`). Без этого лист в PDF не совпадёт с экраном. |
| D3 | `dataSets[].source.type += 'catalog-products'` + резолвер строк | `studio-data-resolver.ts` | PO хочет набирать позиции **из каталога**, а не только из готового КП/заказа. В legacy это отложено как Wave 8 (`document-studio.md` § MVP delivered → «catalog-products live» deferred). Схема не меняется — только новый источник строк. |
| D4 | Снос `document_table_types` | `backend/src/modules/document-table-type/**` | Коллекция-сирота: зарегистрирована в `app.module.ts:250`, потребителей вне своего модуля нет, с `table_templates` не связана (`table-template.schema.ts:12-15`). Дублирует «виды таблиц» и путает. **Решение PO:** сносим / оставляем. |

Каждый пункт D1–D3 — отдельная backend-TZ, выдаётся **только** когда до него дошёл срез из § 6. Заранее не добавляем.

## 5. Геометрия единой страницы (главный ответ на «меню не должны сужать лист»)

Закон `docs/pages/kp-workspace-geometry.md` действует целиком. Прикладываем к новой странице:

- **Центр — плоскость с листом.** Книжный: height-first ~95% заполнения, выравнивание `flex-end`, ~8px от правого края. Альбомный: width-first на всю доступную ширину минус 8px, **то же** выравнивание. Лист не двигается ради «зазора под меню».
- **Панели — overlay.** `position: absolute` поверх плоскости, ширина **480px** фиксированно (книжный = альбомный), контент внутри `max-width: 272px`. Открытие/закрытие панели **не меняет** прямоугольник листа: Δ width/height/right ≤ 0.5px в обеих ориентациях. Запрещено «если панель открыта — уменьшить лист».
- **Рельсы — иконки.** Левый и правый `4rem` рельс в оболочке NX уже размечены (`app-shell.component.ts`, `tool-rail-definitions.ts`) — сегодня все кнопки заглушки. В альбомном рельсы **остаются по бокам**, горизонтальная полоса — только мобильный `<lg`.
- **Ribbon не крадёт высоту** плоскости: тонкая полоса overlay в углу листа.
- **Типографика — плавающий контекстный тулбар** над выделенным блоком (как мини-панель в Word), а не постоянная боковая панель. Причина прямо из требования PO: в альбомном режиме постоянная панель шрифтов либо сужает лист, либо перекрывает его половину. Тулбар появляется по выделению и исчезает по снятию.

### Раскладка панелей

| Рельс | Раздел | Содержимое | Откуда взято |
|---|---|---|---|
| Левый | **Элементы** | вставка: текст, таблица, изображение, подпись, разделитель | Studio rail «Элементы» + палитра вставки Builder |
| Левый | **Слои** | порядок (z), блокировка, видимость, фильтр по странице, выбор блока | Studio rail «Слои» + `isActive` из инспектора Builder |
| Левый | **Страницы** | добавить/удалить страницу, фон по странице, нумерация, размер листа, ориентация, поля страницы, правило переноса строк | Builder (размер/ориентация/поля) + Studio (страницы/фон) — **впервые в одном месте** |
| Левый | **Данные** | наша организация, заказчик, поставщик, связанное КП/заказ; автоподстановка в поля | Studio rail «Данные» + наследование КП Workspace |
| Правый | **Свойства** | геометрия x/y/w/h/z, поворот, блокировка, удаление — **редактируемые**, не read-only | Studio «Свойства» (снимаем read-only) + drag/resize Builder |
| Правый | **Таблица** | колонки на ходу, источник строк, пересчёт итогов, «Сохранить как вид таблицы», применить сохранённый вид | Studio rail «Таблица» + табличный редактор КП + `table_templates` |
| Правый | **Текст** | «Сохранить как текстовый блок», вставить сохранённый текст | `/doc-constructor/texts` втягивается внутрь страницы |
| Ribbon | — | Редактор \| Просмотр · PDF · В архив · нумерация страниц | Studio ribbon + гейты вывода КП |
| Контекст | **Тулбар типографики** | шрифт, размер, жирный/курсив, цвет, выравнивание, межстрочный | новое (дыра всех трёх экранов) |

Ориентация переключается **на этой странице**: закон п.6 отправлял её в редактор шаблона Builder, но Builder втягивается
внутрь единой поверхности, поэтому контрол переезжает в панель «Страницы». Это осознанное уточнение закона по прямому
указанию PO, а не молчаливая правка раскладки — фиксируется здесь и в `kp-workspace-geometry.md` при первом срезе,
который меняет ориентацию.

## 7. Что НЕ входит

- Ctrl+Z и история версий блока (осознанно вне MVP, как в legacy ADR § Not in MVP).
- Перезапись при конфликте ревизий: только «Обновить» и «Сохранить копию».
- Правка legacy `frontend/**`: старые Studio/Builder/КП живут до отдельного kill-plan PO.
- Импорт PDF в блоки, редактор формул, совместное редактирование, offline.
- Проектирование склада (решение PO: один склад с разделами — отдельный модуль).
- Новые коллекции. Любая появившаяся таблица сначала входит в `/registries` (правило PO), потом в модуль.

## 8. Риски

- **PDF держится на одном пути** — puppeteer-core с managed lifecycle (`quotation-output.service.ts:57-87`). Второго пути нет; падение = нет вывода.
- **`DocumentTemplateService` — god-object**, render-extract сделан поверхностно (`tasks/_backlog/doc-studio/TZ-DOC-STUDIO-2006-render-extract-phase2.md`). Новые срезы **не должны** добавлять логику в него.
- **`template_blocks` dual-read cutover, шаги 5–6 не закрыты** (`document-studio.md` § 7). Пишем блоки только через `parentType`/`parentId`; `templateId: null` не писать — поле опускать.
- **Расхождение docs ↔ код** в legacy: `document-studio-generated-document-migration.md` утверждает «схема не менялась», хотя `sourceType: 'studio'` и `studioDocumentId` уже в коллекции. Не опираться на этот файл.
