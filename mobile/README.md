# KPPDF Mobile (Android) — пожелания на будущее

> **Статус: DRAFT.** Это не реализация, а зафиксированные пожелания.
> **Не начинать без отдельного TZ.** Никакого кода здесь нет.

---

## Идея

Android-приложение, которое ставится **с флешки (side-load APK)** — без Google Play.
Подключается к **тому же backend**, что веб и десктоп: работа с телефона =
наполнение тех же данных (товары, материалы, контрагенты, заказы).

Единый backend (multi-device): веб для офиса, десктоп для массового ввода,
телефон для быстрых операций «в поле».

## Предлагаемый стек (варианты)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Capacitor + Ionic (рекомендуется)** | Переиспользование web-стека (TS + Angular уже в проекте), один код на веб/десктоп/мобайл, простой side-load APK, быстрый старт | Не «нативный» UI, производительность чуть ниже нативных |
| Flutter | Отличная производительность, единый код (Dart) | Новый язык в проекте, дублирование бизнес-логики с TS-бэкендом |

**Рекомендация: Capacitor/Ionic** — потому что kppdf уже Angular+TS: переиспользуем
компоненты, сервисы и типы; команде не нужно учить Dart; side-load APK тривиален.

## Фичи (пожелания)

- **Паринг по QR** (вместо копипаста десктопа): веб показывает QR, телефон сканирует → тот же JSON-пакет, что в [desktop/docs/PAIRING.md](../desktop/docs/PAIRING.md).
- **Оффлайн-очередь**: телефон без сети копит изменения, отправляет батчем при появлении связи (per-row Idempotency-Key — безопасные повторы).
- **Push-уведомления**: подтверждения, уведомления о заказах/документах (если выбран Capacitor — плагин push; нужен сервер уведомлений).

## Ограничения / вопросы на будущий TZ

- Side-load APK: подпись, обновления (прямая установка новой версии), версионирование.
- Безопасность: хранилище токена (Android Keystore), биометрия для входа.
- Какие экраны в первой версии: только ввод или ещё просмотр/поиск?
