# Канонический контракт совместной работы

Версия: `1.0-public`.

Это единый источник истины по ролям, handoff, ownership файлов, review и остановке цикла.

## Порядок authority

1. Актуальная прямая команда владельца продукта.
2. `AGENTS.md`.
3. Этот контракт.
4. Роль-специфичные инструкции.
5. Активные Project Review-файлы.
6. Архив и исторические записи.

## Роли

### Владелец продукта

Определяет бизнес-смысл, критические инварианты, приоритеты и отдельно разрешает production, данные, деньги, роли и необратимые действия.

### Codex

Главный архитектор, исполнитель и интегратор. Проверяет рекомендации, владеет итоговым diff, принимает commits агентов, выполняет финальную приёмку и готовит release.

### Claude Code

Независимый reviewer по умолчанию. Исполнитель только по exact bounded task. Не принимает собственный commit.

### Zcode

Третий ограниченный агент для непересекающегося направления. Не получает общего доступа ко всему проекту и не интегрирует себя самостоятельно.

## Владение файлами

| Артефакт | Владелец |
|---|---|
| `current-task.md` | Codex |
| `recommendations.md`, `recommendations_REV-*.md`, `review-log.md` | независимый reviewer |
| `implemented.md` | Codex |
| `agent-task.md` | назначенный executor; Codex сбрасывает после приёмки |
| runtime-файлы | один агент в один момент времени |

## Рабочий цикл

1. Codex фиксирует одну задачу, baseline, scope, ownership и acceptance.
2. Реализация выполняется одним агентом либо делится только на независимые файлы/контуры.
3. Каждый executor создаёт один локальный commit с собственным префиксом.
4. Codex читает exact diff, выполняет проверки и фиксирует решение.
5. Независимый reviewer проверяет код и доказательства, а не отчёт автора.
6. Подтверждённые дефекты исправляются минимальным diff и проходят повторную verification.
7. После reviewer pass Codex выполняет собственную финальную приёмку.
8. Deploy — отдельное решение, не автоматическое продолжение цикла.

## Worktree и ветки

- По умолчанию используйте закоммиченные handoff-точки.
- Параллельный worktree допустим только при непересекающемся scope.
- До создания фиксируются владелец, путь, base, branch, allowed paths и условие удаления.
- Ветки: `codex/<task>`, `claude/<task>`, `zcode/<task>`.
- После handoff исполнитель не меняет branch history и не делает merge/rebase/push.

## Finding и доказательства

Finding содержит:

- ID и приоритет;
- файл/строки или воспроизводимый сценарий;
- фактическое доказательство;
- пользовательский или технический риск;
- минимальную рекомендацию;
- проверяемый критерий приёмки.

Рекомендация без доказательства — наблюдение, а не задача на изменение.

## Остановка цикла

Цикл завершается, когда:

- нет открытых критических findings;
- acceptance текущей задачи доказан;
- diff не вышел за scope;
- нет непроверенного runtime;
- reviewer не проверял собственную работу;
- Codex выполнил финальную приёмку.

Новая независимая находка после закрытия становится новой задачей, а не бесконечным продолжением старой.
