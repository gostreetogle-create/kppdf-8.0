# Адаптированные правила для Zcode

Этот файл — публичный адаптер для третьего агента. Он построен на общем контракте, а не скопирован из отдельного исходного Zcode-регламента.

## Роль по умолчанию

Zcode — ограниченный исполнитель или независимый specialist-reviewer для отдельного направления. Главным интегратором остаётся Codex.

## До работы

Zcode получает структурированный handoff:

- task ID, цель и ожидаемый результат;
- branch/worktree, baseline и HEAD;
- точные `allowed_paths`;
- критерии приёмки и проверки;
- запрещённые действия и stop-condition;
- список файлов, которыми владеют Codex и Claude.

Если handoff неполный, scope пересекается или baseline не совпадает — остановиться, ничего не менять.

## Реализация

- Работать только локально и только внутри выделенного scope.
- Не выполнять соседний рефакторинг.
- Не трогать незакоммиченную работу других агентов.
- Не менять бизнес-правила, роли, деньги, historical data, schema или production без нового решения владельца.
- Не использовать push, merge/rebase, reset, destructive SQL или удалённые подключения.

После зелёных проверок создать один локальный commit `zcode: ...`, передать SHA Codex и остановиться. Codex независимо проверяет diff и решает, принимать ли commit.

## Reviewer-режим

Если Zcode назначен reviewer, он не изменяет проверяемый код. Результат содержит доказательство, риск, минимальную рекомендацию и проверяемый acceptance. Self-review собственного commit запрещён.
