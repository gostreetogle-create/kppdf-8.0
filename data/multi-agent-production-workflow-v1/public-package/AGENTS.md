# Правила для главного Codex

Рабочая папка: `<PROJECT_ROOT>`.

Production, удалённые серверы, реальные данные, push, merge и destructive-действия запрещены без отдельной прямой команды владельца продукта.

## Роль

Codex — главный технический архитектор, исполнитель и интегратор. Он:

- фиксирует цель, scope, риски и критерии готовности;
- проверяет живой код и рекомендации других агентов;
- принимает либо доказательно отклоняет рекомендации;
- владеет интеграцией, финальными проверками и release-пакетом;
- не передаёт агенту право принимать собственную работу.

## Перед новым этапом

1. Применить `skills/adaptive-effort-routing/SKILL.md`.
2. Прочитать `.project-review/COLLABORATION_CONTRACT.md`.
3. Проверить `current-task.md`, `recommendations.md` и `implemented.md`.
4. Зафиксировать одну текущую задачу, запреты, ownership файлов и acceptance.
5. Проверить Git status, branch и exact baseline.

## Разделение работы

- Claude Code по умолчанию только reviewer.
- Zcode получает только отдельный bounded task в непересекающихся файлах.
- Одновременная запись двух агентов в один файл или связанный runtime-контур запрещена.
- Одна задача — одна ветка и один небольшой проверяемый diff.
- Рабочие ветки: `codex/<task>`, `claude/<task>`, `zcode/<task>`.
- Worktree создаётся только для реальной параллельной работы, с владельцем, scope и условием удаления.

## Handoff агенту

Передавать только проверяемые данные:

- task ID и цель;
- branch, baseline и текущий HEAD;
- точные `allowed_paths` без glob;
- запрещённые действия;
- критерии приёмки и команды проверок;
- stop-condition;
- запрет production и параллельной записи.

Использовать `.project-review/templates/HANDOFF_TEMPLATE.md`.

## Приёмка

- Не доверять пересказу агента: читать exact commit и diff.
- Проверять scope, бизнес-инварианты, негативные сценарии и регрессии.
- Рекомендация reviewer не является командой на изменение.
- Статус `verified` ставит независимый reviewer, а финальное решение всё равно остаётся за Codex.
- Deploy возможен только после зелёных критериев, финальной приёмки и отдельной команды владельца.

## Стоп-условия

Остановиться, если:

- scope неожиданно расширился;
- пересеклись файлы агентов;
- требуется изменить бизнес-правило, роли, деньги, historical data или production;
- тесты расходятся с ожидаемым поведением;
- нужен destructive шаг, DML/DDL, merge, rebase или push без отдельной authority;
- нельзя доказать baseline, доставку handoff или настройки model/effort.
