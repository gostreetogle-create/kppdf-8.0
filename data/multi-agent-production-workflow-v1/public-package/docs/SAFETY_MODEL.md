# Модель безопасности

## Непереговорные инварианты

- Один главный интегратор.
- Один владелец файла в момент времени.
- Exact baseline и exact allowed paths.
- Reviewer не пишет проверяемый runtime.
- Executor не принимает собственную работу.
- Рекомендация не является разрешением на изменение.
- Production, push, merge, DML/DDL и destructive-действия не наследуются из обычной задачи.
- При конфликте, росте scope или недоказанной безопасности работа останавливается.

## Защищённые зоны

Каждый проект должен явно перечислить зоны повышенного риска: auth, роли, права, деньги, склад, персональные данные, historical data, миграции, интеграции и production. Название файла не доказывает низкий риск: шаблон или helper может менять payload и policy.

## Evidence gate

Слова «готово» недостаточно. Принимаются exact diff, SHA, тестовый вывод, лог, скриншот, запрос к read-only данным или другой воспроизводимый маркер.

## Stop-condition

Если критерий нельзя доказать безопасно, фиксируется `needs-decision`. Агент не должен обходить ограничение новым скриптом, скрытой записью или более широким разрешением.
