# Карта model/effort без лишнего расхода токенов

Уровень выбирается по цене ошибки и изменяемому инварианту, а не по длине запроса или количеству файлов.

| Этап | Минимальный маршрут |
|---|---|
| Поиск файла, SHA, правила, статуса | Luna · high |
| Документация и механический текст | Luna · high или Terra · high |
| CSS/типографика без изменения поведения | Terra · high |
| Обычный frontend + backend одного сценария | Sol · high |
| Auth, роли, IDOR, DB write, concurrency | Sol · xhigh |
| Деньги, ledger, physical stock, historical data | Sol · xhigh; несколько контуров — ultra |
| Shared policy/guard/resolver | Sol · xhigh или ultra |
| Сложная неделимая архитектурная задача | Sol · max |
| Несколько независимых критических аудитов | Sol · ultra |

## Обязательное повышение

Повышайте уровень при обнаружении новой роли или scope, hidden DML/DDL, денег, количества, historical data, concurrency, destructive path, общего guard/resolver, production или неожиданного расширения diff.

## Разделение этапов

Большой task не обязан целиком работать на максимальном уровне. Нормальное разбиение:

1. read-only инвентарь;
2. решение бизнес-границы;
3. реализация;
4. критическая проверка;
5. docs-closeout;
6. отдельный deploy.

Каждый новый этап проходит собственный gate. Понижение не ослабляет acceptance и безопасность.
