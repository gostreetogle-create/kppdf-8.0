## 0. Цель

- Allowlist mime-types.
- Size limits per type.
- Magic-bytes / file-signature checks где применимо.
- Path traversal protection в disk storage.
- Запрет активного HTML/SVG по умолчанию.
- Безопасная статическая раздача (`/uploads/*`).
- Regression tests PNG/JPEG/WebP/PDF upload workflow.

---

## 1. Контекст

Multer disk storage используется как минимум в `photos`, `product-module-photos`, `product-photo`. Allowlist СЛАБ:
- `FileInterceptor` без `fileFilter` принимает любые mime-types если Multer не ограничивает.
- `diskStorage` с `filename: uuid` без проверки сохраняет даже `.html` c MIME `text/html`.
- `static /uploads` обслуживает все файлы как есть — если `.svg` с `<script>alert(1)</script>` сохранён → critical XSS.

## 2. Архитектурное решение

### ШАГ 1: Allowlist + size limits

Константы в `backend/src/static/file-validation.service.ts`:
```typescript
const ALLOWED_BY_FEATURE = {
  product_photo: ['image/png','image/jpeg','image/webp'],
  product_module_photo: ['image/png','image/jpeg','image/webp'],
  document_bg: ['image/png','image/jpeg','image/webp','application/pdf'],
  inventory_attachment: ['application/pdf','image/png','image/jpeg'],
  user_avatar: ['image/png','image/jpeg','image/webp'],
};
const MAX_SIZE_BY_TYPE = {
  'image/png': 10 * 1024 * 1024,
  'image/jpeg': 10 * 1024 * 1024,
  'image/webp': 10 * 1024 * 1024,
  'application/pdf': 30 * 1024 * 1024,
};
```

### ШАГ 2: Magic-byte verification

`file-validation.service.ts`:
- Читать first 16 bytes (file signature) на stream mode.
- Cross-check magic против dеclared mime (e.g. JPEG начинается с `FF D8 FF`, PNG — `89 50 4E 47`).
- Если mismatch → reject 415.

### ШАГ 3: Path traversal protection

`diskStorage` config:
- `destination: (req, file, cb) => uploadBase/${featureBucket}`.
- `filename: (req, file, cb) => uuid() + secure-ext (no user-input)` — никогда не доверять `file.originalname`.
- Backend validate: filename match `^[a-f0-9-]{36}\.[a-z0-9]+$` иначе 400.

### ШАГ 4: SVG/HTML sanitization

Если feature требует SVG (только для DOCUMENT design assets) — sanitize:
- `backend/src/static/sanitize-svg.ts` — whitelist tags `<svg, g, path, rect, line, circle, ellipse, text>`; вырезать `<script>`, `<foreignObject>`, `on*=`, javascript: hrefs.
- Если sanitize fails → reject 415.

### ШАГ 5: Static serving hardening

`backend/src/static/static.controller.ts`:
- Only allowed mime types servable.
- `Content-Security-Policy: default-src 'none'` для всех `image/*`.
- `X-Content-Type-Options: nosniff` (prevent mime-sniff).
- `Cache-Control: private, max-age=86400` (1 day).
- Если файл expired / deleted → 404, не expose path.

### ШАГ 6: Audit + access check

- Каждый upload logged с `actorId, feature, originalFilename (sanitized), declaredMime, magicMimeMatch`.
- Static GET — audit ТОЛЬКО для sensitive buckets; images — НЕ логировать каждый fetch (perfo noise).

### ШАГ 7: Tests

- Unit `file-validation.spec.ts` — magic-byte detection across PNG/JPEG/WebP/PDF; mismatch case.
- Unit `sanitize-svg.spec.ts` — known XSS vectors stripped.
- E2E `file-upload.e2e-spec.ts` — upload PNG → 200; upload .html→ 415; oversize → 413; magic-byte mismatch → 415; path traversal filename → replaced with uuid.

## 4. Критерии приёмки

1. Upload `.html` в любой image bucket → 415.
2. Upload PNG с magic-byte `FF D8 FF` (JPEG cert) → 415 (mismatch).
3. Upload JPEG 15MB (over 10MB) → 413 Payload Too Large.
4. Upload SVG с `<script>alert(1)</script>` → 415.
5. Upload валидного SVG with clean whitelist → 200.
6. `GET /uploads/products/x.${uuid}.png` → 200 + `X-Content-Type-Options: nosniff` + CSP.
7. `GET /uploads/x/../../secret.env` → 400 (path traversal).
8. Regression: existing photo upload flow (used by `pi-photos.service.ts`) still works.
9. `pnpm test` exit 0; backend typecheck exit 0.
