# TZ-253 — Dependency scan и deployment security checks

**Статус:** READY / будущая задача. Только постановка будущих проверок.

**РОЛЬ АГЕНТА:** DevSecOps Maintainer

**ЗАВИСИМОСТИ:** TZ-248 обязательно. TZ-249 не является обязательной зависимостью; если выполняется параллельно, сначала проверить CONFLICT KEYS и proxy/auth boundary.

**LAYER:** 4

**CONFLICT KEYS:** `.github/workflows/ci.yml`; `.github/workflows/nightly.yml`; `package.json`; `frontend/package.json`; `backend/package.json`; `pnpm-lock.yaml`; `frontend/pnpm-lock.yaml`; `backend/pnpm-lock.yaml`; `docker-compose.prod.yml`; `deploy/synology/DEPLOY.md`; `deploy/synology/RUNBOOK.md`

## Цель

Добавить дешёвый автоматический контроль известных уязвимостей и зафиксировать минимальные настройки reverse proxy без превращения проекта в enterprise DevSecOps platform.

## Что сделать

1. Проверить текущие frontend/backend manifests и lockfiles одним согласованным package-manager audit command; отделить production vulnerabilities от dev-only и задокументировать false positives.
2. Добавить в CI non-invasive dependency audit с понятной policy: high/critical production vulnerability блокирует merge, moderate/low только предупреждают до отдельного решения.
3. Проверить lockfile consistency, отсутствие install scripts/пакетов без обоснования и наличие регулярного weekly/nightly запуска.
4. Проверить reverse proxy: HTTPS redirect, конкретный `server_name`, `client_max_body_size` согласован с backend limits, forwarded headers доверяются только от proxy, MongoDB не опубликована во внешний интернет.
5. Добавить короткий runbook: как обновить dependency, проверить CI, откатить deployment и подтвердить `/api/health`.

## Файлы для изменения

- CI workflows и manifests только для добавления проверки.
- Deployment docs/config templates — только для проверяемых baseline-настроек.

**Не изменять:** production `.env`, реальные серверные конфиги и credentials; не устанавливать глобальные инструменты.

## Критерии приёмки

1. CI запускает dependency audit для backend и frontend и выдаёт воспроизводимый результат.
2. Policy для high/critical production advisories документирована; dev-only advisory не ломает обычный release без причины.
3. Weekly/nightly workflow выполняет audit или явно фиксирует, почему он выполняется в CI.
4. Proxy checklist подтверждает HTTPS, body-size alignment, trusted forwarded headers и отсутствие внешнего MongoDB port.
5. Runbook содержит health check и rollback steps без секретов.
6. Existing lint, tests, typecheck и builds проходят.

## Ограничения

Не добавлять WAF, SIEM, DAST-платформу, container scanner fleet или обязательный еженедельный upgrade всех пакетов. Цель — обнаруживать очевидные известные CVE и ошибки deployment-конфигурации.
