# QA-445B: Склад → «Приход на склад» — инлайн-добавление материала + автоподстановка

РОЛЬ: frontend (+ backend, если для инлайн-создания материала нужен новый
endpoint или расширение существующего).

CONFLICT KEYS: `pages/inventory/*` (движения склада, модалка прихода),
возможно `pages/materials/*` (переиспользуемый inline-create материала, если
он уже существует где-то ещё — проверить перед тем как писать новый).

ЧТО: Модалка «Приход на склад» (Склад / Материал / Количество / Документ-
Примечание / Провести-Отмена). Два отдельных запроса от PO на этом экране:

1. **Инлайн-создание материала.** Сейчас поле «Материал» — это только
   `<select>` из существующих материалов. PO хочет возможность добавить новый
   материал прямо из этой модалки (аналог паттерна «+/карандаш рядом со
   справочным полем», который уже используется в других местах проекта —
   сверить, есть ли готовый переиспользуемый компонент такого рода в
   `shared/ui`, прежде чем писать новый с нуля).
2. **«Данные должны подставиться»** (дословная заметка PO, без уточнения
   какие) — по скриншоту неясно, какое именно поле должно автозаполняться
   после выбора материала/склада. Нужно уточнить у PO при разборе TZ: имеется
   в виду единица измерения материала, последняя цена, последний склад
   поступления, или что-то ещё. **Не гадать — переспросить конкретику перед
   реализацией**, иначе будет угадан не тот autofill.

НЕ: не делать полноценную форму создания материала (все поля материала) —
если инлайн-создание нужно, обсудить с архитектором минимальный набор полей
для быстрого добавления «на лету» (вероятно: название + ед. измерения,
остальное донастраивается потом в карточке материала).

AC: из модалки «Приход на склад» можно создать новый материал не покидая
модалку, и после уточнения у PO — согласованное поле(я) действительно
подставляется автоматически.
