# Backlog — purchase price history (гибко)

> Источник: audit `docs/audits/2026-08-26-legacy-erp-ux-patterns-audit.md` §5.2 + Cursor §8.  
> Решение PO 2026-08-26: **не фиксировать один write-path сейчас**; когда дозреет —
> система должна допускать **несколько вариантов** ввода/ведения истории.

## Зачем парк

У Material сейчас только скаляр `pricePerUnit` — истории в БД нет. Виджет
спарклайна без источника данных = ложный P0. Chart-примитив уже есть
(`app-pi-line-chart`).

## Гибкость (обязательно в будущей TZ)

Не выбирать «только снабжение» или «только ручной ввод» заранее. Спека должна
заложить:

| Канал | Смысл |
|-------|--------|
| A — из снабжения | цена/дата/поставщик с закрытия задачи снабжения / поступления |
| B — ручная запись | менеджер вводит точку истории на карточке материала |
| C — импорт | Excel/Desktop (опционально позже) |

UI-виджет (popover/sheet: спарклайн + список) **один**; источники пишут в
общий store истории. Можно включить A без B или оба.

## Не сейчас

Волна UX-444 (A–D) **не** трогает историю цены. Этот файл — park до отдельного
гриллинга + TZ, когда PO скажет «делаем историю».
