# План задач на следующий рабочий день

## Цель
Продолжить подготовку новой NX-платформы без импорта Excel и без изменения старого приложения.

## Важное уточнение
Импорт файлов Excel в план не входит. Файлы `Снабжение.xlsx` и `Pasports.xlsx` используются только как справочный материал для анализа структуры данных.

## Термины
- **SupplyRequest** — заявка на снабжение.
- **Organization** — организация или поставщик.
- **ProductPassport** — паспорт изделия.
- **StorageItem** — складская позиция.
- **SupplyTask** — задача снабжения.
- **Комплекс** — не отдельная таблица, а изделие, в составе которого есть другие изделия.

## Порядок выполнения

### 1. Проверка текущих реестров — Cursor
Проверить фактическую работу страниц:
- Единицы измерения;
- Материалы;
- Детали;
- Модули;
- Изделия;
- Отделы;
- Заявки на снабжение;
- Организации и поставщики;
- Паспорта изделий.

Для каждой страницы проверить:
- наличие кнопки перехода в меню;
- фильтры;
- постраничный просмотр;
- раскрытие строки;
- кнопки действий;
- сообщения загрузки, ошибки и пустого результата;
- отсутствие неработающих кнопок.

Код менять только при подтверждённом дефекте.

### 2. Независимая проверка архитектуры — Claude Code
Режим проверки без изменения кода.

Проверить:
- не создаются ли дублирующие таблицы поставщиков, деталей или комплексов;
- честно ли указано, какие данные уже поддерживаются;
- не выдаётся ли просмотр паспорта за готовый импорт паспортов;
- не добавлены ли несуществующие параметры фильтрации или постраничного просмотра;
- соответствуют ли документы фактическому коду.

Создать отчёт с разделами:
- готово;
- частично готово;
- отсутствует;
- требует отдельной задачи для серверной части;
- можно отложить.

### 3. Следующий этап серверной части — только после проверки
Отдельно подготовить техническое задание на серверные поля, если это подтвердится:
- номер счёта;
- сведения о доставке;
- однозначный заказчик заявки;
- однозначный автор заявки;
- связь паспорта с изделием.

Ничего из этого не добавлять автоматически без отдельного подтверждённого задания.

### 4. Не делать завтра
- не импортировать Excel;
- не загружать данные в базу;
- не менять старое приложение `frontend/**`;
- не создавать отдельные таблицы «Поставщики», «Детали» или «Комплексы», если для них уже есть действующая модель;
- не добавлять новые поля и серверные маршруты без отдельной проверки;
- не менять оболочку приложения и боковые панели без отдельной задачи.

## Результат дня
К концу этапа должны быть:
1. отчёт о фактическом состоянии всех реестров;
2. список реальных недоделок;
3. отдельный список необходимых изменений серверной части;
4. понятный порядок следующих задач;
5. архивные отчёты агентов и отсутствие незакрытых claims.
