# NOTE — КП: снимок шаблона vs живой шаблон + замок «оплачена»

**Дата:** 2026-08-09  
**Статус:** канон-намерение PO (не executable TZ)  
**После:** TZ-SALES-319 (preview only) → successor persist+snapshot  
**Аудит кода:** schema уже имеет `templateId` / `templateSnapshot` / `designSnapshot`, но Create КП и form **не пишут**; `update()` не трогает snapshot; статуса `paid` нет.

---

## Вердикт для PO

Логика «сохранили КП → бланк не пляшет от правок шаблона» — **правильная**. Сейчас в продукте она **не доведена**: поля под снимок есть, проводки нет. Пока Create КП только превью через live `build(templateId)` — правка шаблона в конструкторе **сразу** меняет то, что видно при повторном открытии превью с тем же id (пока КП не сохранён со снимком).

---

## Канон поведения (зафиксировать в successor TZ)

| Состояние КП | Бланк (внешний вид шаблона) | Правки позиций/% | Обновить из шаблона (замок) |
|--------------|----------------------------|------------------|-----------------------------|
| Черновик / открыт, **замок закрыт** (default после Save) | Читаем **snapshot** | Да | Нет (нужно открыть замок) |
| Замок **открыт** | После «Обновить из шаблона» → новый snapshot из live `build` | Да | Да |
| Статус **«Оплачена»** (или согласованный hard-lock) | Только snapshot; без re-pull | **Нет** | **Нет** |
| «Оплачена» сняли (ошибка / клиент передумал) | Снова editable + можно открыть замок | Да | Да (если не converted в заказ без отдельного правила) |

Дополнительно (уже частично в коде):

- **`versions[]` / freeze** = история «что отправили клиенту» (SALES-302) — **не путать** с template snapshot.
- **`converted` → Order** = отдельный hard gate; не смешивать с «оплачена» без явной таблицы статусов.

---

## Статусы — дыра

Сейчас enum: `draft | sent | accepted | rejected | converted | cancelled`.  
**«Оплачена» в коде нет.** В lifecycle-планах иногда фигурирует как триггер → заказ; в sales-to-shop каноне — `accepted` → convert.

**Решение для successor (выбрать одно в TZ, не оба):**

1. **UI-лейбл «Оплачена» = `accepted`** + hard lock edit/re-pull; convert отдельно; или  
2. Новый статус `paid` между `accepted` и `converted`.

PO сказал: при «оплачена» — архив без правок; снятие статуса — снова можно. Это = **status-driven lock**, не только UI-замок шаблона.

---

## Слои работ (не мешать 319)

1. **SALES-319** — только live preview в Create (ок, не snapshot).  
2. **SALES-32x persist** — Save КП пишет `templateId` + `templateSnapshot` (HTML и/или blocks); view/print из snapshot.  
3. **SALES-32y lock** — UI замок «обновить из шаблона»; gates по статусу (оплачена/converted).  
4. **SALES-302** — версии отправки клиенту (уже в бэклоге канона).

CONFLICT KEYS для 32x/32y: `quotation.schema|service|dto`, proposals save path — **не** center preview keys 319.
