ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

1. **Бейдж статуса + смена**
   - В верхней строке студии: бейдж (Черновик / Отправлено / Принято / Отклонено /
     В заказе / Отменено) и выбор следующего статуса.
   - Разрешённые переходы — по канону продаж; «В заказе»/«Отменено» руками не ставятся.
   - Замок 336 остаётся сильнее: у закрытого КП смена статуса и правки недоступны с RU-подсказкой.

2. **Версии**
   - Кнопка «Сохранить версию» (тот же `freeze`, без второго write-path).
   - «Версии (N) ▾» — список: номер, дата, кто зафиксировал; выбор открывает снимок
     **только на просмотр** (лист из `payload`), с кнопкой «Вернуться к текущему».
   - Просмотр версии не трогает автосохранение и не перетирает текущий КП.

3. **Дальше по потоку**
   - «Создать заказ» — активна только при статусе «Принято» (правило BE не дублировать в FE
     своей логикой, читать ответ API); после успеха — переход на созданный заказ.
   - «Копировать КП» (duplicate) открывает копию в студии.

4. Tests: переходы статусов и disabled-состояния; просмотр версии не шлёт PATCH;
   «Создать заказ» скрыт/выключен вне «Принято».

ИЗМЕНЯТЬ: верхнюю строку студии и её сервисные вызовы.
НЕ ИЗМЕНЯТЬ: backend (эндпоинты уже есть), список «Все КП» (там действия остаются),
шелл 317, PDF (345).

known_limitation: сравнение версий бок о бок и откат к версии — не делаем;
только просмотр снимка.

КРИТЕРИИ ПРИЁМКИ:
1. В студии видно текущий статус КП и его можно перевести в «Отправлено»/«Принято».
2. «Сохранить версию» создаёт снимок, он виден в списке версий и открывается на просмотр.
3. У закрытого (оплаченного) КП правки и смена статуса заблокированы с понятным текстом.
4. «Создать заказ» работает из студии для принятого КП.
5. Gates: FE tsc + `pnpm test -- proposal-create`; Prettier/ESLint/diff-check PASS;
   browser self-verify PASS.
