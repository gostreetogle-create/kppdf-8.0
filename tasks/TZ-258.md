## 0. Цель

Документально зафиксировать матрицу для новых protected pages:

- Capability key формат (`<section>:<action>`).
- Read/write/admin policy.
- Server-side guard + decorator.
- Frontend route metadata API.
- Nav visibility filter.
- 403 state design.
- Audit action conventions.
- Test conventions.

Дополнительно: автоматизированный **audit** в коде, который показывает endpoints/routes без policy metadata. Если audit находит legacy exception — фиксировать его явно (ОТДЕЛЬНЫЙ follow-up), не ломать молча.

---

## 1. Архитектурное решение

### ШАГ 1: Page-author contract

`docs/protected-page-contract.md` (NEW):
- Раздел "Capability key":
  - формат `<section>:<action>` (`section` snake_case; `action` ∈ {read, write, admin}).
  - wildcard `*`.
- Раздел "Server-side":
  - `@Permissions(...)` decorator.
  - `@Roles(...)` AND-composition.
  - Last-admin guard (admin operations).
- Раздел "Frontend route":
  - `data: { capabilities: [...] }` on operational routes.
  - Default: no data → still requires JwtAuthGuard → но capability check skip.
  - `/kit/*` = public showcase, explicit bypass.
- Раздел "403 state":
  - Single `/forbidden` page; capability guard redirects there.
- Раздел "Audit action conventions":
  - format: `{entity}:{verb}` (e.g. `user:create`, `role:patch`).
  - sensitive field redaction.
- Раздел "Test conventions":
  - unit + e2e матрица по endpoint + role.
  - DOM contract for capability guard.

### ШАГ 2: Code-side audit script

`backend/scripts/audit-policy-metadata.ts`:
- Scan all *.controller.ts в `backend/src/modules/`.
- Group: `@Public()`, `@Roles()`, `@Permissions()` coverage.
- Output:
  - controllers WITHOUT any metadata (ad-hoc? potential gap).
  - controllers with @Roles but missing @Permissions (admin-only? add explicit).
  - legacy exceptions list (manual list in JSON config).
- Запускать в CI (or опционально nightly).
- `FAIL exit` если появляется НОВЫЙ controller без metadata И НЕ listed в legacy exceptions.

### ШАГ 3: Documented legacy exceptions

`backend/src/scripts-fields-helpers/LEGACY_RBAC_EXCEPTIONS.json`:
- List controllers intentionally без `@Permissions` (которая в effort coverage phase).
- Каждый: `path: string`, `reason: string`, `planned_remediation_tz: string|null`.

### ШАГ 4: Cross-link validation

- `docs/RBAC-CONTRACT.md` cross-link from `docs/protected-page-contract.md`.
- `ARCHITECTURE.md` mention policy audit script.

### ШАГ 5: Tests

- Unit `audit-policy-metadata.spec.ts`:
  - test data: existing controllers; scan output consistency;
  - legacy exception list honored (no FAIL для known legacy).
  - missing controller → FAIL.
