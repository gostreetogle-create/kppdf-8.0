## 1. Как понять «что уже сделано»

Правда только в файлах (не в прошлом чате):

| Где смотреть | Зачем |
|--------------|--------|
| `tasks/_archive/2026-08/<TZ>.done.md` | TZ закрыт |
| `tasks/_archive/**/*.failed.md` / `.deferred.md` | не повторять вслепую |
| `docs/agent-checklists/TZ-*.md` | AC галочки + claim slot |
| `docs/agent-checklists/_active-map.md` | последний Checkpoint: DONE / IN PROGRESS / NEXT / HEAD |
| `tasks/_backlog/**/WAVE-*.md` | порядок # и DEPENDS ON |
| `tasks/_active/` | кто сейчас держит файл |
| `git log -15 --oneline` | свежие коммиты по теме |
| `STATUS.md` + `bash verify-status.sh` | FSM kit синхронен |

Правило продолжения:
- Если TZ в archive DONE — **пропусти**, бери следующий по WAVE.  
- Если checklist/claim показывает IN PROGRESS и `_active/` твой/пустой — **доделай** этот TZ, не начинай новый.  
- Если DEPENDS ON не DONE — **не claim** зависимого; возьми ближайший разблокированный.  
- PARKED / «нужен ключ PO» — **skip** до явной команды PO.

## 2. Цикл одной TZ (не ломай порядок)

```
CLAIM → код по AC → gates зоны → progress.md → ARCHITECTURE (если зона) 
→ lock → archive → STATUS → verify-status → commit+push → Checkpoint → NEXT TZ
```

Детали: `OrchestratorKit/AGENTS.md` + `TZF-00`.  
Acceptance = измеримые пункты из файла TZ, не «кажется готово».

### 2a. Коммиты = сохранение версий (обязательно)

Работай **без пауз на согласование**, но **не копи** весь день в один гигантский uncommitted WIP.

| Когда | Что сделать |
|-------|-------------|
| **Обязательно** после каждой закрытой TZ | `git commit` + **`git push origin main`** своей зоны (код + archive + checklist + progress). Сообщение: `feat|fix|docs(<scope>): TZ-… — кратко зачем` |
| **Желательно** mid-TZ, если работа крупная (>~1–2 часа / много файлов) | промежуточный commit+push осмысленного куска после зелёных gates куска (миграция; затем API; затем FE) — чтобы обрыв не унёс полдня |
| **Checkpoint** после commit | `_active-map.md` с `HEAD: <sha> pushed: yes` |
| Не коммитить | секреты, чужой WIP, half-baked ломающий main без gates |

Правило PO: лучше **много маленьких зелёных коммитов по TZ**, чем один огромный в конце дня. Откат = один TZ, не вся неделя.

Закрытая TZ **без push** = для следующего агента как будто не доделано. Push — часть DONE.

**После каждого закрытого TZ** обнови Checkpoint в `_active-map.md` (верх/актуальный блок):

```markdown
## Checkpoint <ISO-дата-время>
- DONE: TZ-… (кратко что сделано + зачем для продукта)
- IN PROGRESS: none | TZ-…
- NOT DONE: список оставшихся READY волны
- NEXT: конкретный файл TZ
- HEAD: <short sha> pushed? yes/no
- Blockers: none | …
- _active/: empty | …
- Deploy: NO
```

Пиши так, чтобы **чужой** агент завтра без тебя понял: *что закрыто, зачем, куда идти*.

## 3. Очередь и волны

1. Источник приоритета: `tasks/_backlog/QUEUE.md`.  
2. Внутри волны — таблица порядка в `WAVE-*.md` (номера #1, #2…).  
3. Один агент в одном чате → **последовательно** по волне (параллель только если WAVE явно разрешает и CONFLICT KEYS не пересекаются).  
4. Волна DONE (кроме PARKED) → вернись в QUEUE → следующая READY волна / слот.  
5. Не воскрешай DONE-волны. Не бери чужой живой слот из «Не брать».

Текущий пример (может устареть — сверяй QUEUE):  
Shop-north **#7 TZ-UX-FORM-307** (Party-docs DONE; Catalog DONE; INN PARKED).

## 4. Когда остановиться (и только тогда)

Стоп **разрешён** если:
- очередь READY пуста (остались только PARKED / RESERVED / park) → отчёт: «готово предложить деплой»; **не** запускай `deploy.ps1`;
- CONFLICT KEYS с живым `_active/` коллегой → DEFERRED / needs_help;
- нужен секрет/ключ/решение PO (INN, wipe, prod);
- `verify-status.sh` FAIL и не чинится в своей зоне;
- gates красные после честной попытки фикса в зоне TZ.

Стоп **запрещён** mid-queue из-за «ок?», «поехали?», «продолжать?».

## 5. Деплой и полировка

- Цель волны задач — **код+доки в `main`, gates зелёные, архивы на месте**.  
- «Подготовлено к деплою» = очередь пуста + короткий отчёт PO + список PARKED.  
- `deploy.ps1` / wipe / prod — **только** явная фраза PO: «задеплой» / «деплой» / «кати».  
- Не выдумывай новые TZ из parked backlog без PO. Если видишь дыру качества на пути показа — **короткая заметка** в progress / audit, не раздувай scope текущей TZ.

## 6. Жёсткие запреты

- Не ждать «поехали» / «ок» / «продолжать?».  
- Не копить много TZ без commit+push.  
- Не писать «задача закрыта», если **нет** commit **и** push на remote.  
- Не автодеплой.  
- Не коммить секреты, `__pycache__`, `tasks/Данные/`.  
- Не коммить чужой half-baked WIP (напр. `desktop/mcp-runtime/**` до DESKTOP-SOT).  
- Не трогать CONFLICT KEYS чужого `_active/` TZ.  
- Не claim PARKED (INN и т.п.) без unpark от PO.  
- Не врать в финале «закрыта», если archive + verify не прошли.
