| 1 | GET /api/document-templates/:id              | owner      | own template             | 200      | authenticated owner CAN read                                   |
| 2 | GET /api/document-templates/:id              | OTHER user | owner's template         | **404**  | non-owner gets 404 (NOT 403; do not leak)                       |

| 8 | PATCH /api/document-templates/:id            | OTHER user | owner's template         | **404**  | IDOR — non-owner mutation denied                                |

- `RolesGuard` Step 1 (no `@OwnerOnly` metadata) → routes without `@OwnerOnly` pass through unchanged;
- `OwnershipGuard` Step 7 (legacy createdBy=undefined) → existing legacy documents are still mutable by `admin | manager` per existing `@Roles('admin','manager')`.

## 2. Mongo harness requirements

To run the e2e file, the project must adopt (or already have) one of:

- `mongodb-memory-server` (npm) — recommended path; integrates with Jest's `globalSetup` to spin up a real Mongo and tear it down per test run;
- `@nestjs/testing` Test module + Mongo Memory Server binary download (uses `MongoMemoryServer.create()` lifecycle hooks).
- OR: a `setup-jest.ts` that already provides a connection factory.

The harness must additionally provide:

- a seed helper that materializes:
  - 2 admin users (one of which becomes the test "owner" of the legacy + normal templates);
  - 1 manager user (mid-tier, no createdBy template);
  - 1 plain `user` with `counterparty:read` granted;
- a teardown hook that wipes the in-memory DB between `it()` blocks (or uses unique collection names);
- audit-trail silence harness — the AuditInterceptor must not write to a real Mongo audit collection for e2e noise (use a stub logger or skip AuditInterceptor for the e2e suite).

If the harness is **not** available yet, this TZ remains DEFERRED — do not mark PARTIAL. Either run all 15 scenarios, or none.
