## Цель

Дать пользователю удобный список слоёв и основные appearance-controls, которые он видит в ReportBro-подобном редакторе: выбрать элемент из списка, изменить порядок overlay-элементов, скрыть, заблокировать перемещение и настроить прозрачность самого элемента.

## Что сделать

1. Создать tab/section Layers внутри существующей правой панели, используя Paper & Ink primitives и текущую selection model. Показывать понятное имя, тип, active/hidden/locked state и порядок сверху вниз.
2. Click по layer item выбирает соответствующий block на canvas; selection на canvas прокручивает/подсвечивает соответствующий item. Не создавать отдельный selected state.
3. Для overlay/positioned элементов реализовать reorder, visibility и lock с безопасным сохранением. Для flow-блоков не притворяться, что z-index меняется, если фактически меняется только document order: явно отобразить семантику.
4. Добавить element opacity (0–1) отдельно от уже существующей `DocumentTemplate.backgroundOpacity`. Значение валидируется, сохраняется в block settings и одинаково отражается в canvas/preview/PDF pipeline.
5. Lock должен запрещать drag/resize и показывать доступное объяснение; delete/edit policy должна быть определена явно, чтобы lock не создавал обход через другой control.
6. Добавить component tests для layer selection/reorder, hide/lock/opacity, multi-select display и keyboard navigation; обновить builder docs.

## Критерии приёмки

1. Layers tab перечисляет все блоки в детерминированном порядке; click по item и click по canvas синхронизируют одну selection model.
2. Visibility и element opacity применяются к самому block, не к background; после reload значения восстанавливаются и не теряются при других settings patches.
3. Locked block нельзя переместить или resize мышью/клавиатурой; причина блокировки доступна через label/tooltip и ARIA state.
4. Reorder overlay изменяет фактический render order и сохраняется; flow reorder сохраняет текущий server order без ложного z-index.
5. Есть tests на boundary values 0/1, invalid input, selection sync, lock enforcement, reorder persistence и print/PDF parity.
6. Frontend/backend checks проходят; новый UI использует существующие Paper & Ink components, а не новый UI-kit.

## Ограничения

Не добавлять полноценную Photoshop-like scene graph, blend modes, rotation, masks или nested groups. Не смешивать opacity элемента с opacity фонового изображения. Не принимать решения авторизации на frontend.
