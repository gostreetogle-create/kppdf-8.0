# TZ-235.C — builder-inspector: extract state + split into 3 mode-specific sub-components

**Branch:** `freebuff/new-thread-thms6ee2rx5i1q`
**Status:** Planning
**Depends on:** TZ-235.A R3 (shipped) + TZ-235.B (shipped) — same architectural pattern.

---

## Цель (простым языком)

`builder-inspector.component.ts` — это самый «толстый» компонент во всём проекте (1856 строк). Это правая панель конструктора, которая показывает свойства в зависимости от того, что выбрано:
- **Шаблон целиком** (когда кликнули пустое место холста): яркость фона, шапка/подвал, фоновые картинки
- **Один блок** (когда кликнули на блок): название, контент, картинка, отступы, привязки
- **Несколько блоков** (Ctrl+Click): общие отступы, удалить всё
- **Ничего не выбрано** (никликнули): сводка документа + настройки сетки

**Проблема**: 1856 строк, в которых перемешаны 4 разных режима интерфейса, 17 сигналов формы, 30 обработчиков, 11 формул. Когда добавляем фичу (магнитная сетка, undo/redo, группировка) — приходится лезть в эту гору и рисковать что-то сломать в соседнем режиме.

**Решение**: распилим на 5 файлов по той же логике, что в TZ-235.A R3 + TZ-235.B:
- **Один** сервис-источник правды (все сигналы, формулы, обработчики)
- **Один** тонкий переключатель режимов (по какому режиму показать)
- **Три** подкомпонента, по одному на каждый «богатый» режим (template / block / multi-select)

## Архитектура (как разделяем код)

### Сервис — `BuilderInspectorStateService` (~420 строк)

**Что внутри** (зеркальная копия оригинального component class, только упакованная в `@Injectable()`):
- **9 сигналов-входов** (block, selectedCount, selectedBlocks, paperWidth, templateSelected, template, allBlocks, snapEnabled, gridSize, boundaryPadding) — компонент-родитель зеркалит через `effect()` в constructor.
- **17 сигналов формы** (title, content, height, isActive, showLine, bindingValue, blockWidth, blockMarginLeft + 7 image-сигналов + 3 snap-локальных сигнала).
- **1 Subject для debounce** (`textInput$` — 300мс debounce на template header/footer text, чтобы не дёргать бекенд на каждом символе).
- **11 формул** (opacityPercent, blockCount, activeBlockCount, blockTypeSummary, marginLeftPx, marginRightPx, maxMarginLeftPx, maxMarginRightPx, multiMarginLeftPx, multiMarginRightPx, settingsTableId).
- **2 эффекта в constructor**:
  1. Hydrate form-сигналы когда `block()` меняется
  2. Hydrate snap-локальные сигналы когда `snapEnabled/gridSize/boundaryPadding` меняются
- **12 Output-каналов** (Subject) для boundary-events: update$, delete$, deleteSelected$, editSelected$, marginReset$, multiMarginUpdate$, templateUpdate$, uploadBackground$, removeBackground$, setDefaultBackground$, snapSettingsChange$, closePanel$.
- **30+ обработчиков** (все original handlers, перенесённые побайтово: onTitleInput, onContentInput, onHeightInput, onIsActiveChange, onShowLineChange, onBindingValueInput, onDelete, onSnapEnabledChange, onGridSizeInput, onBoundaryPaddingInput, onClosePanel, onOrientationChange, onPageSizeChange, onTemplateSettingChange, onTemplateTextInput, onOpacityInput, onFileChange, onImageUpload, onRemoveImage, onImageWidthInput, onImageHeightInput, onImageOverlayToggle, onOverlayLeftInput, onOverlayTopInput, onRemoveBackground, onSetDefaultBackground, onMarginLeftInput, onMarginRightInput, onResetMargins, onMultiMarginLeftInput, onMultiMarginRightInput, onMultiResetMargins).

**Lifetime**: per-instance через `providers: [BuilderInspectorStateService]` на `@Component` switcher. Не `providedIn: 'root'` — у инспектора тоже должен быть per-instance scope (если вдруг 2 инспектора когда-нибудь окажутся на экране — их состояние не должно интерферировать).

### Переключатель — `BuilderInspectorComponent` (~170 строк)

**Что внутри** (class body после template/styles):
- **9 `input()`** + **12 `output()`** — ровно те же, что у оригинала. Так что `builder.page.ts` не меняется ни в одной строке.
- `private readonly state = inject(BuilderInspectorStateService)`.
- **Constructor**: 2 mirror-effects (input → service) + 12 subscriptions (service Subject → Angular output).
- **Template** (~80 строк): `<aside class="inspector">` + header + `@if (@else if) ... <app-.../>` диспетчер на 4 ветки.
- **Inline empty/summary state** (snap-настройки + сводка документа) — оставлен внутри switcher как самый маленький и тесно связанный с остальной инфраструктурой.

### Подкомпонент `TemplatePropertiesFormComponent` (~310 строк)

**Что внутри**:
- Selector: `app-template-properties-form`.
- Standalone, без своих inputs/outputs.
- `private readonly state = inject(BuilderInspectorStateService)` — получает тот же instance от родителя (hierarchical DI).
- **Template** (~150 строк): Section 01 Visual Style (opacity slider + page numbering + table-of-contents toggles) + Section 03 Metadata (headerText + footerText inputs) + Section 04 Background Image (grid + uploader).
- **Styles** (~120 строк) — все `.props-section`, `.field`, `.bg-grid`, `.bg-upload` стили, вырезанные из большого общего stylesheet.
- 0 нового DI — нужен только `LucideAngularModule` для иконок (Hash, List, Upload, X, Check, Star).

### Подкомпонент `BlockInspectorComponent` (~490 строк)

**Что внутри**:
- Selector: `app-block-inspector`.
- Standalone, без своих inputs/outputs.
- `private readonly state = inject(BuilderInspectorStateService)`.
- **Template** (~310 строк): большой диспетчер по `block()!.type` — для каждого типа (text/header/image/table/signature/spacer) показывает свой набор полей + actions (edit/delete + margin controls).
- **Styles** (~180 строк) — `.inspector__form`, `.field`, `.badge`, `.margin-controls`, `.inspector__section`.
- 0 нового DI — `LucideAngularModule` + `ButtonComponent` (`app-pi-button`) + `SwitchComponent` (`app-pi-switch`).

### Подкомпонент `MultiSelectInspectorComponent` (~100 строк)

**Что внутри**:
- Selector: `app-multi-select-inspector`.
- Standalone, без своих inputs/outputs.
- `private readonly state = inject(BuilderInspectorStateService)`.
- **Template** (~50 строк): counter + margin controls (left/right) + reset button + delete-all button.
- **Styles** (~30 строк) — margin-controls, button, counter.
- 0 нового DI — `LucideAngularModule` (RotateCcw) + `ButtonComponent`.

## Дифф с builder.page.ts

**Ноль изменений**. Switcher сохраняет все 9 inputs + 12 outputs, поэтому page.ts продолжает работать как раньше.

## Тонкости (gotchas)

1. **Hierarchical DI** — подкомпоненты MUST быть ДОЧЕРНИМИ `BuilderInspectorComponent` (в DOM), чтобы `inject(BuilderInspectorStateService)` находил общий instance. Это выполняется автоматически: switcher рендерит подкомпоненты через tag `<app-template-properties-form />` внутри своего `<aside>`. Angular DI работает через view hierarchy injection tree.
2. **`providers:` на switcher** — без этого сервис был бы singleton через root injector и все три подкомпонента делили бы один instance. С `providers:` каждый экземпляр switcher (на случай двухпанельного UI) изолирован.
3. **Subject-как-boundary bridge** — 12 output Subjects в сервисе + 12 `takeUntilDestroyed()` подписок в switcher constructor. Ноль утечек на destroy.
4. **Debounce в сервисе** — `textInput$` Subject с `debounceTime(300)` живёт в сервисе, `pipe(debounceTime)` подписывается один раз в constructor. По destroy сервиса — Subject умирает вместе с ним (нет утечки наблюдателей).
5. **Computed `multiMarginLeftPx`/`multiMarginRightPx`** нужны обоим — и block-inspector (для single mode с disabled inputs), и multi-select-inspector. Они живут в сервисе как shared state.
6. **Orphan styles после split** — общие стили (`.inspector__header`, `.inspector__type-pill`, `.inspector__close`) остаются в switcher styles, специфичные (`.inspector__form`, `.margin-controls__input-row`) уезжают в подкомпоненты.

## Что НЕ делаем (отложено в TZ-235.D и далее)

- **Undo/Redo** (TZ-235.E) — будет жить в этом же сервисе как стек истории.
- **Группировка + multi-drag** (TZ-235.D) — расширит multi-select-inspector.
- **Magnetic grid с визуальными линиями** — расширит snap-settings внутри inline empty state.
- **Ki-flow Color picker** — будет новый input в template-properties-form.

Все эти фичи добавятся как новые сигналы/обработчики в сервис или новые поля в подкомпонентах — без касания switcher и других режимов.
