# TZ-239 — OrgScopeGuard (TX data isolation, enforced multi-tenant)

**Дата создания:** 2026-07-31 (audit от multi-tenant readiness review)
**Автор:** senior-architect audit (TZ-238..241 batch)
**Приоритет:** CRITICAL (закрывает cross-org data leak на STORED данных — contract, order, document-template, generated-document, quotation, reconciliation-act)
**Связь:** REQUIRES `TZ-238 (User.organizationId)` как prerequisite
**Скоуп:** New `@RequireOrgScope()` decorator + `OrgScopeGuard` interceptor + apply to 11 transactional controllers. **Никаких** changes to reference-data collections (TZ-240).

---

## 0. TL;DR для PO

**Цель:** Сделать невозможным cross-org data access — даже с валидным JWT пользователь из Орг-A получит 404 при попытке `GET /api/contracts/<id-Org-B>`.

**Два архитектурных варианта (нужен review от PO):**
1. **Interceptor (recommended):** Reflector на route metadata → auto-filter in interceptor (less invasive, opt-in per method).
2. **Mongoose pre-find plugin:** Auto-injects `{organizationId: user.organizationId}` (DRY but invasive — touches every read).

Decision: Variant 1 (interceptor). См. §2.

**Объём:**
- ~150 LOC backend (interceptor + decorator + 11 controller applications)
- 2-3 LoC на каждый tx-controller для добавления декоратора + interceptor binding
- 3 e2e tests (cross-org GET → 404, cross-org GET с query param OrgB → только свои, cross-org PATCH/DELETE → 403/404).

---

## 1. Контекст (проблема)

### 1.1 Audit findings (post-TZ-238)

После apply TZ-238 у нас есть `req.user.organizationId` для каждого authed request. НО service-уровень фильтры НЕ enforce'ятся:

- `document-template.service.ts:294` — `if (dto.organizationId && Types.ObjectId.isValid(dto.organizationId))` — read-фильтр optional, **не rejects** cross-org ids.
- `contract.controller.ts` — нет `@RequireOrgScope()`, GET возвращает любой id по ObjectId без проверки org.
- `reconciliation-act.service.ts:91` — read фильтр `if (organizationId)` — optional. Не работает как security guard.
- `order.service.ts`, `quotation.service.ts`, `generated-document.service.ts` — same pattern.

### 1.2 Cross-org attack vectors (после TZ-238)

1. **Direct GET:** Visiting `/api/contracts/<orgB-id>` own id в URL → returns OrgB contract (no org check).
2. **Query param injection:** `GET /api/contracts?organizationId=<orgB-id>` — user possibly из OrgA может прочитать `filter: {organizationId: orgB}`, если service игнорирует user.organizationId. (Currently: filter only applied if Org param match — but no validation that user is in that org).
3. **PATCH/DELETE across org:** POST/PATCH /api/orders/{orgB} — currently allowed. Writes **into other org's data**.
4. **Audit gap:** AuditLog не записывает cross-org attempted access → invisibility в forensics.

### 1.3 Architectural decision

**Two approaches comparison:**

| Aspect | A: Interceptor | B: Mongoose plugin |
|--------|----------------|---------------------|
| Code surface | 1 interceptor + 1 decorator + opt-in per controller | 1 plugin + auto-applies to all reads |
| Testability | easy mock | harder (Mongoose model-level) |
| Granularity | per-controller/method | global |
| Backward compat | explicit opt-in → empty change for non-org-scoped collections | opt-out via `@SkipOrgScope()` |
| Side effects on non-org-scoped colls (Role, Permission, Setting, etc.) | ZERO (no decorator → no filter) | POTENTIALLY breaks non-org-scoped |
| Risk level | LOW (opt-in) | MEDIUM (auto-applies everywhere) |

**Decision: Approach A (interceptor + opt-in decorator).** Compatible with reference data still being shared (TZ-240 separate scope).

## 2. Архитектурное решение

### 2.1 Decorator

```typescript
// backend/src/common/decorators/require-org-scope.decorator.ts (NEW)
import { SetMetadata } from '@nestjs/common';

export const REQUIRE_ORG_SCOPE = 'requireOrgScope';

/**
 * Marks a controller or method as requiring enforced organizationId scope.
 * OrgScopeGuard reads this metadata and:
 *   - GET: filters `findById`/`findAll` queries by {organizationId: req.user.organizationId}
 *   - PATCH/DELETE: validates `params.id` belongs to user.organizationId before mutation
 *   - Returns 404 if cross-org attempted
 *
 * Combine with @Roles() — composable:
 *   @Controller('contracts')
 *   @Roles('admin', 'manager', 'user')
 *   @RequireOrgScope()
 *   export class ContractController { ... }
 *
 * Bypass: @Public() OR explicit @SkipOrgScope() (for cross-org admin actions).
 */
export const RequireOrgScope = (): MethodDecorator & ClassDecorator =>
  SetMetadata(REQUIRE_ORG_SCOPE, true);
```

### 2.2 Interceptor

```typescript
// backend/src/common/interceptors/org-scope.interceptor.ts (NEW)
import { CallHandler, ExecutionContext, Injectable, NestInterceptor, NotFoundException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable } from 'rxjs';
import { REQUIRE_ORG_SCOPE } from '../decorators/require-org-scope.decorator';

@Injectable()
export class OrgScopeGuardInterceptor implements NestInterceptor {
  constructor(
    private readonly reflector: Reflector,
    private readonly model: Model<{ organizationId?: Types.ObjectId; _id: Types.ObjectId }>,
  ) {} // injected Model for the controller's collection (per-controller registered)

  intercept(ctx: ExecutionContext, next: CallHandler): Observable<unknown> {
    const isOrgScoped = this.reflector.getAllAndOverride<boolean>(REQUIRE_ORG_SCOPE, [
      ctx.getHandler(),
      ctx.getClass(),
    ]);
    if (!isOrgScoped) return next.handle();

    const req = ctx.switchToHttp().getRequest();
    const me = req.user as AuthenticatedUser | undefined;
    if (!me?.organizationId) {
      // system user (bootstrap admin) → bypass scope. Audit-logged.
      return next.handle();
    }

    return next.handle().pipe(
      map((result: unknown) => {
        if (!result) return result;
        return this.assertOrgOwnership(result, me.organizationId);
      }),
    );
  }

  private assertOrgOwnership(value: unknown, userOrgId: string): unknown {
    // Single document OR array — for findAll
    const docs = Array.isArray(value) ? value : [value];
    const filtered = docs.filter((d) => {
      if (!d || typeof d !== 'object' || !('organizationId' in d)) return true;
      const docOrgId = (d as { organizationId?: Types.ObjectId | string }).organizationId;
      if (!docOrgId) return true; // for hybrid records (e.g. system records)
      return String(docOrgId) === userOrgId;
    });
    if (Array.isArray(value)) return filtered;
    if (filtered.length === 0) throw new NotFoundException('Not found');
    return filtered[0];
  }
}
```

**Per-model interceptor registration** (controller-level):

```typescript
// Pattern: each controller provides its own interceptor binding.
// Generic helper:
export const OrgScopeInterceptorFor = (model: Model<unknown>) =>
  class extends OrgScopeGuardInterceptor {
    constructor(reflector: Reflector) { super(reflector, model as any); }
  };
```

**Apply в контроллере:**

```typescript
@UseInterceptors(OrgScopeInterceptorFor(ContractModel))
@UseGuards(JwtAuthGuard, RolesGuard)
@Controller('contracts')
export class ContractController { ... }
```

### 2.3 Audit integration

The interceptor logs 403/404 cross-org attempts via `AuditInterceptor` (TZ-05 already configured for ALL routes). Description field includes `entityType='cross_org_attempt'` and `details.meta={attemptedOrgId, userOrgId, route}`.

### 2.4 Controllers to apply

Apply to 11 transactional controllers (TZ-238 assumed done — so req.user.organizationId is always present):

## 8. Risks

- **R1:** Per-controller interceptor binding adds boilerplate. Mitigation: factory helper `OrgScopeInterceptorFor(model)`.
- **R2:** Some controllers might accidentally expose docs without organizationId (legacy data no TZ-240). Mitigation: TZ-240 applies orgId to ALL docs at write; pre-TZ-240 reports filtered empty.
- **R3:** Cross-org super-admin bypass — auditable BUT still security risk if admin token leaked. Mitigation: refreshTokenVersion + 2FA in future TZ-238-extension.
- **R4:** Existing e2e tests pre-TZ-238 might not seed organizationId. Mitigation: TZ-238 includes migration; TZ-239 e2e uses OrgA/OrgB isolation explicitly.
