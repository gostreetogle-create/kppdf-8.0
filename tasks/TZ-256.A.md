## 0. Контекст и причины появления

TZ-256 (Capability-aware routes + navigation) формально закрыт — frontend
**typecheck EXIT 0** ✓, backend TZ-255/254/251 baselines все PASS ✓.
Однако code-reviewer rounds 2-3 отметил блок неблокирующих gap, которые
сознательно отложены в этот follow-up, чтобы не блокировать верификацию:

1. **Jest TestBed setup** — TZ-256 specs (capabilities.service.spec,
   capability-route.guard.spec, forbidden.page.spec) не компилируются
   в текущей форме без дополнительной TestBed-инфраструктуры. Frontend
   typecheck проходит (TS safe), но jest runtime падает на 17/18 specs.
   Минимальные возможные причины:
   - AuthService injection требует `provideHttpClient` + `provideHttpClientTesting`
     для HTTP-вызовов в bootstrap;
   - CapabilitiesService + AuthService без `provideRouter([])` без
     полной Stub-провайдерской сети;
   - `@jest/globals` import был снят, но TS jest preset-jest-preset-angular 14
     может иметь config-зависимость для `injectIntoGlobalThis`.

2. **`Palette` icon collision** — admin nav category и "UI Kit" header link
   оба используют `Palette` lucide icon. Визуальная коллизия в шапке.

3. **`/admin/users` и `/admin/roles` route registration** — NAV_CATEGORIES
   их добавил, но реальные routes не зарегистрированы в `app.routes.ts`.
   TZ-257 их заполнит, но в STATUS следует явно перечислить gap
   для предотвращения silent flip.

4. **`SKIP_FORBIDDEN_REDIRECT` blast radius** — opt-out token дефолтно
   `false`, поэтому ЛЮБОЙ backend 403 (включая programmatic probes)
   redirect-ит на `/forbidden`. Компоненты, которые сейчас ловят 403
   через toast/inline error UI, будут молча тер-ять видимое сообщение.
   Survey существующих callers + дефолт `true` (opt-in redirect)
   для migration safety.

## 1. Acceptance criteria

### 1a. Frontend jest TestBed scaffolding (CRITICAL)

Файл `frontend/src/app/core/capabilities/capabilities.service.spec.ts`:

- Заменить ручной `TestBed.configureTestingModule` на
  полноценную scaffolding, использующую
  `provideHttpClientTesting()` + AuthService (already injected) +
  Router provideRouter(test routes) + ApiTokens `API_BASE_URL`.
- 4 user role кейса должны покрывать:
  - null user → empty Set
  - role='user' + permissions=['x'] → x present
  - role='admin' + permissions=[] → ALL catalog
  - role='user' + permissions=['*'] → ALL catalog

Файл `frontend/src/app/core/capabilities/capability-route.guard.spec.ts`:

- Заменить `TestBed.runInInjectionContext(() => capabilityRouteGuard(...))`
  на `TestBed.inject(CapabilitiesService)` + invoke guard through
  Router testing module для rea-лизованной nav-схемы.
- 7 cases: bypass on empty / has / no-match / null user / missing data / admin / wildcard.

Файл `frontend/src/app/shared/ui/forbidden/forbidden.page.spec.ts`:

- Добавить минимальное provideRouter + AuthService mocking.

### 1b. Icon collision fix

Файл `frontend/src/app/layout/app-layout.component.ts`:

- Заменить `icon: Palette` для admin nav category на
  `icon: ShieldCheck` (lucide-angular) или `Wrench` в зависимости от
  визуальной согласованности.

### 1c. /admin/* routes registration (TZ-257 territory, route only)

Файл `frontend/src/app/app.routes.ts`:

- Добавить placeholder route definitions для `/admin/users` и
  `/admin/roles` с:
  - `canMatch: [authGuard, capabilityRouteGuard]`
  - `data: { capabilities: ['user:read'] }` для `/admin/users`
  - `data: { capabilities: ['role:read'] }` для `/admin/roles`
  - `loadComponent: () => import('./pages/admin/_admin-placeholder.page').then(...)`,
    где placeholder — minimal "TBD by TZ-257" stub компонент
    (`<div class="pi-page-frame">TZ-257 placeholder</div>`).

### 1d. SKIP_FORBIDDEN_REDIRECT opt-in semantics

Файл `frontend/src/app/core/auth.interceptor.ts`:

- Поменять default `skip` поведение → опции: default `false` (redirect
  на /forbidden) ИЛИ default `true` (только opt-in redirect).
- Рекомендация: default `true` (programmers opt-in) для migration safety.
- Survey существующих /api/* 403-вызовов через grep + manual review.
