# TZ-249 — Auth entry points and anti-automation

**Дата создания:** 2026-07-31
**Автор:** senior-orchestrator
**Приоритет:** CRITICAL (защита production auth surface)
**ЗАВИСИМОСТИ:** Рекомендуется TZ-248 перед стартом
**LAYER:** 4
**CONFLICT KEYS:**
- backend/src/modules/auth/auth.controller.ts
- backend/src/modules/auth/auth.service.ts
- backend/src/common/guards/throttler-behind-auth.guard.ts
- backend/src/main.ts
- backend/src/config/runtime-config.ts (NEW optional)

---

## 0. Цель

- Production registration НЕ создаёт manager.
- Login throttling реально работает и не bypassable.
- `DISABLE_THROTTLE=1` не имеет эффекта в production.
- `X-Forwarded-For` не позволяет обходить throttling.
- Login errors не раскрывают username enumeration (одна generic ошибка для invalid-user vs wrong-password).

---

## 1. Контекст

Текущая TZ-91 sweep применил `@Roles` decorator на большинстве controllers, но не закрыл все anti-automation угрозы:
- Default `@Throttle(5/min, 20/hour)` теоретически отключается через переменную `DISABLE_THROTTLE`.
- В dev-стеке X-Forwarded-For принимается → в prod под reverse-proxy это потенциальный spoofable header.
- `/auth/login` response различает 401 «нет юзера» vs 401 «неверный пароль» — username enumeration leak.

---

## 2. Архитектурное решение

### ШАГ 1: Production throttling invariant

`backend/src/main.ts`:
- Если `NODE_ENV === 'production'` И `process.env.DISABLE_THROTTLE` truthy → `console.error('DISABLE_THROTTLE is ignored in production; aborting')` ; `process.exit(1)`.
- В prod throttling enforce even если `app.useGlobalGuards(new ThrottlerGuard())` не регистрировал.

`backend/src/common/guards/throttler-behind-auth.guard.ts`:
- Если guard стоит за auth guard → JwtAuthGuard до него, проверка user.
- Trust `X-Forwarded-For` ТОЛЬКО если `TRUST_PROXY=1` (env). Default — игнорировать spoofed headers (используем IP из req.socket.remoteAddress).

### ШАГ 2: Registration hardening

`backend/src/modules/auth/auth.service.ts`:
- В production: `POST /auth/register` создаёт ТОЛЬКО user role:
  - явный `role: 'user'` несмотря ни на что в DTO;
  - DTO `RegisterDto.role` — `@IsOptional()` но в prod игнорируется.
- В dev: всё ещё работает TEMPORARY (TZ-91A1 marker).
- Audit: каждый register logged с IP.

### ШАГ 3: Generic login errors

`backend/src/modules/auth/auth.controller.ts`:
- Если user not found → bcrypt-dummy compare (timing attack safety) + вернуть ТАКУЮ ЖЕ generic ошибку как invalid-password.
- Ошибка: `'Неверный логин или пароль'` (single message).
- Audit log — **раздельные** entries: 'login_attempt_unknown_user' vs 'login_attempt_wrong_password' для forensics, но client response идентичен.

### ШАГ 4: Rate-limit backoff

- Login: 5/min, 20/hour (existing per TZ-91A3) — keep as is.
- Добавить: при 5 подряд failed login для username — softlock 15 min (Redis OR in-memory counter). **Not** deferred to TZ-extension — это критичное property.
- Реализация: in-memory cache `attemptsByUsername: Map<string, {count, lockedUntil}>` — per-instance, ok for single-pod dev; для multi-pod — TODO follow-up.

### ШАГ 5: Tests

- unit `auth.controller.spec.ts` — production register всегда 'user'; dev mode register respects DTO role.
- unit `auth.service.spec.ts` — generic error на invalid user И invalid password (identical message).
- unit `throttler-behind-auth.spec.ts` — DISABLE_THROTTLE в production → throws.
- e2e `auth-rate-limit.e2e-spec.ts` — 6 rapid failed login → 6-й возврат 429.
- e2e `username-enum.e2e-spec.ts` — два запроса с разным username дают IDENTICAL response.

## 4. Критерии приёмки

1. Production boot с `DISABLE_THROTTLE=1` → exit 1.
2. Production boot с `JWT_SECRET=dev` ИЛИ `JWT_SECRET=changeme` → exit 1 (TZ-248).
3. `POST /auth/register {role:'admin'}` в production → 403 или role=null coerced to 'user'.
4. `POST /auth/login` для несуществующего username И для существующего с wrong_password → response.identical body message.
5. 6 rapid failed login on one username → 6-й response.status === 429, 7-й тоже 429.
6. `X-Forwarded-For: <arbitrary>` без `TRUST_PROXY=1` в prod → IP из req.socket используется.
7. Unit + e2e tests pass; backend typecheck exit 0.
