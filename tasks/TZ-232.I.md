# TZ-232.I — Angular ESLint Safety Rules: `no-raw-http-in-components` + `no-implements-oninit-in-pages`

**Дата создания:** 2026-07-28
**Автор:** Buffy (Layer 2 implementation owner)
**Приоритет:** STRATEGIC — обязательная часть Wave F (Advanced UX + tooling). Защита на lint-level от regressing миграцию на DSL.
**Wave:** TZ-232 Wave F — параллельно с TZ-232.C POC (не блокирует).
**Layer:** Frontend tooling (ESLint custom rules).
**Скоуп:** 2 новых ESLint rule files + spec tests + config integration + pre-commit hook + 1 disable annotation batch в `templates.page.ts`.

---

## 0. TL;DR для PO

**Проблема (из master plan §1.2, §1.4):**
1. **Raw `this.http.X()` в page/component файлах** — bypasses DSL Repository layer (defineEntity), creates regression risk по мере миграции на Wave C/D/E/F.
2. **`OnInit` lifecycle в page файлах** — legacy Angular pattern, должен migrate на `effect()` или `inject()` in constructor.

**Решение:** 2 custom ESLint rules (`@pi-dsl/no-raw-http-in-components`, `@pi-dsl/no-implements-oninit-in-pages`) встроены в `frontend/eslint.config.js` (ESLint 9 flat config). Severity = ERROR — block `pnpm lint` exit на любую новую violation. Pre-commit hook (`.husky/pre-commit`) автоматически runs rule spec tests + ESLint на staged frontend .ts files.

**Эффект:** TZ-232.D/E/F page migration теперь fully safe — raw HTTP и pre-migration patterns блокированы на lint-level. Параллельно с TZ-232.C POC → 0 blocking dependency.

## 1. Архитектура

### 1.1 Stack & Constraints

- **ESLint 9** с **flat config** (`eslint.config.js`) — НЕ legacy `.eslintrc.json`.
- **TypeScript-ESLint** v8: `@typescript-eslint/parser` установлен. `@typescript-eslint/utils` **НЕ установлен** → правила реализованы на vanilla ESLint API (никаких `@typescript-eslint/utils` imports).
- **Angular ESLint** `@angular-eslint/eslint-plugin@^22.1.0` + `@angular-eslint/template-parser@^22.1.0` для Angular-specific rules (existing).
- **Pre-commit** через Husky (existing `.husky/pre-commit`).

### 1.2 Rule 1: `no-raw-http-in-components`

**Цель:** Ban `this.http.<get|post|put|patch|delete>(...)` member calls AND direct `HttpClient` imports в `*.component.ts` И `*.page.ts` файлах (оба convention names покрыты — pages have `@Component` decorator too).

**Scope:**
- `files: 'src/**/*.{component,page}.ts'` в eslint.config.js (relative to `frontend/eslint.config.js`'s `__dirname` = `frontend/`).
- Self-filter inside rule: filename MUST end with `.component.ts` OR `.page.ts`, MUST NOT end with `.spec.ts`.

**Что блокирует:**
1. `this.http.get(...)`, `this.http.post(...)`, etc. — chained member call variants.
2. `import { HttpClient } from '@angular/common/http'` — direct symbol import (catches both bare `HttpClient` И aliased `import { HttpClient as HC }`).
3. Все 5 HTTP verbs: `get`, `post`, `put`, `patch`, `delete`.

**Что разрешает:**
- `httpResource(...)` calls (Angular 20 signal-based HTTP — used by `<pi-lookup-*>`/`<pi-data-grid>`).
- `HttpParams`, `HttpErrorResponse` imports (used by lookup tables для URL building / error normalization).
- `*.service.ts`, `*.interceptor.ts`, `*.spec.ts` (filename filter exempts these).

**AST pattern:** `CallExpression` visitor walks callee chain:
```
this.http.get(...)  →  CallExpression
                        callee: MemberExpression(this.http.get)
                          property: 'get'  (in HTTP_VERBS)
                          object:    MemberExpression(this.http)
                            property: 'http'
                            object:    ThisExpression
```
Verified by 11 test cases (6 valid + 5 invalid).

**Сообщения:**
- `rawHttpCall`: "this.http.{{method}}(...) is banned in *.component.ts / *.page.ts. Use defineEntity() from shared/dsl/entity/ (or toEntityService(svc) adapter for hand-written services)."
- `rawHttpImport`: "HttpClient import is banned in *.component.ts / *.page.ts. Use the DSL Repository layer (defineEntity/toEntityService) instead."

### 1.3 Rule 2: `no-implements-oninit-in-pages`

**Цель:** Ban `implements OnInit` + `ngOnInit()` method combination в `frontend/src/app/pages/**/*.page.ts`.

**Scope:**
- `files: 'src/app/pages/**/*.page.ts'` в eslint.config.js.
- Self-filter: filename MUST end with `.page.ts`, MUST NOT end with `.spec.ts`, MUST contain `/pages/`.

**Что блокирует:**
- `class FooPage implements OnInit { ngOnInit() { ... } }` — both `implements` AND method present.
- Both bare `OnInit` и qualified `@angular/core.OnInit` (via `TSQualifiedName` AST check).

**Что разрешает:**
- Decorative `implements OnInit` без ngOnInit method (structural conformance only).
- `*.spec.ts` (testing fixtures).
- `*.component.ts` outside `pages/` (`shared/ui/pi-table.component.ts` — TZ-104.4.2 intentional OnInit).
- `*.service.ts` (infrastructure services may legitimately use OnInit).

**AST pattern:** `ClassDeclaration` visitor checks `implements[]` clause + `MethodDefinition` for `ngOnInit()`.

Verified by 7 test cases (4 valid + 3 invalid).

**Сообщения:**
- `onInitImplementation`: "`implements OnInit` is banned in *.page.ts. Migrate to `effect()` (signal-based) for reactive setup, or `inject(...)` in constructor for one-time DI. ngOnInit is reserved for infrastructure services per TZ-232 section 1.4."

## 5. Known limitations (carry-forward)

1. **AST obfuscation bypass (Rule 1):** `const h = this.http; h.get(...)` and `(this.http as any).get(...)` patterns slip past the literal MemberExpression/CallExpression checks. Frequency is low in mature TS codebases (TypeScript's `no-explicit-any` warning catches the second form). Carries as INTENTIONAL v1 limitation; future TZ-232.I.b could narrow.

2. **Disable annotation brittleness in `templates.page.ts`:** 5 line-level `// eslint-disable-next-line` annotations are fragile — file edits may shift line numbers and require re-annotation. TZ-232.F migration (scheduled per master plan §2.1 row 7) will refactor to `defineEntity`/`toEntityService` adapter and remove all 5 annotations atomically.

3. **`context.getFilename()` fallback chain:** ESLint 10 will deprecate `getFilename()`. Current code uses `context.filename || context.getFilename()`. Simplification possible in v10 migration.

4. **Pre-existing TSC errors in `builder.page.ts`:** `templateBlocksService.uploadImage` + `uploadRes` implicit-any. NOT introduced by TZ-232.I. UNRELATED. Already in archive as out-of-scope.
