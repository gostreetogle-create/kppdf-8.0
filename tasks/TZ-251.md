# TZ-251 — Backend Image Upload Endpoint for TemplateBlock

**Date:** 2026-07-28

## 0. Context

Pre-existing debt: `frontend/src/app/shared/services/pi-template-blocks.service.ts:uploadImage()` was added in a prior debt-cleanup session to consume the `POST /template-blocks/:id/upload` endpoint — but the backend endpoint was a forward-reference with no implementation. Builder photo upload worked session-only via local blob URLs that disappeared on page reload.

This TZ closes that carry-over debt by adding the matching backend endpoint.

## 1. Goal

Provide `POST /api/template-blocks/:id/upload` that accepts a multipart image, persists it under `./uploads/document-templates/<blockId>/`, and returns `{ url: '/uploads/document-templates/<blockId>/<uuid>.<ext>' }` so the frontend can patch `settings.imageUrl` from a local blob URL to a permanent path.

## 2. Decisions

| Question | Choice | Rationale |
|----------|--------|-----------|
| Storage | Multer + local filesystem | Matches `PhotosService` + `document-templates/upload-background` convention; simple; avoids MongoDB bloat |
| Storage layout | `./uploads/document-templates/<blockId>/<uuid>.<ext>` | Per-block subdirectory → easy orphan sweep via fs.rm in TZ-251.1 followup |
| MIME validation | `image/png`, `image/jpeg`, `image/webp` | Matches frontend `ALLOWED` list in `builder.page.ts:onPhotoFileSelected` |
| Size limit | 5 MB | Multer limit + service re-check (defense-in-depth) |
| URL format | Relative path | Frontend prepends `API_BASE_URL` from existing token; no `@nestjs/serve-static` required |
| Soft-delete sync | None — file persists on block soft-delete | Deferred to TZ-251.1 cleanup sweep |
| Auth | `@Roles('admin', 'manager')` | Mirrors existing write endpoints |
| Audit | `@AuditAction({ action: 'upload-image', entityType: 'TemplateBlock' })` | Project-wide convention (TZ-247 AuditInterceptor stack) |

## 3. Implementation

### 3.1 Modified files

**`backend/src/modules/template-block/template-block.service.ts`** (~80 LoC added)
- New imports: `BadRequestException`, `fs/promises`, `path/join`, `crypto.randomUUID`
- 4 module-level constants: `ALLOWED_IMAGE_MIME` (Set), `MIME_TO_EXT` (Record), `MAX_FILE_SIZE_BYTES`, `UPLOAD_URL_PREFIX`
- New method `uploadImage(blockId, file: Express.Multer.File): Promise<{ url: string }>`:
  1. Validates file exists (`BadRequest`)
  2. Validates MIME in whitelist (`BadRequest`)
  3. Validates size ≤ 5MB (`BadRequest`)
  4. Validates block exists via `findById` (`NotFound 404`)
  5. `mkdir -p` on `./uploads/document-templates/<blockId>/`
  6. `writeFile` with `randomUUID() + ext`
  7. Returns `{ url: /uploads/document-templates/<blockId>/<uuid>.<ext> }`

**`backend/src/modules/template-block/template-block.controller.ts`** (~30 LoC added)
- New imports: `BadRequestException`, `UploadedFile`, `UseInterceptors` from `@nestjs/common`; `FileInterceptor` from `@nestjs/platform-express`
- New endpoint `@Post('template-blocks/:id/upload')` with:
  - `@Roles('admin', 'manager')`
  - `@UseInterceptors(FileInterceptor('file', { limits: { fileSize: 5MB }, fileFilter: <MIME OR> }))`
  - `@AuditAction({ action: 'upload-image', entityType: 'TemplateBlock' })`
  - Delegates to `service.uploadImage(id, file)`

### 3.2 NEW files

**`backend/src/modules/template-block/template-block.service.spec.ts`** (~150 LoC, 9 unit tests)
- Mocks `@nestjs/mongoose` `Model<TemplateBlock>` with `jest.fn()` for `findById.exec()`
- Spies on `fs.mkdir` + `fs.writeFile` to avoid actual filesystem writes during unit tests
- Tests:
  1. PNG happy path → returns URL match + 1 mkdir call + 1 writeFile call
  2. JPEG → `.jpg` ext
  3. WebP → `.webp` ext
  4. text/plain MIME → `BadRequestException`
  5. empty file → `BadRequestException`
  6. file > 5MB → `BadRequestException`
  7. missing block → `NotFoundException`
  8. malformed ObjectId → `NotFoundException`
  9. validation failure → `writeFile NOT called`

**`backend/test/e2e/template-block-upload.e2e-spec.ts`** (~150 LoC, 4 e2e tests via supertest)
- Uses 1x1 transparent PNG buffer (mirrors `document-templates-upload-background.e2e-spec.ts`)
- Helper functions: `createTestTemplate` + `createImageBlock` (one-time setup per test)
- Tests:
  1. valid PNG → 201 + URL match `^/uploads/document-templates/<blockId>/<uuid>.png$`
  2. text/plain → 400 (fileFilter rejection)
  3. 6MB buffer → 413 (Multer limit via MulterExceptionFilter)
  4. non-existent block → 404 (findById throws)

## 5. Known limitations (carry-forward to TZ-251.1)

1. **DRY: duplicated MIME whitelist + size constant** between controller `FileInterceptor({fileFilter, limits})` and service `uploadImage()` body. Recommended fix: extract `IMAGE_MIME_WHITELIST` + `MAX_UPLOAD_BYTES` to `backend/src/common/upload-constants.ts` and import in both files.
2. **Soft-delete leaks files**: block `remove()` does `isActive: false` but doesn't remove uploaded file. After 50 block deletions, `uploads/document-templates/` accumulates orphans. Cleanup worker needed in TZ-251.1.
3. **E2E test pollution**: each `template-block-upload.e2e-spec.ts` run writes ~4 orphan PNGs into `uploads/document-templates/<blockId>/`. Cleanup helper needed in TZ-251.1.
4. **No `@nestjs/serve-static`**: files are persisted but not auto-served by NestJS. Today, the frontend has the relative URL but cannot directly fetch it. Either needs ServeStaticModule wiring OR a CDN/reverse-proxy in production. Not blocking for the TZ-251 contract; flagged as production deploy concern.
