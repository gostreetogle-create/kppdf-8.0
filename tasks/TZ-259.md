## Цель

Зафиксировать единый координатный и геометрический контракт, чтобы текстовые и другие рабочие блоки можно было предсказуемо перемещать и изменять по ширине/высоте, как в ReportBro, без поломки существующего flow-layout, таблиц и PDF-рендера.

## Что сделать

1. Провести read-only inventory реальных geometry-полей и режимов: flow-блоки, image overlay, `width`, `height`, `marginLeft`, `overlayLeft`, `overlayTop`, `imageWidth`, `imageHeight`, порядок и template page-size. Не придумывать поля, пока их нет в типах/schema.
2. Зафиксировать канонический контракт координат: `settings.layoutMode: 'flow' | 'positioned'`; для positioned-блоков `settings.geometry: { x, y, width, height }`, где все четыре значения — document-space CSS px от верхнего левого угла страницы. Для текущего canvas scale `1 CSS px = 1 document-space px`; при изменении масштаба пересчитывается только presentation layer. Базовые размеры страницы фиксируются как `A4 portrait = 794×1123`, `A4 landscape = 1123×794`, `A5 portrait = 559×794`, `A5 landscape = 794×559`, `Letter portrait = 816×1056`, `Letter landscape = 1056×816` CSS px (96 dpi; округление до целого). `x/y` и размеры округляются до целых неотрицательных значений, `width/height` имеют зафиксированные минимумы, а clamp учитывает эти канонические размеры. UI scale/scroll остаются только presentation coordinates. Существующие image-overlay поля (`overlayLeft`, `overlayTop`, `imageWidth`, `imageHeight`) обслуживаются через adapter и не переписываются массово в этой задаче.
3. Реализовать явный document-space ↔ rendered-canvas adapter рядом с `PiCanvasPage`/BuilderCanvas: все pointer coordinates переводятся через текущий rendered-to-document scale и scroll offset, а persisted geometry никогда не зависит от viewport width. Добавить backward-compatible positioned-модель для текстового блока по этому контракту. Legacy flow-блоки и записи без `geometry` продолжают отображаться без ручной миграции; включение positioned-режима должно быть явным действием пользователя или безопасным default только для нового блока.
4. Реализовать drag текстового блока в positioned-режиме и resize по ширине/высоте с boundary clamp, minimum size и отменой незавершённого жеста. Не превращать таблицы и многостраничный flow в абсолютные блоки без отдельного решения.
5. Сохранить optimistic update + текущий autosave/409 contract; при перезагрузке страницы геометрия должна восстановиться без drift. Для серверного сохранения использовать существующий endpoint/DTO-паттерн либо отдельное изменение API только при доказанной необходимости.
6. Обновить builder docs и типы. Добавить unit/component tests для координат, clamp, resize, reload/persistence и режима без geometry.

## Критерии приёмки

1. Новый или переведённый в positioned-режим текстовый блок можно выделить, перетащить и изменить по ширине и высоте; после reload persisted `x/y/width/height` совпадают с сохранённым document-space snapshot (0 px document-space drift; допускается только заранее определённое `Math.round()` при конвертации).
2. Тесты реального `PiCanvasPage`/BuilderCanvas adapter подтверждают document-space ↔ rendered-canvas conversion при scale 1, responsive scale и scroll offset: round-trip возвращает исходные document-space значения с 0 px drift после канонического `Math.round()`; блок не выходит за границы страницы и не становится меньше зафиксированного минимального размера; resize сохраняет валидные значения для portrait и landscape.
3. Существующие flow-блоки, таблицы, background/overlay images, reorder и PDF render проходят без изменения поведения.
4. Нет расхождения между локальным canvas preview и сохранённой geometry-моделью: один и тот же блок не «прыгает» после autosave.
5. Есть тесты на legacy block без geometry, positioned text block, drag, resize, clamp, сохранение и восстановление.
6. Frontend/backend typecheck, lint и релевантные tests проходят; документация отражает фактические поля, а не планируемые псевдонимы.
