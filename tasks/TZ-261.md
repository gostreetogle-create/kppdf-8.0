## Цель

Превратить существующий невидимый/частичный snap в понятную систему: пользователь видит клеточную сетку при включённом snap, получает направляющие к краям и центрам соседних блоков, а magnetic spacing применяется предсказуемо и не мешает свободному движению.

## Что сделать

1. Добавить canvas grid overlay через существующий builder canvas и design tokens: grid видна только когда snap enabled, не перехватывает pointer events, не попадает в print/PDF и не ухудшает контраст текста.
2. Расширить snap engine с текущего grid/edge snap до горизонтальных и вертикальных центров; выбирать ближайший кандидат детерминированно при конфликте нескольких кандидатов.
3. Показывать временные alignment guides на всём полезном участке страницы: edge/center различаются визуально, guides появляются только во время drag и исчезают на pointer up/cancel.
4. Добавить optional equal-spacing hint только когда есть подтверждённый кандидат; не менять положение автоматически при слабом совпадении и не добавлять «магии» без видимой подсказки.
5. Уважать boundary padding, scale/scroll canvas и positioned geometry из TZ-259. Не использовать hardcoded screen pixels, которые ломаются при zoom/scroll.
6. Покрыть pure snap calculations unit tests и canvas component tests; обновить docs с настройками threshold/grid/guide semantics.

## Критерии приёмки

1. При включённом snap grid видна на canvas, при выключенном — скрыта; ни один grid element не попадает в print output и не блокирует selection/drag.
2. Positioned-блок притягивается к ближайшему edge/center в пределах установленного threshold, а соответствующая guide line видна во время drag.
3. Guides исчезают после drop/cancel, не остаются в DOM как stale overlays и корректно работают при scroll/resize canvas.
4. В конфликте кандидатов результат стабилен; отключение snap возвращает свободное движение без непредсказуемого скачка.
5. Equal-spacing hint отображается только при валидной геометрии и не ломает relative positions группы.
6. Unit/component/visual tests и typecheck/lint проходят; есть ручной сценарий с пятью блоками без заметных drag-janks.

## Ограничения

Не копировать ReportBro и не добавлять GSAP/Anime.js. Не строить отдельный canvas renderer. Не вводить сложный constraint solver: достаточно edge/center/spacing candidates в текущем масштабе проекта.
