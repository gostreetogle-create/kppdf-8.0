## Цель

Проверить, что ReportBro-подобные взаимодействия образуют один понятный продуктовый workflow, а не набор разрозненных жестов: меню, выделение, перемещение, resize, snap, grouping, layers, opacity, undo/redo и preview должны быть предсказуемы для мыши, клавиатуры и screen reader.

## Что сделать

1. Зафиксировать короткий builder interaction contract: click/select, Shift/Ctrl multi-select, marquee, drag, resize, snap toggle, Escape/cancel, Delete, undo/redo, layers, lock и preview/print.
2. Дополнить component tests для BuilderPage/Canvas/BlockRenderer/Inspector/Toolbar и relevant dialogs. Проверять не только создание компонентов, но и пользовательские outputs/state transitions.
3. Добавить keyboard contract без конфликтов с input/textarea/contenteditable: arrows/nudge только при фокусе builder, Delete с безопасным подтверждением, Ctrl/Cmd+Z/Y, Escape и доступные focus states.
4. Проверить меню и dropdowns: trigger keyboard support, focus return, outside click, Escape close, loading/error/empty states, no accidental duplicate requests.
5. Выполнить route-level smoke сценарий через существующий Jest/Angular test harness (и Playwright только если он уже подключён): direct URL, empty template, five blocks, selected group, locked layer, opacity 0/1, snap on/off, print mode, save error and reload. Не заявлять отдельный E2E runner, если его нет в репозитории.
6. Обновить `docs/pages/builder.page.md` фактическим состоянием и checklist для нового блока. Удалить из документации утверждения о незавершённых/несуществующих task-файлах, если код уже изменился.

## Критерии приёмки

1. Есть component tests для основных builder interactions и минимум один browser smoke flow для selection → move → resize → save → reload → preview/print.
2. Keyboard and focus behavior не активирует destructive/editor actions внутри text inputs; Escape и focus return работают для dropdowns/dialogs.
3. Accessibility audit не выявляет blocker-нарушений для selection, drag/resize handles, guides, layers, opacity controls и status/errors.
4. Visual regression covers empty, normal, selected, multi-selected, snapping and locked states without stale overlays.
5. Builder documentation matches real inputs/outputs/endpoints and clearly separates implemented, partial and planned capabilities.
6. Frontend tests, typecheck, lint and the documented smoke command pass; результаты зафиксированы в progress/STATUS workflow.

## Ограничения

Не добавлять новый UI framework, broad redesign или performance benchmark suite без симптома. Не объявлять builder production-ready только по unit tests: route-level smoke и save/reload scenario обязательны.
