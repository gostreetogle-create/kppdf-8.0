## Цель

Дать пользователю надёжную отмену и повтор действий в конструкторе, чтобы перемещение, resize, grouping, reorder и изменения свойств не превращались в необратимые ошибки.

## Что сделать

1. Ввести component-scoped history service с bounded undo/redo stacks и сериализуемыми snapshots только для поддерживаемых builder mutations: block geometry/settings/order и template settings. Не хранить DOM, File, Blob, token или необязательный runtime state.
2. Публично определить `record`, `undo`, `redo`, `canUndo`, `canRedo`, `clear` и один transaction boundary для drag/resize/group operation. Серия pointer-moves одного жеста = одна history entry; незавершённый/cancelled жест = ноль entries.
3. После undo новая mutation очищает redo stack. Установить bounded depth 50 и защитить snapshots от последующей мутации через immutable clone/serialization по существующему проектному паттерну.
4. Добавить Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z и Ctrl/Cmd+Y только при фокусе builder; не перехватывать input, textarea, select и contenteditable. Escape отменяет активный жест, но не должен неожиданно очищать сохраненную history.
5. Применять восстановленный state через существующий optimistic/autosave contract без N лишних запросов на одну операцию; обработать save error/409 с понятным состоянием и без потери последнего локального snapshot.
6. Добавить unit/component tests и обновить builder docs. Не смешивать undo с browser navigation и не обещать server-wide collaborative history.

## Критерии приёмки

1. Add/update/move/resize/reorder/group mutation можно отменить и повторить; итоговый state после undo+redo идентичен исходному snapshot.
2. Один drag/resize/group gesture создаёт одну запись, 20 движений мыши не создают 20 записей; cancelled gesture не создаёт запись.
3. После новой mutation redo недоступен; history depth не превышает 50.
4. Ctrl/Cmd shortcuts работают на canvas и не ломают ввод текста/форм controls; Escape корректно отменяет активный жест.
5. Undo/redo не записывает DOM/runtime-only values и сохраняет совместимость с autosave/409 handling.
6. Есть tests для stack limits, transaction boundary, keyboard guards, cancel, redo invalidation и representative builder mutations; frontend checks проходят.

## Ограничения

Не добавлять серверную историю, collaborative editing, event sourcing, Redis или новый state-management framework. Не переиспользовать идентификатор `TZ-235.C` для undo: inspector extraction остаётся отдельным завершённым историческим/архитектурным срезом в `tasks/_archive/2026-07/TZ-235.C-builder-inspector-decompose.md.done`.
