## Objective

Provide a NestJS middleware that intercepts mutating requests (`POST/PUT/PATCH/DELETE`) carrying an `Idempotency-Key` header. Records are persisted in MongoDB and replayed on subsequent requests if the request fingerprint matches. Mismatched fingerprints return 409. Auth and health endpoints bypass.

## Test #4 fingerprint-mock bug

Initial test #4 used `expect.stringMatching(/^[a-f0-9]+$/)` as a placeholder for the cached `requestFingerprint`. Jest matchers are unresolved objects, not hex strings, so the `!==` deep-equal always returned true and the test fell into the 409 branch. **Bug was in the test mock, not production middleware.** Fix: replaced with literal SHA-256 hex `d0a028cd092ac938b4b4b05fe3896568837e164169746dfc3a2572a11e31a1dd` (matches what the middleware computes for body `{x:1}` on path `/api/foo`, method POST). Inline comment explains why literal hex is required.

## Known limitations / Deferred to TZ-247.A

1. **main.ts wiring:** middleware is shipped but not mounted in production. To activate, `IdempotencyStorageModule.forRoot()` must be imported in `app.module.ts`, and `consumer.apply(IdempotencyMiddleware).forRoutes('*')` must be added in a NestJS configure() or in main.ts via express `app.use()`.
2. **E11000 race handling:** two concurrent requests with same idempotency key both pass `findByKey === null`, both reach `insert()`. The unique index guarantees only one succeeds, but the loser's Mongo error is currently swallowed by `.catch()`. Future TZ-247.A should catch E11000 → re-fetch → replay cached.
3. **app.use() integration smoke test:** jest covers middleware logic in isolation. No supertest/Express-integration smoke test against a real NestJS app — production behavior unverified end-to-end.
