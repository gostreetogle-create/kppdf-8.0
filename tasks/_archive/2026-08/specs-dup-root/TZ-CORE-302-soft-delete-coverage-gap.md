# TZ-CORE-302: soft-delete — закрыть схемы без deletedAt и без opt-out

> Источник: внешний аудит (сессия Claude/Cowork 2026-08-22, файл `tasks/аудит.txt`)
> + перепроверка кода в этой же сессии. Аудит цитировал баг из
> `docs/architecture-audit-2026-07.md` (5 июля) как «плагин ломает выборки на
> ВСЕХ 67 схемах» — это устарело: плагин с тех пор получил explicit opt-out
> (`softDelete: false`) и дубль `pre('find')`-хука убран. Но rollout не полный.

РОЛЬ АГЕНТА: Backend Developer

ЗАВИСИМОСТИ: Нет

LAYER: 4 (backend)

CONFLICT KEYS: `backend/src/database/soft-delete.plugin.ts` ; список схем ниже (по одному коммиту на пачку, не одним махом — см. ШАГ 2)

Проверено (эта сессия, 2026-08-22):
- Схем всего: 90. С полем `deletedAt`: 20. С explicit `softDelete: false`: 9.
- **61 схема** не имеет ни `deletedAt`, ни `softDelete: false` — таких схем плагин
  не ломает на простых `find`, но по комментарию в самом плагине (`soft-delete.plugin.ts`)
  бросает ошибку Mongoose strict mode на **upsert**, если фильтр содержит `deletedAt`.
- `RegisterDto.role` (аудит считал critical hole) — **уже исправлено**: whitelist
  `@IsIn(['user','manager'])`, admin невозможен через `/register` (TZ-91/TZ-95).
- Дублирующийся `pre('find')`-хук — **уже исправлено**: в текущем файле хук
  регистрируется 1 раз.

## ЧТО ДЕЛАТЬ

### ШАГ 1: Список 61 схемы

`grep -rlL "deletedAt" backend/src --include="*.schema.ts" | grep -vFf <(grep -rl "softDelete: false" backend/src --include="*.schema.ts")`
— получить точный список, приложить к отчёту.

### ШАГ 2: Для каждой схемы — решение, не шаблон

Для каждой из 61: посмотреть, это бизнес-сущность (нужен soft-delete → добавить
`deletedAt: { type: Date, default: null }` в схему + индекс) или системная/справочная
(role, permission, counter, feature-flag, audit-log, rate-limit — им soft-delete не
нужен → добавить `{ softDelete: false }` в `@Schema({...})`, как уже сделано для
9 других). Не добавлять `deletedAt` бездумно всем подряд — это ручное решение по
каждой схеме, не механическая правка одной строкой на 61 файл разом.

Разбить на пачки по домену (склад, снабжение, справочники и т.д.), коммитить
по пачке — не один гигантский дифф на 61 файл.

### ШАГ 3: Тест на регресс

Один интеграционный тест: schema без `deletedAt` и без opt-out **не должна**
существовать после этой TZ (список из ШАГ 1 должен стать пустым) — можно
оформить как unit-тест, который grep'ает `*.schema.ts` и падает, если находит
схему без одного из двух признаков (защита от будущего дрейфа).
