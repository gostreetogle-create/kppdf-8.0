# TZ-OPS-317: git показывает ~3000 «изменённых» файлов из-за переносов строк — почистить

> Источник: перепроверка внешнего аудита (сессия Claude/Cowork 2026-08-22).
> Аудит этого не заметил — он не смотрел `git status`. Найдено отдельно в этой
> сессии и подтверждено: это НЕ реальные правки, а разница в переносах строк
> (CRLF/LF), `.gitattributes` в репозитории нет вообще.

РОЛЬ АГЕНТА: любой executor с доступом к `D:\kppdf-8.0` (важно — см. СТОП ниже)

ЗАВИСИМОСТИ: Нет, но см. условие запуска

LAYER: repo-wide (единолично, см. ниже — это НЕ Layer 3 «один файл», это «весь репозиторий разом»)

Проверено (эта сессия):
- `git status --porcelain` → 3000 строк `M` (почти весь репозиторий: tasks, docs,
  backend, frontend, OrchestratorKit, .mimocode и т.д.), плюс 58 untracked, 8 deleted.
- `git diff -- .gitignore` → показывает 166 из 166 строк изменёнными.
- `git diff -b -- .gitignore` (игнорируя пробелы/переносы) → **пусто**, разницы нет.
- `.gitattributes` в корне — отсутствует. `core.autocrlf` — нигде не задан (ни
  локально, ни глобально на этой машине).
- Origin **синхронизирован**: `git rev-list --left-right --count origin/main...main`
  → `0 0`. Это опровергает главный вывод аудита («риск потери всего проекта,
  единственная машина без пуша») — репозиторий реально запушен на GitHub
  (`gostreetogle-create/kppdf-8.0`) и актуален.

---

## ПОЧЕМУ ЭТО ВАЖНО, А НЕ КОСМЕТИКА

Пока `git status`/`git diff` показывают 3000 «изменённых» файлов, которые на
самом деле не изменены — невозможно быстро увидеть **реальные** незакоммиченные
правки среди этого шума. Это прямой риск: кто-то (человек или агент) закоммитит
что-то лишнее вместе с этим шумом, не заметив, или наоборот — не заметит реальную
правку в этом шуме и потеряет её при откате.

## ЧТО ДЕЛАТЬ

### ШАГ 1: Условие запуска — читать перед стартом

Эта TZ трогает **весь repo** одним нормализующим коммитом. Нельзя запускать,
пока в `tasks/_active/` есть хоть один claim другого агента (проверить перед
стартом) — иначе нормализация конфликтует с чужим in-flight diff. Если
`_active/` не пуст — DEFER, попробовать позже.

### ШАГ 2: `.gitattributes`

Добавить в корень:

```text
* text=auto eol=lf
*.{png,jpg,jpeg,gif,ico,pdf,zip,exe,gguf,woff,woff2} binary
```

(список binary-расширений сверить с реальными типами файлов в репо — не гадать,
пройтись по `git diff --stat` после ШАГ 3 и убедиться, что бинарники не попали
в text-нормализацию).

### ШАГ 3: Один нормализующий коммит

```text
git add --renormalize .
git status   # ожидается: только реальные построчные изменения, шум ушёл
git commit -m "chore: normalize line endings (LF) via .gitattributes"
```

Проверить `git status --porcelain | wc -l` **до** и **после** — до должно быть
~3000+, после — 0 (плюс уже реально незакоммиченные вещи, если были).

### ШАГ 4: Push

Обычный push этого одного коммита — он не «деплой» и не «wipe», это чистка
истории, permission не нужен по `docs/GIT-POLICY.md` (см. канон, не выдумывать
новое правило).

## КРИТЕРИИ ПРИЁМКИ

1. `git status --porcelain | wc -l` после коммита = 0 (без учёта реально новых правок).
2. Бинарные файлы (картинки, `.gguf` модели, шрифты) не попали под текстовую
   нормализацию — проверить `git diff --stat` перед коммитом.
3. `pnpm architecture:check`, backend/frontend `tsc --noEmit` — PASS (нормализация
   переносов строк не должна ничего сломать функционально).
4. Один коммит, не десятки — легко откатить, если что-то не так.

known_limitation: после этой TZ каждый агент/человек на Windows должен иметь
`core.autocrlf=true` в своём git config, иначе шум вернётся при следующем checkout
— стоит упомянуть в `docs/how-to-connect-ai.md` одной строкой (не обязательно
в этой TZ, но не забыть).
