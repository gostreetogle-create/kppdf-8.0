═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. `TemplateSetupDialogComponent` открывается из `BuilderPage.onCreateTemplate()` и из `TemplatesPage.onCreate()`.
2. `TemplateSetupDialogComponent.onConfirm()` вызывает `ref.close(result)`.
3. В `BuilderPage` после результата запускаются запросы организации/типа документа, затем создание шаблона и навигация.
4. Наблюдение пользователя: после одного нажатия «Создать» шаблон уже появляется созданным в фоне, но окно настройки остаётся видимым. Пользователю приходится дополнительно нажимать крестик или вне диалога.
5. Это создаёт риск повторной отправки (двойной submit) и визуально показывает устаревшее состояние.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Воспроизвести проблему отдельно для двух входов: `/doc-constructor/builder` и `/doc-constructor/templates`. Зафиксировать, закрывается ли overlay сразу после подтверждения, не зависит ли результат от скорости API и не возникает ли второй POST при двойном клике.

ШАГ 2: Проследить полный lifecycle `DialogRef.closed` → `onDialogCloseOnce` → `onCreateTemplate/createWithSettings` → POST → navigation. Исправить минимально только тот слой, который подтверждён причиной. Закрытие должно происходить ровно один раз при первом подтверждении, а Cancel/Escape/backdrop не должны запускать создание.

ШАГ 3: Добавить регрессионные unit-тесты на подтверждение и отмену. Если проблема зависит от CDK overlay/browser timing, добавить отдельный ручной сценарий и тестировать observable/signal-контракт без хрупкой проверки внутренних DOM-деталей.

ШАГ 4: Проверить loading/disabled состояние: после подтверждения повторное нажатие не должно создавать второй шаблон; при ошибке API окно не должно самопроизвольно открываться снова.

РУЧНОЙ СЦЕНАРИЙ ПРОВЕРКИ
═══════════════════════════════════════════════════════════════

1. Запустить приложение (`node start.mjs`).
2. Войти администратором.
3. Перейти на /doc-constructor/builder.
4. Нажать «Создать шаблон».
5. Заполнить обязательные поля и нажать «Создать».
6. Убедиться, что диалог закрывается автоматически после успешного создания.
7. Повторить шаги 3-6 для /doc-constructor/templates.
8. Нажать «Отмена» или Escape — убедиться, что шаблон НЕ создаётся.
9. Нажать «Создать» дважды быстро — убедиться, что создаётся только один шаблон.
10. Имитировать ошибку API (отключить backend) — убедиться, что диалог остаётся открытым с сообщением об ошибке.
