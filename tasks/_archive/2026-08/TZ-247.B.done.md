## Objective

Eliminate the **duplicate-key race** in `IdempotencyStorageService.insert()`. Two concurrent POSTs with the same `Idempotency-Key` would both pass `findByKey === null` and both reach the persistence path; the unique-index winner's body was previously the loser's view, double-execution risk. This task added an `insertOrFetch(record)` API that always returns the canonical (winner's) record.
