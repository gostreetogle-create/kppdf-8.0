═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. Фронтенд dev-сервер НЕ компилируется. `ng serve` падает с NG5002 /
   TS2339 / TS2531 в трёх admin-диалогах из-за TypeScript-кастов `as`
   ВНУТРИ выражений Angular templates (template expression не
   поддерживает `as` — это синтаксис TS, а не Angular).

2. Проблемы / неточности текущего состояния:
   - `user-form-dialog.component.ts` — 6 выражений вида
     `(input)="username.set(($event.target as HTMLInputElement).value)"`
     (строки 56, 67, 79, 92, 104, 118).
   - `role-form-dialog.component.ts` — 3 выражения `as HTMLInputElement`
     (строки 65, 80, 91).
   - `reset-password-dialog.component.ts` — 2 выражения `as HTMLInputElement`
     (строки 45, 57).
   - Доказательство (лог `ng serve`, 2026-08-02):
     ```
     ✘ [ERROR] NG5002: Parser Error: Missing closing parentheses at column 25
       in [role.set(($event.target as HTMLSelectElement).value)]
       .../user-form-dialog.component.ts@103:24
     ✘ [ERROR] TS2339: Property 'value' does not exist on type 'EventTarget'.
       TS2531: Object is possibly 'null'.
     Watch mode enabled. Watching for file changes...
     ```
   - HTTP :4200 недоступен (curl → 000). Бэкенд и Mongo — up
     (GET /api/health: `{"status":"ok","info":{"mongo":{"status":"up"}}}`).
   - Важно: `tsc --noEmit` проходил (exit 0), потому что tsc НЕ проверяет
     templates. Это известный класс багов, задокументированный в TZ-86 F.6:
     «tsc --noEmit запускает только TypeScript — он НЕ вызывает Angular
     template typecheck. Только ng serve / ng build ловили этот класс багов».

3. Контекст (внешние зависимости, conventions, нюансы):
   - Проектная конвенция обработки input-событий — методы-обработчики
     в компоненте (см. `onSearchInput(event)` в materials/products/orders
     pages, `shared/dsl/entity-list`). Каст `as` легален в теле метода
     `.ts`-файла, но НЕ в template expression.
   - Диалоги открываются через `PiDialogService.open(...)`; шаблон —
     `PiDialogComponent` (variant=form), инпуты которого
     (`title/width/showClose/animate/variant`) уже корректны.
   - Тест `users-admin.page.spec.ts` (5/5 PASS) мокает HTTP и НЕ компилирует
     диалоги — поэтому баг прошёл незамеченным.

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: Добавить в каждый из 3 диалогов приватные методы-обработчики
       событий, переносящие каст из template в тело метода.

  Для `user-form-dialog.component.ts` добавить (аналогично для
  displayName/email/password/role/isActive):

    protected onUsernameInput(event: Event): void {
      this.username.set((event.target as HTMLInputElement).value);
    }
    protected onRoleChange(event: Event): void {
      this.role.set((event.target as HTMLSelectElement).value);
    }
    protected onActiveChange(event: Event): void {
      this.isActive.set((event.target as HTMLInputElement).checked);
    }

  Для `role-form-dialog.component.ts`:
    protected onNameInput(event: Event): void {
      this.name.set((event.target as HTMLInputElement).value);
    }
    (+ onLabelInput / onDescriptionInput по аналогии)

  Для `reset-password-dialog.component.ts`:
    protected onPasswordInput(event: Event): void {
      this.password.set((event.target as HTMLInputElement).value);
    }
    protected onConfirmInput(event: Event): void {
      this.confirm.set((event.target as HTMLInputElement).value);
    }

ШАГ 2: Заменить ВСЕ inline-выражения в templates трёх файлов на вызовы
       методов:

  Шаблон ДО (пример из user-form-dialog):
    (input)="username.set(($event.target as HTMLInputElement).value)"
    (change)="role.set(($event.target as HTMLSelectElement).value)"
    (change)="isActive.set(($event.target as HTMLInputElement).checked)"
  Шаблон ПОСЛЕ:
    (input)="onUsernameInput($event)"
    (change)="onRoleChange($event)"
    (change)="onActiveChange($event)"

  Итог: в трёх файлах не должно остаться НИ ОДНОГО `as` внутри
  `template:` (проверка: grep 'target as HTML' по template-строкам = 0).

ШАГ 3: Проверка компиляции templates (ОБЯЗАТЕЛЬНО, т.к. tsc их не ловит):
       cd frontend && pnpm exec ng build --configuration=development
       (или `pnpm start` до «Watch mode enabled» без ошибок).
