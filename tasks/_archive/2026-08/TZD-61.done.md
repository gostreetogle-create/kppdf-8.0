## ИСХОДНОЕ СОСТОЯНИЕ

1. Три разных понятия — (а) паринг-ключ с сайта, (б) MCP host для внешних клиентов
   (Cursor/LM Studio), (в) локальная AI-модель для подбора колонок при импорте — физически
   не разделены по вкладкам так, как их называет документация, и никак не объяснены
   пользователю в моменте (нет «зачем мне это» на самих вкладках).
2. Пользователь, скачавший «AI», ожидаемо ищет чат — визуально это не опровергнуто явно.
3. Документация (`INSTALL.md`) называет вкладку паринга «MCP», хотя в коде и в UI это
   «Подключение» — расхождение сбивает и PO, и любого нового агента, читающего доку
   до кода.

## ЧТО ДЕЛАТЬ

### ШАГ 1: Синхронизировать доку с реальными подписями вкладок

В `INSTALL.md`, `MCP.md`, `PAIRING.md` — везде, где вкладка названа «MCP», заменить на
фактическую подпись **«Подключение»** (с уточнением в скобках при первом упоминании:
«Подключение (паринг + MCP host)», чтобы не потерять смысл). Не переименовывать саму
вкладку в коде на этом шаге — сначала синхронизировать доку с существующей правдой.

### ШАГ 2: Пояснить вкладку «AI» на месте, без чата

На вкладке `'ai'` (после баннера `:2121`, до карточки «Локальная модель») добавь одну
короткую строку, прямо отвечающую на ожидание «где чат»: например «Это не чат — модель
работает в фоне и подсказывает сопоставление колонок на вкладке «Импорт»." Без новых
компонентов/состояния — чистая правка `<p>`/hint-текста рядом с существующим баннером.

### ШАГ 3: Единая последовательность «с чего начать»

Добавь в `desktop/docs/INSTALL.md` (в начало, до текущего раздела «Что ставить клиенту»)
короткий нумерованный список: 1) сайт → «Подключить десктоп» → «Выпустить ключ»
(`PAIRING.md`); 2) вставить пакет во вкладке «Подключение» Desktop; 3) (опционально,
если нужен внешний AI-клиент типа Cursor) MCP host там же → «Скопировать mcp.json»
(`MCP.md`); 4) (опционально, для помощи при импорте) вкладка «AI» → скачать модель
(`AI-PROVIDERS.md`). Каждый пункт — ссылка на соответствующий файл. Это единственная
задача этого шага — переставлять существующий текст доков не нужно, только добавить
оглавление-последовательность и перелинковать.

### ШАГ 4 (опционально, если время/scope позволяют — не обязателен для DONE)

Если правка ШАГ 1 делает подпись вкладки в коде откровенно вводящей в заблуждение —
зафиксируй как **отдельный findings-пункт** в отчёте (не переименовывай `'Подключение'`
в самом коде в этой TZ — переименование видимого текста кнопки затрагивает
`data-test="tab-connection"`-зависимые тесты и e2e, это отдельная TZ с своим scope).
