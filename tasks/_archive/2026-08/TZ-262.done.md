═══════════════════════════════════════════════════════════════
ИСХОДНОЕ СОСТОЯНИЕ
═══════════════════════════════════════════════════════════════

1. Frontend-гейты admin-страниц НЕ совпадают с backend-правами:

   - Route `/admin/users` (`app.routes.ts`): `data: { capabilities:
     ['user:read'] }`; nav-элемент («Пользователи») — `capabilities:
     ['user:read']`.
   - Backend `GET /api/admin/users` (`users-admin.controller.ts`):
     `@Permissions('user:admin')` + `@Roles('admin')`. Т.е. список
     пользователей доступен только с `user:admin`.

   Результат: пользователь с `user:read`, но БЕЗ `user:admin`, проходит
   frontend-гейт (видит пункт меню «Пользователи» и открывает страницу),
   но получает 403 от backend — страница бесполезна, «тупик UX».

   - Route `/admin/roles`: `capabilities: ['role:read']`; nav — `role:read`.
   - Backend `GET /api/admin/roles`: `@Permissions('role:read')` +
     `@Roles('admin')` — здесь совпадает (роль admin всегда проходит
     hierarchy `admin > manager > user`). Проблема только у `/admin/users`.

2. Проблемы / неточности текущего состояния:
   - Несоответствие frontend capability-гейта и backend permission для
     `/admin/users`: гейт `user:read` vs backend `user:admin`.
   - Нарушается контракт TZ-256 §0: «FRONTEND VISIBILITY = UX» — гейт
     должен скрывать то, что backend всё равно запретит 403.

3. Контекст (внешние зависимости, conventions, нюансы):
   - `CapabilitiesService.hasAny()` — OR-семантика (любой ключ из списка).
   - Backend — authority (TZ-255). Frontend-гейт — только UX-видимость.
   - Системные роли: admin автоматически имеет все capability
     (см. комментарий в capability-route.guard.ts).

═══════════════════════════════════════════════════════════════
ЧТО ДЕЛАТЬ
═══════════════════════════════════════════════════════════════

ШАГ 1: В `app.routes.ts` изменить гейт маршрута `/admin/users`:

  data: { capabilities: ['user:read'] }  →  data: { capabilities: ['user:admin'] }

  (поле `capabilities` — массив, оставить OR-семантику; `user:admin`
  покрывает список, создание, редактирование, удаление — см. backend).

ШАГ 2: В `app-layout.component.ts` изменить capability nav-элемента
       «Пользователи» (категория `admin`):

  capabilities: ['user:read']  →  capabilities: ['user:admin']

ШАГ 3: Проверить, что `/admin/roles` (route + nav) остаются
       `role:read` — они соответствуют backend `GET /admin/roles`
       (`@Permissions('role:read')`). Если найдено другое расхождение
       с конкретным endpoint — зафиксировать в комментарии TZ, НЕ менять
       без доказательства.

ШАГ 4: Вручную проверить два профиля (после TZ-261):
       - роль `admin` → видит «Пользователи», открывает страницу, данные
         грузятся (200).
       - роль `manager` с permission `user:read` (без `user:admin`) →
         пункт «Пользователи» скрыт, прямой переход на `/admin/users`
         редиректит на `/forbidden`.
