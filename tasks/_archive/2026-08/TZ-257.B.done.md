## Summary

TZ-257.B asked for two hardening items on the `/api/admin/*` surface:

1. **DTO-whitelist on admin mutations** — the admin surface must never accept
   internal/privilege fields from the client. New `AdminCreateRoleDto` /
   `AdminUpdateRoleDto` (`backend/src/modules/admin/dto/admin-role.dto.ts`)
   declare ONLY `name` (create) / `label` / `description` / `permissions`.
   Internal fields (`isSystem`, `sortOrder`, `sectionIds`, `isActive`) are not
   declared, so the global `ValidationPipe({ whitelist: true,
   forbidNonWhitelisted: true })` rejects any attempt to smuggle them with 400
   BEFORE the controller/guard layer runs — defence in depth on top of
   `SystemRoleGuard`'s `SYSTEM_ROLE_ESCALATION`. `roles-admin.controller.ts`
   mutations switched from the legacy role DTOs to the admin DTOs;
   `AdminUpdateRoleDto` deliberately has no `name` (the dialog locks names on
   edit, so renames are not offered on the admin surface).

2. **Permission catalog + UI** — new read-only endpoint
   `GET /api/admin/permissions` (`permissions-admin.controller.ts`) serves the
   canonical `PERMISSIONS` constant (the single source of truth used by the
   seeder, `PermissionsBootValidator` and role validation) grouped by `section`:
   `{ sections: [{ section, permissions: [{ key, action, description }] }] }`.
   Gated by the global guard stack + `@Permissions('role:read')` +
   `@Roles('admin')`; no DB round-trip, no audit (read-only). Registered in
   `admin.module.ts`.

   Frontend: `pi-permissions.service.ts` (`PermissionsCatalogService` +
   `silentGet`) fetches the catalog; `role-form-dialog.component.ts` was
   rewritten to render a checkbox catalogue grouped by section — editors pick
   from the REAL permission keys instead of free-typing, with per-section
   «все»/«снять все» toggles, selected-count, loading/error states, and
   JetBrains-Mono key + description columns. `roles-admin.page.ts` edit path
   now sends ONLY `{ label, description, permissions }` (strips the dialog's
   locked `name`) to satisfy `forbidNonWhitelisted`.
