# PROMPT — Единый «Редактор таблицы» КП (merge Состав + Таблица)

Скопируй блок ниже в чат с сильной моделью (vision/UX). Цель ответа: готовая концепция + wireframe-канон + критерии приёмки, без кода. Фото на A4 — в хвост волны, не в первый экран дизайна.

## Промпт (копировать отсюда)

Ты — не разработчик «фич ради фич». Ты — **менеджер отдела продаж**, который **каждый день** собирает коммерческие предложения в цеховом ERP (kppdf): выбирает шаблон бланка, кидает изделия из каталога, правит кол-во/цены/скидки, смотрит превью A4, шлёт клиенту. Завтра ты будешь показывать экран коллегам — стыдно за кашу нельзя.

### Контекст «как сейчас» (факт)

В Create КП справа два соседних инструмента:

1. **Состав КП** — широкая таблица строк: порядок ↑↓, имя, qty, ед., цена, %, сумма, опциональность, карандаш в каталог, удалить, «Своя строка» внизу. Это место **данных**.
2. **Таблица этого КП** (Table Studio) — почти ширина A4: рамка/шапка, порядок и видимость колонок, % ширины, живая таблица тех же строк (qty/цена тоже правятся). Это место **вида экземпляра** (copy-on-write; общий TableTemplate в Документах не трогаем).

Центр экрана = **A4 только смотреть** (sandboxed HTML), не кликать ячейки на листе.

Боль: два меню про одно и то же → дубль внимания, «куда идти править», менеджер путается. Qty уже есть и в Составе, и в студии. Фото в колонке бланка — отдельная боль (можно отложить на конец).

### Задача

Спроектируй **один** правый инструмент с правильным именем:

**«Редактор таблицы»** (не «Состав» и не «Таблица этого КП» в двух кнопках).

Он **объединяет** всё полезное из обоих экранов **без дубля**:

- одна живая таблица позиций этого КП;
- правки qty / цена / сумма / скидка / опц / своя строка / порядок / удалить / карандаш каталога;
- настройки вида экземпляра (колонки видна/скрыта/порядок/ширина %, рамка, вес шапки, «добавить поля КП», ссылка открыть пресет в Документах — без тихой записи в shared template);
- визуально: меню настроек ≠ данные строк (toolbar / strip отделены hairline/фоном);
- компактность Paper & Ink: минимум chrome, максимум пользы; flyout ≈ ширина A4 или чуть уже, но не 20rem-карточки;
- интуиция с первого взгляда: «сюда кладу позиции и здесь же решаю, как они выглядят на бланке»; A4 справа/в центре сразу отражает изменения.

Правый рейл после merge: **Параметры → Редактор таблицы → Условия** (одна кнопка вместо двух). Слева без изменений: Шаблон · Товары · Получатель.

### Жёсткие ограничения

- Не предлагай править прямо внутри iframe A4.
- Не предлагай полный конструктор колонок Документов (типы, формулы) внутри КП.
- Не пиши в shared TableTemplate молча.
- Не предлагай второй параллельный write-path строк.
- DnD строк — опционально позже; стрелки ↑↓ ок для v1.
- Язык UI — русский.
- Дизайн: спокойный, цеховой ERP, без «дашборд-карточек», без фиолетовых градиентов, без мусорных badges.

### Как думать (обязательно)

1. Пройди сценарий менеджера вслух: пустой КП → добавить 5 изделий → своя строка «доставка» → спрятать артикул → ужесточить рамку → поменять qty → глянуть A4 → отправить.
2. Найди, где сейчас лишний клик / двойной смысл.
3. Предложи **одну** компоновку «Редактора таблицы» (ASCII или чёткий блочный макет): что сверху, что в таблице, что редкое уезжает в «Ещё».
4. Явно напиши, **что выкидываем** из двух старых панелей (дубли), а что оставляем один раз.
5. Фото на бланке: коротко «как должно быть в конце», но **не** раздувай первый экран этим.

### Формат ответа (строго)

1. **Одной фразой** — север: что такое «Редактор таблицы» для менеджера.
2. **Макет** — блоки сверху вниз (toolbar / strip / live table / footer).
3. **Карта действий** — таблица: действие менеджера → где в редакторе → что на A4.
4. **Рейл** — итоговые кнопки справа и подписи (RU).
5. **Антипаттерны** — 5 вещей, которые нельзя сделать в этом экране.
6. **Критерии приёмки** — 8–12 проверяемых пунктов «готово для показа коллегам».
7. **Порядок внедрения** — 2–3 тонких шага (сначала merge UI, потом полировка, фото в хвост).

Не пиши код. Не предлагай микросервисы. Думай как человек за мышью восемь часов в день.
