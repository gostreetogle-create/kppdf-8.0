## Summary

TZ-256.B asked for the real `/admin` body: CRUD/mutation dialogs for Users + Roles + Audit actions. Users CRUD was shipped by TZ-257.A.1 (create/patch/activate/deactivate/delete + reset-password + LastAdminGuard + dialogs + 5 tests). This task closes the Roles remainder:

1. **Backend** — `roles-admin.controller.ts` gains `POST /`, `PATCH /:id`, `DELETE /:id`:
   - `@Permissions('role:write')` (create/patch) / `@Permissions('role:admin')` (delete) + `@Roles('admin')`.
   - `@UseGuards(SystemRoleGuard)` on PATCH/DELETE — refuses system-role mutation (`SYSTEM_ROLE_FROZEN`) and escalation patches (`SYSTEM_ROLE_ESCALATION`).
   - POST always forces `isSystem: false` regardless of payload (system roles are seed-bootstrapped only, TZ-257 §ШАГ 0).
   - Audit contract: `admin.role.created` / `admin.role.updated` (idParam) / `admin.role.deleted` (idParam).
   - `ClientRole` mapper gained `label` (display name) — the frontend table renders it; fallback to `name`.
   - Delegates to existing `RoleService.create/update/remove` (rename cascade + cache invalidation already handled).
2. **Frontend** — `roles-admin.page.ts` full rewrite:
   - «Создать роль» button → `role-form-dialog.component.ts` (name slug locked on edit, label, description, permissions comma-list).
   - Per-row edit/delete via `PiRowActionsComponent`; system roles render `read-only` with actions hidden.
   - All HTTP through `silent-*` helpers; `refresh()` after every mutation.
   - 403 mapping: `SYSTEM_ROLE_FROZEN` / `SYSTEM_ROLE_ESCALATION` → «Системные роли доступны только для чтения».
3. **Tests** — `roles-admin.controller.spec.ts` (5 tests: create isSystem-forcing, update/remove delegation, list/getById mapping); `mapper` label covered via assertion.
