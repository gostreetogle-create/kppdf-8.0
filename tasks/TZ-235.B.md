# TZ-235.B — block-renderer: extract state into per-instance service

**Branch:** `freebuff/new-thread-thms6ee2rx5i1q`
**Status:** Planning
**Depends on:** TZ-235.A R3 (shipped — same pattern applied to `builder.page.ts`)

---

## Цель (простым языком)

`block-renderer.component.ts` — это «листик» (leaf-компонент), он рисует один блок на холсте конструктора. Сейчас в нём **1484 строки**, и почти 700 из них — это не шаблон, а хитрый код про перетаскивание, сетку прилипания, ресайз, и расчёты цветов. Сейчас этот код сидит прямо в компоненте, и каждый раз, когда мы захотим добавить магнитную сетку или группировку, придётся лезть в этот огромный файл и рисковать что-то сломать.

**Решение:** вытащим всю эту логику в отдельный сервис `block-renderer-state.service.ts`, по тому же принципу, что мы применили к `builder.page.ts` в TZ-235.A R3:
- **Сервис** — единственный источник правды (сигналы, вычисления, обработчики перетаскивания).
- **Компонент** — тонкий «хост»: только шаблон (CSS+HTML) и пара простых обработчиков для кликов.

## Что делаем

## Архитектура (как разделяем код)

### Сервис — `BlockRendererStateService` (~430 строк)

**Что внутри**:
- **8 сигналов состояния** (размеры, маржа, состояние перетаскивания, состояние ресайза)
- **15 вычислений** (computed) — извлекают данные из настроек блока: картинка, таблица, цвет фона, бейдж привязки и т.д.
- **3 эффекта** в конструкторе: авто-синхронизация размеров из настроек; авто-сброс локального перетаскивания когда сервер вернул новые координаты; авто-сброс ресайза.
- **3 обработчика перетаскивания** (onResizeStart, onOverlayDragStart, onCornerResizeStart) — содержат DOM-логику и `document.addEventListener`.
- **3 приватных хелпера прилипания** (snapValueToGrid, applySnapToGrid, snapToBlockEdges).
- **3 Subject для outputs** (widthChange$, overlayMove$, overlayResize$) — компонент подписывается и эмитит в Angular `output()`.

**Lifetime**: компонент-скоупед (per-instance). Каждый экземпляр `<app-block-renderer>` имеет свой собственный сервис. Регистрируется через `providers: [BlockRendererStateService]` в `@Component`. **Почему не `providedIn: 'root'`**: иначе при переходе между шаблонами состояние перетаскивания смешивалось бы (как у TZ-235.A R3).

### Компонент — `BlockRendererComponent` (~870 строк, из них ~700 — это шаблон и стили)

**Что внутри** (в class body, ~120 строк):
- **Inputs** (6) и **outputs** (6) — все те же, что сейчас.
- **Aliased signals** — проброс всех 23 сервисных сигналов/computed по ссылке (`protected readonly currentWidth = this.state.currentWidth`). Это сохраняет текущий синтаксис шаблона (без `state.X()`).
- **Простые обработчики** остаются в компоненте: `onSelect`, `onCheckboxClick`, `onDeleteClick`, `onArrowKey`, `formatTableCell`, `byPassHtml`. Они либо чисто emit'ят output, либо делают форматирование — не имеют state-мутаций.
- **Подписка на subject'ы сервиса** в конструкторе — пробрасывает события в Angular `output()` с `takeUntilDestroyed()`.
- **Делегирование** мутирующих обработчиков на сервис: `onResizeStart(event, side) → state.onResizeStart(...)`.

## Дифф шаблона

**Не меняется** — все алиасы сигналов пробрасываются по ссылке, поэтому синтаксис шаблона `[style.left.px]="dragActive() ? dragLeft() : overlayLeft()"` остаётся **ровно таким же**. Это критично: 220 строк HTML трогать не нужно.

## Дифф @Component

```ts
@Component({
  selector: 'app-block-renderer',
  // ...
  providers: [BlockRendererStateService],  // ← НОВОЕ: per-instance
  // ...
})
```

## Тонкости (gotchas)

1. **Безопасность от null в computed**: сервисный `block` сигнал инициализируется как `null` до первого зеркалирования. Computed должны корректно обрабатывать `null` (возвращать дефолт).
2. **OnPush + алиасы**: т.к. алиасы — это просто ссылка на сервисный сигнал, Angular OnPush трекает чтения как обычно. Ноль потери производительности.
3. **Memory leaks**: `takeUntilDestroyed()` подписки на subject'ы — обязательно в конструкторе (тут он наследует контекст компонента).
4. **Trust-model banner** (`⚠ innerHTML trust-model notice`) — должен быть сохранён на компонент-файле (так как `byPassHtml` остаётся в компоненте).

## Что НЕ делаем (отложено в TZ-235.C/D)

- **Группировка блоков** (TZ-235.D) — когда несколько блоков перетаскиваются вместе.
- **Undo/Redo** (TZ-235.E) — стек истории изменений.
- **Магнитная сетка «сосед-блок»** — расширение текущего snapToBlockEdges.
- **Линии выравнивания** (визуальные подсказки при перетаскивании).

Все они станут **тривиальнее** после этого рефактора — просто добавим в сервис ещё пару сигналов + пару хелперов, не трогая шаблон.
