# TZ-236 — PDF/Print стек + Backend зависимости для Конструктора v2

**Дата создания:** 2026-07-30
**Автор:** senior-architect review (PO-driven бриф от 2026-07-30 — после прочтения data-model + design-spec + TZ-232 + TZ-235)
**Приоритет:** STRATEGIC (Без печати/PDF — конструктор = красивый редактор без бизнес-ценности. Это инфраструктурный TZ, без которого TZ-235.Wave 6 не запустится)
**Связь:** COMPANION к `TZ-235` (UX-фичи). TZ-235 в §7 перечисляет 3 backend-зависимости (TZ-236, TZ-237, TZ-238), которые разрослись в самостоятельный ТЗ. **Этот TZ-236 частично перекрывает тот маленький TZ-236 про datasets — расширяем scope до полной PDF/Print инфраструктуры, datasets делаем отдельным под-Wave.**

## 0. TL;DR для PO

**Главное:** Конструктор документов без печати/PDF = игрушка. Это ТЗ закрывает **всю инфраструктуру вокруг печати и PDF**:
- Как сделать «Печать» в браузере (preview + window.print)
- Как сервер генерирует финальный PDF для скачивания / отправки клиенту
- Какие backend endpoints нужны (3 шт.: bulk PATCH, datasets, PDF render)
- Какие UX-фичи печати добавить (header/footer, номера страниц, поля для печати)
- Как связать preview в редакторе с финальной PDF-генерацией

**Ключевое архитектурное решение:** **Native Print (`window.print`) для клиента + Gotenberg (Docker) для сервера.** Никакого jsPDF / html2canvas (мыло, ~500 KB, плохая кириллица).

**Что НЕ делаем в этом ТЗ:**
- ❌ Никаких UI-фич самого редактора (snap, guides, undo/redo) — это всё в TZ-235.
- ❌ Никаких dataset-каталогов в этой итерации — выделено в **TZ-236.B** как под-Wave.
- ❌ Никаких placeholders data binding — это TZ-235.E.

**Скоуп:** ~140–180 h, 3-4 календарных месяца при 2-3 сессиях в неделю.

## 1. Бизнес-контекст

### 1.1 Где в проекте нужна печать / PDF

| Источник | Получатель | Формат | Где живёт |
|---|---|---|---|
| **Конструктор шаблонов** (наш редактор) | Сам разработчик шаблона | Визуальный preview + window.print | TZ-235 уже работает |
| **Коммерческое предложение** (page proposals) | Клиент (скачивает / получает по email) | PDF файл | Proposal.page → кнопка «Скачать PDF» |
| **Договор** (page contracts) | Клиент + подписание | PDF + place для подписи | Contract.page → «Скачать PDF» |
| **Паспорт продукции** (product passport) | Производство / заказчик | PDF с QR-кодом | ProductPassport.page → «Печать» |
| **Акт сверки** (reconciliation act) | Бухгалтерия | PDF | ReconciliationAct.page → «Печать» |
| **Наряд-заказ** (work order) | Цех / работник | PDF | WorkOrder.page → «Печать» |
| **Финансовый отчёт** | Руководство | PDF | FinancialReport.page → «Экспорт PDF» |

**Итого 7 страниц-источников PDF.** Все они будут использовать **общий сервис** `PdfGenerationService` (DSL-деталька).

### 1.2 Почему это критично

- **Конструктор = дифференциатор ERP** (см. TZ-235 §0). Без печати/PDF — это WYSIWYG без «WY».
- **Юридическая сила:** PDF для договоров должен быть byte-stable (одинаковый на всех устройствах) — это значит только серверная генерация.
- **Печать в браузере** нужна для разработчика шаблонов (быстрая итерация без backend round-trip).

## 3. PDF/Print стек — ФИНАЛЬНОЕ РЕШЕНИЕ

### 3.1 Сравнение вариантов (decision matrix)

| Вариант | Bundle | Cyrillic | Качество | Server-side | Browser | Пригодность |
|---|---|---|---|---|---|---|
| `window.print()` + `@media print` | 0 KB | ✅ идеально | ✅ вектор | ❌ нет | ✅ да | 🟢 CLIENT PREVIEW |
| **Gotenberg** (Docker) | 0 KB | ✅ если шрифты в image | ✅ идентично браузеру | ✅ да | ❌ нет | 🟢 **SERVER GENERATION** |
| puppeteer (npm) | ~250 MB | ✅ | ✅ | ✅ да | ❌ нет | 🔴 Слишком тяжёлый |
| react-pdf | 0 KB | ✅ через fontkit | ✅ | ✅ SSR | ❌ нет | 🟡 Альтернатива, но не Angular-friendly |
| pdfmake | ~400 KB | ✅ | ✅ | ✅ | ✅ | 🟡 Старый, монструозный API |
| jsPDF + html2canvas | ~500 KB | ⚠️ rasterized | ❌ мыло/блюр | ❌ | ✅ | 🔴 Плохое качество для договоров |
| pdfme | 0 KB | ✅ | ✅ | ✅ | ✅ | 🟡 Хорошая альтернатива, но младший брат Gotenberg |

**ПОБЕДИТЕЛИ:**
- **Client preview:** native `window.print()` + `@media print` CSS (0 KB, идеально для разработчика шаблонов)
- **Server generation:** **Gotenberg** (Docker-микросервис, 0 KB bundle, идеально для финальных документов)

### 3.2 Почему НЕ jsPDF / html2canvas

- jsPDF рендерит HTML через Canvas → rasterized → **мыло в тексте**. Для договора с мелким шрифтом — нечитаемо.
- 500 KB на bundle: для preview, который вызывается только в редакторе — это всё равно много.
- Кириллица: jsPDF требует ручной загрузки шрифта через `addFont()` и конвертации TTF → base64. Gotenberg — принимает HTML со ссылкой на Google Fonts / локальный файл, русифицирует автоматически.

### 3.3 Почему Gotenberg, а не puppeteer напрямую

- **Изоляция:** Gotenberg — отдельный Docker-контейнер. NestJS процесс не блокируется рендерингом (puppeteer блокирует event-loop ~1.5s на документ).
- **Отказоустойчивость:** крах Chromium не валит backend.
- **Шрифты на уровне OS:** один раз установили в Docker image — все шаблоны имеют правильный шрифт.
- **API:** простой HTTP endpoint `POST /forms/chromium/convert/html` — послал HTML, получил PDF.
- **CDN-friendly:** можно поднять 3-5 контейнеров за nginx — горизонтальное масштабирование.

### 4.2 Cyrillic font consistency (CRITICAL)

Без явного решения — шрифты в browser ≠ шрифты в server PDF. Решение:

**Зафиксировать 3 шрифта:**
- **PT Sans** (основной, 400/700) — русский, бесплатный, лицензия OFL
- **PT Serif** (для заголовков, 400/700) — OFL
- **JetBrains Mono** (для цифр и кода) — OFL

**Где живут:**
1. **Angular UI:** `frontend/src/assets/fonts/*.woff2` + CSS `@font-face` через `src/styles.css`. Load до первого render.
2. **Gotenberg Docker image:** custom `Dockerfile.gotenberg` — копирует те же `*.woff2` в `/usr/share/fonts/`. Chromium подхватывает автоматически.
3. **Template HTML для рендера:** CSS объявляет те же 3 шрифта. Gotenberg видит их (потому что они в OS).

**Acceptance:**
- Visual diff: side-by-side browser preview vs server PDF — 0 визуальных различий (Chromium рендерит одинаково).
- Test: рендерим шаблон с `{{title}}` → проверяем что PDF содержит текст на русском без квадратиков.

### 5.3 Preview vs Generation — два разных pipeline

**Preview (in builder, live):**
- Browser рендерит HTML/CSS напрямую (Angular UI = DOM).
- Print как fallback: `window.print()` + `@media print` правила.
- **Никакого PDF не создаётся.** Только DOM.

**Generation (proposal page → "Скачать PDF"):**
1. Frontend: `POST /api/documents/:id/generate-pdf` с минимальным payload.
2. Backend: 
   - Fetch template JSON + dataset data.
   - Render HTML через Handlebars (`render(template, data)`).
   - POST HTML → Gotenberg → PDF binary.
   - Return PDF как `application/pdf` stream.
3. Frontend: `Blob` → `URL.createObjectURL` → `<a download="proposal-123.pdf">`.

**Почему preview ≠ generation:**
- Preview = WYSIWYG, должен реагировать на каждый чих < 16ms.
- Generation = авторитетный, может занять 1.5s.
- Visual drift возможен, но acceptance: side-by-side сравнение после каждой фичи.

### 5.4 Idempotency для PDF generation

POST `/api/documents/:id/generate-pdf` использует **тот же `Idempotency-Key` interceptor** (TZ-232.I) — повторный клик = 1 PDF, не 2.

### 5.5 Caching

In-memory `Map<hash(template.json + datasetId), Buffer>` в `PdfRenderService`:
- TTL: 60s (после `template.updatedAt`).
- Max size: 100 entries (LRU eviction).
- Hash: `sha256(JSON.stringify({template, datasetId}))`.

При cache hit — мгновенный return (без Gotenberg call).

## 8. Risks & Pitfalls

| Риск | Severity | Mitigation |
|---|---|---|
| **Gotenberg падает под нагрузкой** | HIGH | Очередь задач через Bull/BullMQ. Горизонтальное масштабирование (3-5 контейнеров). |
| **Visual drift browser vs PDF** | HIGH | Side-by-side test в CI. Фиксированные шрифты. |
| **Cyrillic font не подхватывается Gotenberg** | CRITICAL | Custom Dockerfile с явной копией шрифтов в `/usr/share/fonts/`. Verify в Wave A. |
| **Bulk PATCH ломает документ** | MED | Mongo transaction в Wave C.1. Dry-run mode для разработки. |
| **PDF caching stale** | MED | TTL 60s + invalidation при `template.update`. |
| **Templates без print margins** | LOW | Default margins = 15mm (самый безопасный). |
| **Page numbers off-by-one** | MED | Тест: рендерим 3-страничный документ → проверить "Page 1 of 3", "Page 2 of 3", "Page 3 of 3". |
| **Watermark ломает scanning** | LOW | Watermark НЕ применяется к native scan (пост-обработка). |
| **Email PDF attachment спам** | LOW | Rate limit per user. Max 10 emails/hour. |
| **Bundle size Gotenberg Docker image** | LOW | ~600 MB image. Acceptable для production. |
