# TZ-232 Wave 2 — Migration of 5 list-pages to `<pi-entity-list>`

## Goal

Replace bespoke list-page boilerplate (own httpResource + own toolbar + own pagination + own search) with the canonical `<pi-entity-list>` shell component. Each migrated page becomes ~140 lines (template + class). All CRUD logic (dialogs, row actions, delete confirmations) lives in the page; all data plumbing lives in the DSL component.

## Reference (READ FIRST)

Canonical example (do not modify):

```
frontend/src/app/pages/organizations/organizations.page.ts   (141 lines)
```

```bash

## Pattern (minimum viable page)

@Component({
  selector: 'app-<entity>s-page',
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [PiEntityListComponent, PiRowActionsComponent],
  template: `
    <app-pi-entity-list
      endpoint="<endpoint>"
      [columns]="cols"
      title="<Title>"
      eyebrow="<eyebrow>"
      description="<description>"
      emptyMessage="Нет данных. Нажмите «Создать», чтобы добавить первую запись."

  `,
})
export class <Entity>sPage {
  private readonly service = inject(<Entity>Service);
  private readonly dialog = inject(PiDialogService);
  private readonly toast = inject(PiToastService);
  private readonly destroyRef = inject(DestroyRef);
  private readonly injector = inject(Injector);

  protected readonly cols: ColumnDef<<Entity>>[] = [
    { key: 'name', label: 'Название', sortable: false, sticky: 'left' },
    // ... other columns, all `sortable: false` UNLESS backend supports sortBy

  @ViewChild('rowActionsTpl', { static: true })
  protected readonly rowActionsTpl!: TemplateRef<{ $implicit: <Entity> }>;

  protected openCreate(): void { /* dialog open + refreshOnDialogClose */ }
  protected openEdit(row: <Entity>): void { /* dialog open */ }
  protected onDelete(row: <Entity>): void { /* AlertDialog + service.remove().subscribe */ }
}
```

## Backend sortBy status (DO NOT enable server-side sort without checking)

| Entity | Service path | sortBy? | Notes |
|---|---|---|---|
| materials | `backend/src/modules/material/material.service.ts` | NO | disable server-side sort |
| products | `backend/src/modules/product/product.service.ts` | YES (line 51, 65) | server sort OK |
| work-types | `backend/src/modules/work-type/work-type.service.ts` | NO | disable |
| product-modules | `backend/src/modules/product-module/product-module.service.ts` | NO | disable |

Use `sortable: false` when backend lacks `sortBy`. Reference: organizations.page.ts uses `sortable: false` everywhere and comments the TODO.

## Cases

### materials.page.ts (482 → ~140 lines)

- Service: `MaterialsService` from `frontend/src/app/shared/services/materials.service.ts` (use `silentGet/List/Remove`)
- Form-dialog: `frontend/src/app/pages/materials/material-form-dialog.component.ts`
- Has unit lookup (category, etc.) — form-dialog handles itself
- Columns: name (sticky), article, sku, unit (accessor .map to label), categoryId (resolve via lookup)

### products.page.ts (475 → ~140 lines)

- Service: `ProductsService` from `frontend/src/app/shared/services/products.service.ts`
- Form-dialog: `frontend/src/app/pages/products/product-form-dialog.component.ts`
- Products has `sortBy` → can use `sortable: true` on plain columns where data is sortable (name, sku, kind, createdAt)
- Columns: name, sku, kind (accessor), unit, status
- Has `(rowClick)` → opens detail page (already routed as `/products/:id`)

### work-types.page.ts (340 → ~140 lines)

- Service: `WorkTypesService` from `frontend/src/app/shared/services/pi-work-types.service.ts`
- Form-dialog: `frontend/src/app/pages/work-types/work-type-form-dialog.component.ts`
- No sortBy → all `sortable: false`
- Columns: name, section, workCenterId (accessor fallback to id), isActive (switch-like)

### modules.page.ts (523 → ~150 lines)

- Service: `ProductModulesService` from `frontend/src/app/shared/services/pi-product-modules.service.ts`
- Form-dialog: `frontend/src/app/pages/modules/module-form-dialog.component.ts`
- Has `(rowClick)` → opens detail page (`/modules/:id`)
- Columns: name, sku, unit, defaultWorkTypeId, dimensions

### tables.page.ts (533 → ~150 lines)  ⚠ NO FORM-DIALOG

- Service: `TableTemplatesService` from `frontend/src/app/shared/services/pi-table-templates.service.ts`
- **NO existing form-dialog component** — options:
  - (a) Create a minimal `tables-form-dialog.component.ts` mirroring pattern from `dictionaries/category-form-dialog`
  - (b) Use a stub `<create>` that toasts "Создание таблиц в разработке"  ⚠ not production-quality
  - **(Choose a)** — create minimal dialog using fields: name + sampleRows (preview rows)
