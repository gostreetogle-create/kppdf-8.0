**Цель:** Доказать, что DSL `<pi-entity-list>` wrapper работает на РЕАЛЬНОЙ production-странице ДО масштабирования на остальные 13 list-pages из миграционного чеклиста (TZ-232.D/E/F).

## 1. Implementation summary (retro-style)

### 1.1 Что уже реализовано (pre-existing, validation confirmed)

**`<pi-entity-list>` standalone wrapper (`pi-entity-list.component.ts`, 314 LoC):**
- Accepts `[service]: EntityService<T, P>` input — typed 5-CRUD service reference.
- Accepts `[params]: P` input (signal-reactive) + auto-fires debounced search 300ms.
- Accepts `[cols]: ColumnDef<T>[]` for table columns.
- Outputs `(rowEdit)`, `(rowDelete)`, `(create)` events.
- Built-in: loading skeleton, error banner, empty state, server-side pagination via `pi-table`.
- Standalone, OnPush, signal-based. NO Material, NO shadows.
- Depends on `entity-service.ts` for the `EntityService<T, P>` interface contract.

**`toEntityService` adapter (in `entity-service.ts`, from TZ-232.B):**
- 1-LOC bridge between hand-written `EntityService`-shaped service (returning `{items, total}` envelope) and the `<pi-entity-list>` wrapper.
- Synthetic page/limit mapping for non-paginated endpoints.
- Type-safe via generics `<T, P>`.

**`storage-items.page.ts` migration:**
- Original: ~280 LoC of raw `httpResource` + manual signal management + manual loading/error state + manual empty state + manual pagination.
- Migrated: ~170 LoC using `<pi-entity-list>` + `toEntityService` + 1 `httpResource` for warehouses dropdown (page-level concern).
- Custom filter `warehouseId` is page-level — uses signal + `effect()` to trigger `wrapper.reload()` on filter change.
- Filters pass-through via `ExternalParams<StorageItemsListParams>` type-stripping pattern.
