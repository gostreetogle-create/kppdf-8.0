## Цель

Дать пользователю понятное выделение нескольких элементов рамкой или modifier-click и возможность перемещать выбранную группу одним жестом, сохраняя относительные расстояния и единый undo/save operation.

## Что сделать

1. Реализовать marquee/rubber-band selection на пустой области canvas: pointer down → rectangle → pointer up; выбрать блоки, чьи bounds пересекают прямоугольник по согласованному правилу. Shift добавляет к выбору, Escape очищает, click по пустому месту сохраняет текущий contract свойств шаблона.
2. Синхронизировать marquee с существующими `selectedId`/`selectedIds`, checkbox/multi-select и inspector. Не создавать второй источник selection state.
3. При drag любого выбранного positioned-блока вычислять один delta и применять его ко всем выбранным блокам с общим clamp относительно страницы. Flow-блоки не должны случайно перемещаться как absolute элементы.
4. Для выбранной группы показать единый visual boundary и ясное состояние `is-group-dragging`; не скрывать отдельные selection outlines и не ломать keyboard focus/ARIA.
5. Сохранять group operation атомарно через фактически доступный bulk endpoint/сервис. Если bulk endpoint не готов, остановить только этот технический срез с точным отчётом, а не отправлять N скрытых PATCH-запросов.
6. Связать group drag с history contract из TZ-264 через его публичный transaction boundary: одно действие пользователя = одна undo entry; отмена незавершённого drag не создаёт запись. Добавить component/service tests и обновить docs.

## Критерии приёмки

1. Рамка выделения выбирает ожидаемые блоки на canvas, работает с Shift/Escape и не выбирает элементы за пределами прямоугольника.
2. При выделенных трёх positioned-блоках drag любого из них переносит все три на одинаковый delta; относительные расстояния сохраняются.
3. Группа не выходит за page bounds; cancel/escape возвращает исходные координаты и не отправляет сохранение.
4. Group drag создаёт один bulk request и одну undo entry; повторное открытие шаблона показывает итоговые координаты.
5. Flow reorder, single selection, keyboard navigation, inspector и delete selected продолжают работать.
6. Есть tests для marquee, additive selection, group delta, boundary clamp, cancel, bulk payload и accessibility states; frontend/backend checks проходят.

## Ограничения

Не вводить отдельную сущность «Group» в базе: на этом этапе группа — временное выделение. Не делать nested groups, rotation, arbitrary transforms или отдельную scene graph. Не менять существующий auth/RBAC contract.
