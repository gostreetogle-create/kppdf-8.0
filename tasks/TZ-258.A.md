## 0. Контекст и причины появления

TZ-258 ships:
- `docs/protected-page-contract.md` (10-section operator runbook)
- `backend/scripts-fields-helpers/LEGACY_RBAC_EXCEPTIONS.json` (9 entries)
- `backend/scripts/audit-policy-metadata.ts` (CLI script — static-scan helpers, exit 0/1)
- `backend/scripts/audit-policy-metadata.spec.ts` (8 unit tests against the helpers)

The verifier confirms jest runs ALL baseline suites + TZ-257 suites GREEN,
but TZ-258 spec suite reports "0 tests found" because the spec lives
under `backend/scripts/`. Jest's `testRegex: 'src[/\\\\].*\\.spec\\.ts$'`
only matches files under `src/`, so the CLI-script spec isn't executed
in the test pipeline.

The script itself works fine when invoked via `ts-node`/`tsx` directly,
but jest's coverage gate goes silent on the helpers. Two options:

1. Move the spec to `backend/src/scripts/audit-policy-metadata.spec.ts`
   (jest picks it up via the existing regex). Source-of-truth scripts
   stay in `backend/scripts/`; the spec migrates for discoverability.
2. Add a `roots: ['<rootDir>/src', '<rootDir>/scripts']` configuration
   to `jest.config.js` so scripts/ shares the same test scope.

Path of least churn: option (1). The spec already has no runtime
dependency on the script's location — it imports `extractHandlers` etc.
which are exported by `audit-policy-metadata.ts`. We just relocate the
test file.
