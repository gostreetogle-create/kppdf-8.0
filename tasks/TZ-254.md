## 0. Цель

Каноническая спецификация RBAC для проекта:

- Формат permission key: `<section>:<action>` (action ∈ {read, write, admin}).
- Семантика слоёв: read (SELECT), write (INSERT/UPDATE), admin (DELETE / управление пользователями).
- Effective permissions = `Role.permissions ∪ (User.permissions для конкретного юзера)` ∪ (wildcard '*' для admin role).
- Role.permissions — assigned на уровне role.
- User.permissions — overrides/additions поверх роли (для expansion).
- Wildcard admin: permission key `*` или роль `admin` (полный доступ).
- System roles (admin/manager/user) — не могут быть удалены.
- Custom roles — могут иметь любую combination permissions.
- Shared corporate data vs user-owned — оформлено в TZ-251 (OWNERSHIP_BY_ENTITY).

**Не вводить в этой TZ:**
- ABAC, multi-tenancy, SSO, LDAP, policy engine.
- Обязательная миграция User.role field (single string OK).

### ШАГ 2: Wildcard resolution

```typescript
function effectivePermissions(user: User, role: Role): Set<string> {
  const result = new Set<string>();
  for (const p of user.permissions ?? []) result.add(p);
  for (const p of role.permissions ?? []) result.add(p);
  if (user.permissions?.includes('*') || role.name === 'admin') {
    for (const p of PERMISSIONS) result.add(p.key);
  }
  return result;
}
```

### ШАГ 4: Invariant rules (documented)

- `admin` role: cannot be deleted.
- Last admin invariant: when removing admin from system, refuse if it's the only one.
- Custom role name uniqueness across non-system roles.
- `User.role` is single string (per TZ-04) — multi-role migration **out of scope** of this contract.
