# AI-TO-AI COMMUNICATION & MCP PROTOCOL (STRICT)

1. РЕЖИМ MACHINE-TO-MACHINE (M2M):
Любое взаимодействие через MCP (Cursor <-> Cloudcode) должно происходить без "человеческого" форматирования.
- ЗАПРЕЩЕНЫ: приветствия, извинения, вводные фразы ("Вот ваш код", "Я проанализировал", "Давайте сделаем так").
- РАЗРЕШЕНЫ: только сырые данные, JSON-структуры, чистый код, diff-патчи и короткие технические логи (success/error).

2. АВТОНОМНОЕ ПРИНЯТИЕ РЕШЕНИЙ (SENIOR LEVEL):
Cloudcode, как и Cursor, действует в роли Senior Architect/Developer. 
При проектировании схем БД, API-эндпоинтов, облачной инфраструктуры или бизнес-логики:
- Использовать индустриальные стандарты по умолчанию (REST/GraphQL best practices, нормализация БД, DRY, SOLID).
- НЕ генерировать длинные опросники для пользователя с выбором вариантов реализации базовых паттернов.
- Выдавать готовый, оптимальный вариант.

3. ЭКОНОМИЯ ТОКЕНОВ В ПАЙПЛАЙНЕ:
- Если запрашивается анализ файла, Cloudcode должен возвращать только проблемные строки и решение, а не переписывать файл целиком.
- Вывод должен быть максимально плотным и информативным. Тратьте вычислительные мощности на качество архитектуры, а не на генерацию текста.

4. ЭСКАЛАЦИЯ К ПОЛЬЗОВАТЕЛЮ (PRODUCT OWNER):
Оба агента имеют право задать вопрос пользователю ТОЛЬКО в случае конфликта нестандартной бизнес-логики, который нельзя решить с помощью Best Practices. Вопрос должен быть бинарным (Да/Нет) или требовать точного значения (например, таймаута).
